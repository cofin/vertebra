# Design: Single-File Distribution (Consolidated)

**Goal**: Create a standalone, self-contained executable (`vertebra`) using `pyapp`.
**Targets**: Linux + macOS for initial release; Windows later.
**Key Innovation**: The "Unified Supervisor" pattern. The Python entry point immediately invokes the Rust extension (`vertebra-py`), which acts as the system supervisor—managing the embedded Resource Broker and the Bun Sidecar.

## 1. Architecture

```
[ Single Executable (vertebra) ]  <-- Generated by pyapp
      |
      |-- [ pyapp launcher (Rust) ]
      |      |
      |      |-- [ Embedded Python Dist (PBS) ]
      |      |
      |      +-- [ Vertebra Wheel (.whl) ]
      |             |
      |             +-- [ vertebra/ ]
      |             |      |-- cli.py  <-- Entry Point
      |             |      |-- bin/
      |             |           +-- vertebra-engine (Compiled Bun Binary)
      |             |
      |             +-- [ vertebra_core.so ] (Rust Extension)
      |                    |
      |                    +-- [ Resource Broker ] (Embedded Rust Thread)
      |                    +-- [ Process Manager ] (Spawns Bun)
```

## 2. Startup Sequence

1.  **User** runs `./vertebra serve`.
2.  **PyApp** bootstraps Python.
3.  **Python** invokes `vertebra.cli:main`.
4.  **Vertebra CLI** calls `vertebra.rust.init_supervisor()`.
5.  **Rust Supervisor** (inside `vertebra-py`):
    *   **Starts Broker**: Spawns the `vertebra-broker` logic in a background Rust thread (tokio runtime). No separate process needed.
    *   **Spawns Sidecar**: Locates and spawns `vertebra-engine` (Bun) as a subprocess.
    *   **Establishes IPC**: Sets up shared memory rings (no sockets).
6.  **Python** continues to run the ASGI worker loop (or CLI logic).

## 3. Build Pipeline

### Step A: Compile Engine (Bun)
```bash
bun build --compile src/ts/src/server/index.ts \
  --outfile src/py/vertebra/bin/vertebra-engine \
  --target=...
```

### Step B: Build Rust Extension (Maturin)
Include the `vertebra-broker` crate logic as a library dependency in `vertebra-py`.
Expose `init_supervisor()` via PyO3.

### Step C: Build Wheel & Bundle
```bash
hatch build  # Creates wheel with .so and bin/
vertebra build --one-file # Runs pyapp packaging
```

## 4. Hooking via Rust

The user asked: *"Can we programmatically hook into this in Rust?"*

**Answer**: **Yes.**
Because our wheel includes a compiled Rust extension (`vertebra-py`), we have a native code hook into the runtime.
We do not need to modify the `pyapp` launcher itself.
Instead, we treat the Python Entry Point as a thin shim that "hands over" control to our Rust Supervisor immediately.

**Benefits**:
*   **Embedded Broker**: The Resource Broker runs in-process (or same process group), reducing deployment complexity.
*   **Lifecycle Management**: Rust handles signals (SIGTERM) and ensures the Bun sidecar is killed cleanly.
*   **Performance**: Zero latency startup for Broker.

## 5. Configuration

`pyproject.toml` handles the `pyapp` wrapping:
```toml
[tool.hatch.build.targets.binary]
python-version = "3.12"
standalone = true
# Installs the wheel built in previous step
```
