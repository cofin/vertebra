# Changelog

All notable changes to Vertebra are documented on this page.

## Unreleased

### Added

- Standalone optional PyO3 native wheel `vertebra-sqlite` (`vertebra._sqlite`, `[sqlite]`) with bundled modern SQLite 3.45+, `GIL_USED = False` compatibility on free-threaded Python `3.14t`/`3.15t`, single-writer / multi-reader WAL OS worker pool, SQLite 3.45+ binary `JSONB`, fast `< 50ms` `InterruptHandle` query cancellation, online `backup_to` and `restore_from`, and zero-copy `VTBARROW` `ArrowCursor` streaming (`select_to_arrow`) and `load_from_arrow`.
- Delayed-commit `SyncSQLitePipeline` and `AsyncSQLitePipeline` (`driver.pipeline()`) supporting batch statement execution with nested `SAVEPOINT` isolation.
- Dual-mode MCP version negotiation (`SUPPORTED_PROTOCOL_VERSIONS = ("2026-07-28", "2025-11-25", "2025-06-18", "2025-03-26")`), `MCPSessionStore`, legacy `initialize` / `ping` / `logging/setLevel` / `2025-03-26` JSON-RPC batch arrays, `DELETE /mcp`, and structured `-32022` negotiation payloads ([#109](https://github.com/cofin/vertebra/issues/109)).
- Server-initiated `GET /mcp` SSE notification streams (`McpHttpResponse.stream` across native `App`, ASGI, Starlette, WSGI, Flask, and Django), `Last-Event-ID` replay, level-gated `MCPCore.log`, progress event relay, authorized `resources/subscribe`, `notify_resource_updated`, and `2026-07-28` `subscriptions/listen` ([#109](https://github.com/cofin/vertebra/issues/109), [#112](https://github.com/cofin/vertebra/issues/112)).
- `SKILLS_EXTENSION` (`io.modelcontextprotocol/skills`) filtering/URI resolution across `SkillCatalog` and framework mounts ([#111](https://github.com/cofin/vertebra/issues/111)), plus SEP-1865 `UI_EXTENSION` (`io.modelcontextprotocol/ui`) metadata (`McpIcon`, `ToolSpec.meta`, `ToolRegistry.validate_ui_links`, `MCPCore.validate()`) and app-only tool filtering ([#110](https://github.com/cofin/vertebra/issues/110)).
- Google Cloud `IapIdentitySource` ES256 signed JWT header verification (`vertebra-core[iap]`), `OidcTokenSource` (`AsyncGcpIdTokenCache` + `401` single retry) for `vtb ai mcp bridge --audience`, incremental cancellable `run_stdio_server`, and `resolve_app_mcp_core` / `is_litestar_mcp_app` discovery in `vtb ai mcp serve --app` ([#114](https://github.com/cofin/vertebra/issues/114)).
- `Tool.authorize` single-pass guard splitting (`-32004` / `-32005`), `Mcp-Param-*` header validation (`-32020`), and single-use expiring confirmation consumption (`ConfirmationGate.consume_call_approval`).

- Standalone PEP 249 `vertebra.db.dbapi` (`SyncDBAPIConnection`, `AsyncDBAPIConnection`, `SyncDBAPIModule`, `AsyncDBAPIModule`), isolated `SQLAlchemyAsyncDBAPI` (`vertebra.extensions.sqlalchemy.async_adapter`), partitioned SQLAlchemy pooling (`BrokerPool`, `AsyncBrokerPool`, `broker_creator`), and `DbPoolMetricSample` quarantine counters (`quarantined`, `total_quarantined`, `total_disposed`).

### Changed

- `create_event_loop()` attaches `asyncio.eager_task_factory` on every loop backend (`uvloop`, `winloop`, `rloop`, `zuvloop`, and `asyncio`), and `vertebra.utils.sync_tools.run_()` creates its loop through `create_event_loop()` so it honors `VERTEBRA_LOOP` and free-threaded loop quarantine ([#129](https://github.com/cofin/vertebra/issues/129)).
- `EventLoopPool` names shard tasks `vertebra.loop.shard.{idx}.task.{seq}` and `WorkerRunner` names tasks `vertebra.worker.runner` and `vertebra.worker.lane.{lane}.{seq}` ([#130](https://github.com/cofin/vertebra/issues/130)).
- With an AWS or Azure token provider on a remote host, `PostgreSQLConfig` and `MySQLConfig` default to `verify-full` and reject SSL modes that can fall back to plaintext (`disable`, `allow`, `prefer`); explicit `require` and `verify-ca` stay allowed. `MSSQLConfig` with an Entra token provider rejects unencrypted or login-only encryption and `trust_server_certificate=True` on remote hosts. Both PostgreSQL and MySQL apply the Azure database scope to an unscoped `AzureEntraTokenProvider` and attach the bundled AWS RDS root CAs for remote `AwsRdsIamTokenProvider` hosts. `token_provider` and CA settings pass through PEP 249 `connect_args`, SQLAlchemy `+vtb` URLs, and SQLSpec `derive_pool` ([#67](https://github.com/cofin/vertebra/issues/67), [#68](https://github.com/cofin/vertebra/issues/68)).
- `MySQLConfig.ssl_mode` is `None` until set and no longer rewritten at construction; `canonical_ssl_mode` reports the effective mode, including a mode given in the DSN.
- `SyncObjectStore` and `AsyncObjectStore` raise `ImproperConfigurationError` at construction for incomplete Azure service principal or SAS options, partial OCI API signing fields, and blank or unreadable explicit GCS credential options.
- `ArrowCursor.to_polars()` passes the cursor to Polars through the Arrow C Stream capsule instead of building a `pyarrow.Table` ([#128](https://github.com/cofin/vertebra/issues/128)).
- Cut `SyncSQLiteDriver` and `AsyncSQLiteDriver` over from stdlib `sqlite3` to native `vertebra._sqlite` (`ensure_module`), replacing per-query thread offloading with native async completion task dispatch.
- Consolidated `MCPCore` well-known discovery and `SkillCatalog` / UI validation wiring across `AgentPlugin`, Starlette, FastAPI, Flask, Django, and `litestar-mcp>=0.20.0` (`create_mcp_plugin`) ([#110](https://github.com/cofin/vertebra/issues/110), [#111](https://github.com/cofin/vertebra/issues/111)).
- `DuckDBSecretConfig` rejects `persistent=True` with dynamic `value_provider` callables and validates `refresh_interval_seconds` as a positive finite number; `SyncDuckDBDriver` and `AsyncDuckDBDriver` invalidate dynamic secret providers on `(HTTP 401)` / `(HTTP 403)` `httpfs` errors and close the underlying `_client` if startup initialization fails.
- `ProxySyncDriver` and `ProxyAsyncDriver` (`vertebra.extensions.sqlspec`) inherit `SyncDriverAdapterBase` and `AsyncDriverAdapterBase` with aligned upstream method signatures and `ArrowResult` returns, and `_BaseSQLSpecProvider` replaces `inspect.signature` / suppressed exits with `@runtime_checkable` broker Protocols and fail-loud lease quarantine ([#98](https://github.com/cofin/vertebra/issues/98)); `create_sync_alchemy_config` and `create_async_alchemy_config` wire `BrokerPool` / `AsyncBrokerPool` when a broker is provided.
- SQLSpec, SQLAlchemy, and `vertebra.db.dbapi` run statements through the native cursor; broker leases are taken per connection checkout and embedded engines take none; and the DB-API exception names are the native `vertebra.db` driver classes, so `InterfaceError` is a subclass of `DatabaseError` and `Error` is `DatabaseError`.
- Raised the minimum `sqlspec` dependency floor to `>=0.74.0`, switched cached statement executor registration in `BaseSyncDriver` and `BaseAsyncDriver` to `set_cached_statement_executor(..., owner=...)`, normalized `bool` and empty-string `lastrowid` values to `None` inside `BaseSyncDriver._normalize_last_inserted_id()`, aligned `resolve_last_inserted_id()` across `BigQuery*Driver`, `Spanner*Driver`, and `Proxy*Driver`, migrated all eight extension `reconcile.py` modules onto public `sqlspec.extensions.events.resolve_backend_name` and `sqlspec.extensions.adk` configuration helpers, switched `ObjectStoreRegistry` and `register_storage_alias()` to `StorageRegistry.register_backend("vertebra", ObjectStoreBackend)` and pre-configured instance aliases, thinned the SQLite, PostgreSQL, Oracle, Spanner, DuckDB, MSSQL, and BigQuery `data_dictionary.py` modules onto shared `sqlspec.data_dictionary.dialects.<dialect>.dictionary` base classes, and removed unused `sqlite_index_rows_to_metadata`.
- Optimized GitHub Actions CI and release pipelines around build-once wheel artifacts (`tools/scripts/build_ci_wheels.py`), reusable composite Rust/Python setup actions (`.github/actions/setup-rust-build`, `.github/actions/setup-python-env`), `ubuntu-slim` runners for non-native lint/docs/TS jobs, Cargo `[profile.ci]` and `[profile.release]` thin LTO (`lto = "thin"`, `codegen-units = 4`), `uv sync --no-install-local` across non-building jobs, pull-request matrix tiering (`full-ci` and `macos` opt-in labels, full coverage on `main` pushes and nightly schedule when commits landed), intra-run ephemeral artifact cleanup, closed-PR cache cleanup (`.github/workflows/cache-cleanup.yml`), and opt-in `sccache` remote cache configuration (`vars.SCCACHE_BACKEND`).
- Raised the minimum `advanced-alchemy` dependency floor to `>=1.13.0b3`, adopting late-bound SQLAlchemy engine factory lookup (for OpenTelemetry `SQLAlchemyInstrumentor().instrument()` compatibility on single-engine and routed configs) and AES-256-GCM cursor token encryption behind the optional `cryptography` extra.

### Fixed

- Fixed `SQLiteCore.initialization_pragmas` to validate pragma values directly without suppressed native call defects, removing legacy `sqlite_initialization_pragmas` binding from `vertebra-py` and `_vertebra.pyi`.
- `SyncOracleNotificationSource` and `AsyncOracleNotificationSource` execute an idle `SELECT 1 FROM DUAL` session liveness probe whenever an `OracleNotifyConfig.wait_timeout_seconds` poll cycle yields no queued messages so dropped connections trigger reconnect backoff immediately.
- A single-loop inline `EventLoopPool.stop()` cancels tracked tasks, runs `shutdown_asyncgens()`, and closes the loop, matching multi-shard pools ([#129](https://github.com/cofin/vertebra/issues/129)).
- `ArrowCursor.to_pyarrow()` and `to_arrow_table()` raise `ValueError` after `release()`, and `to_pylist()` raises `ValueError` for a dictionary key outside the dictionary values ([#128](https://github.com/cofin/vertebra/issues/128)).
- A corrupt Arrow IPC stream raises `ValueError` from `ArrowCursor` (or an Arrow error through the C stream interface) instead of terminating the process.
- MySQL `ssl_ca`, `ssl_cert`, and `ssl_key` given as inline PEM text load from memory; previously they were treated as file paths and the connection failed.

### Removed

- Removed legacy RESP3 bindings (`encode_resp_command`, `encode_hello3_handshake`, `crc16_xmodem`, `redis_hash_slot`, `parse_cluster_redirect`) from `src/rs/vertebra-py` and `src/py/vertebra/_vertebra.pyi`, and deleted `src/rs/vertebra-db/src/resp3`.
- Deleted empty compatibility alias `MCPService(MCPCore)` and `--name` flag on `vtb ai mcp serve` ([#114](https://github.com/cofin/vertebra/issues/114)).
- Removed in-memory fallback broker transports (`SyncInMemoryBrokerTransport`, `AsyncInMemoryBrokerTransport`, `use_shm=False`), duplicate embedded PEP 249 classes inside `vertebra.extensions.sqlalchemy.dialects`, and unsupported Django database backend stubs (`bigquery`, `duckdb`, `mssql`).
- Removed Python and native client symbols superseded by native cursors: `SyncDBAPICursor`, `AsyncDBAPICursor`, `is_read_only_sql`, `is_insert_sql`, `coerce_dbapi_rows_and_desc`, `NATIVE_CURSOR_ENGINES`, `query_with_columns`, protocol members `execute_with_description`, `execute_tuples`, and `select` on `SyncSQLDriverProtocol` / `AsyncSQLDriverProtocol`, adapter helpers (`DuckDBCore.normalize_parameters`, `DuckDBCore.param_len`, `PostgreSQLCore.normalize_parameters`, `PostgreSQLCore.project_query_rows`, `OracleCore.split_out_bind_parameters`, `OracleCore.is_dml_or_plsql`), `vertebra._vertebra.classify_sql_statement`, and unused native client query methods (`fetch_all` on `SyncSQLiteClient`/`AsyncSQLiteClient`; `fetch_all`, `fetch_one`, `fetch_optional`, `execute_tuples`, `execute_with_description`, and `select_value` on `SyncDuckDBClient`/`AsyncDuckDBClient`; `execute_with_description`, `fetch_all`, `fetch_one`, `fetch_optional`, `fetch_many`, and `select_value` on `SyncMySQLClient`/`AsyncMySQLClient`; `execute_with_description`, `query`, `fetch_all`, `fetch_one`, `fetch_optional`, and `select_value` on `SyncMSSQLClient`/`AsyncMSSQLClient`; and `query` and `query_one` on `SyncOracleClient`/`AsyncOracleClient`).

## 0.3.0

Release introducing shared-memory vector embeddings, zero-copy PEP 3118 vector views, binary database vector codecs, active Google Cloud ADC credential refresh, and the `vtb ai` CLI. It also adds co-located background worker lanes, dynamic A2A `AgentInterface` origin URL resolution, updated isometric axial vertebrae branding, and expanded topic documentation.

### Added

- **Rust HTTP Ingress & Shared-Memory IPC (`vertebra-core`, `vertebra-http`)**:
  - Hyper HTTP/1.1 and HTTP/2 server, ALPN TLS, optional HTTP/3 over QUIC, gRPC wire framing, WebSocket, and Server-Sent Events (SSE).
  - Lock-free SPSC and MPMC shared-memory ring buffers (`ShmHeader`, `SpscRing`, `MpmcRing`, `TieredRingSet`) and embedded `BatchBridge` with adaptive `futex`/`ulock` and `eventfd` signaling.
  - Opt-in `BackpressureController` with bounded in-flight permits, queue timeouts, and sliding-window circuit breaking.

  - `App`, `Controller`, `Router`, `Route`, `Procedure`, `ProcedureRouter`, `Container`/`DependencyGraph`/`Provide`/`Inject` dependency injection, `Guard`/`SecurityConfig`, `OpenAPIConfig`, `LiveState`, and `QueueService`/`CronScheduler`.
  - Multi-protocol worker execution supporting native `RequestBatch` handlers, ASGI 3.0 (`AsgiRunner`), RSGI 1.6 (`RsgiAdapter`), and PEP 3333 WSGI (`WsgiAdapter`) across isolated worker lanes (`fast`, `async`, `cpu`, `blocking`).
- **Free-Threaded Python Support (`3.14t` / `3.15t`)**:
  - Native PyO3 extensions (`vertebra._vertebra`, `vertebra._bundler`, `vertebra._storage`) compiled with `gil_used = false` and PEP 561 `.pyi` type stubs.
- **Frontend Bundler, QuickJS SSR & TypeScript SDK (`vertebra-bundler`, `@vertebra/client`)**:
  - Embedded Rolldown/Oxc bundler (`Bundler`, `BundleConfig`) and pooled QuickJS server-side rendering engine (`SyncEmbeddedSSRClient`, `AsyncEmbeddedSSRClient`, `SSRConfig`) with Inertia v3 and HTMX integration.
  - `@vertebra/client` TypeScript SDK providing `HttpClient`, `SseClient`, `WebSocketClient`, `LiveStateClient`, `ApexRegion`, `WASMClient`, `ArrowStreamClient`, `McpClient`, `A2aClient`, and framework adapters for React, Vue, Svelte, Angular, HTMX, and Vite.
- **Native Storage, Database Drivers & Telemetry (`vertebra.storage`, `vertebra.db`, `vertebra.telemetry`)**:
  - Multicloud and local object storage (`SyncObjectStore`, `AsyncObjectStore`) backed by Rust `object_store` (S3, GCS with ADC, Azure, R2, OCI, HTTP, Local, Memory) with presigned URLs and PyArrow range readers.
  - Native database drivers (`PostgreSQLConfig`, `MySQLConfig`, `SQLiteConfig`, `SyncSQLiteDriver`, `AsyncSQLiteDriver`) with OpenTelemetry `sqlcommenter` trace propagation.
- **Agent Protocols (`vertebra.agent`)**:
  - Model Context Protocol (`MCPRegistry`, `MCPConfig`, `MCPSkillsConfig`, `MCPTaskConfig`, `run_stdio_http_bridge`) and Agent-to-Agent (`A2AService`, `A2AConfig`, `AgentCard`) support plus `AgentRuntime` and `WorkflowEngine`.

  - `vtb` CLI (`run`, `dev`, `init`, `build`, `js`, `mcp`, `workers`) and standalone/single-file binary builders (`StandaloneBuilder`, `OnefileBuilder`, `BuildOrchestrator`).
