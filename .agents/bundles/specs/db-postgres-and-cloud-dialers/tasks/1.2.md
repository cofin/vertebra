# 1.2 Live CloudSqlDialer and AlloyDbDialer with IAM refresh, ephemeral X.509 cert exchange, and mTLS sockets

## Objective
Complete `CloudSqlDialer` (`src/py/vertebra/db/dialer/cloudsql.py`) and `AlloyDbDialer` (`src/py/vertebra/db/dialer/alloydb.py`) so both dialers refresh Google Cloud IAM tokens, exchange ephemeral client certificates against the Cloud SQL Admin (`generateEphemeralCert`) and AlloyDB Admin (`generateClientCertificate`) REST APIs, load client certificate/key PEM chains into TLS 1.3 `ssl.SSLContext` instances without raising `NotImplementedError`, verify AlloyDB `MetadataExchangeResponse` frames, and open mTLS sockets (`connect_sync` and `connect_async`).

## Context
- `src/py/vertebra/db/dialer/cloudsql.py:54,82` names the refresh window field `refresh_Lead_seconds` with an uppercase `L` (`FW-54`).
- `src/py/vertebra/db/dialer/cloudsql.py:111-112` raises `NotImplementedError("Use load_cert_chain with a temporary memfd/file when client PEMs are provided")` whenever `client_cert_pem` and `client_key_pem` are passed (`FW-04`).
- Neither `CloudSqlDialer` (`cloudsql.py:58-113`) nor `AlloyDbDialer` (`alloydb.py:70-124`) implements ephemeral certificate exchange, `MetadataExchangeResponse` decoding, or mTLS socket connection (`FW-04`).
- Note on test file: `src/py/tests/unit/data/test_cloud_dialers.py` verifies `test_cloudsql_and_alloydb_dialers`.
- Strategy `behavior_tdd` applies because this task implements client PEM loading, certificate exchange, and mTLS socket creation.

## Steps
- [ ] 1. In `src/py/tests/unit/data/test_cloud_dialers.py`, expand `test_cloudsql_and_alloydb_dialers` with failing tests verifying:
  - `CloudSqlConfig(instance_connection_name="my-proj:us-central1:my-pg", refresh_lead_seconds=300)` uses snake_case `refresh_lead_seconds`.
  - `CloudSqlDialer.build_tls_context(ca_pem=..., client_cert_pem=..., client_key_pem=...)` loads a valid self-signed X.509 client certificate and private key into an `ssl.SSLContext` with `minimum_version == ssl.TLSVersion.TLSv1_3` and cleans up its temporary `0o700` directory immediately.
  - `CloudSqlDialer.refresh_ephemeral_cert(public_key_pem=..., access_token="mock-oauth-token", http_transport=...)` posts `{"public_key": public_key_pem, "access_token": "mock-oauth-token"}` to `generate_ephemeral_cert_url()` and returns an `EphemeralCertBundle(ca_cert_pem=..., client_cert_pem=..., server_ip=..., expiration_ts=...)`.
  - `AlloyDbDialer.decode_metadata_exchange_response(frame)` parses the 4-byte length-prefixed protobuf response (`field 1` status enum: `1 = OK`, `2 = ERROR`, `field 2` error message string) and raises `PermissionError` when status is not `OK`.
  - `CloudSqlDialer.connect_sync` and `AlloyDbDialer.connect_sync` wrap a loopback socket pair with the configured mTLS context (and for AlloyDB, send the `MetadataExchangeRequest` frame and validate the `MetadataExchangeResponse` frame before returning the socket).
