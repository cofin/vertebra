# 1.4 Integration and acceptance tests for PostgreSQL drivers, Cloud SQL/AlloyDB dialers, and postgresql+vtb dialect

## Objective
Wire `DatabaseRegistry` (`src/py/vertebra/db/_registry.py`) to expose `get_sync_driver` and automatically attach `CloudSqlDialer` or `AlloyDbDialer` when `PostgresConfig.to_cloud_dialer_config()` is non-null, and create the chapter integration and negative-state acceptance suite in `src/py/tests/unit/data/test_postgres_driver.py` and `src/py/tests/unit/data/test_cloud_dialers.py`.

## Context
- `src/py/vertebra/db/_registry.py:103-129` (`DatabaseRegistry.get_driver`) instantiates `AsyncPostgresDriver(config)` without attaching the dialer produced by `config.to_cloud_dialer_config()` (`postgres.py:93-106`), and `DatabaseRegistry` has no `get_sync_driver(name)` method for synchronous SQLAlchemy `+vtb` engines.
- Tasks `1.1`, `1.2`, and `1.3` build the PostgreSQL driver pool, Cloud SQL/AlloyDB mTLS dialers, and `PostgresVtbDialect`. This task composes all three through `DatabaseRegistry` and verifies both end-to-end happy paths and injected refusal states (`integration_acceptance`).

## Steps
- [ ] 1. In `src/py/vertebra/db/_registry.py:32-129`, update `DatabaseRegistry`:
  - Add `_sync_drivers: dict[str, object]` to `__slots__` and `__init__` (clearing `self._sync_drivers.pop(name, None)` in `register`).
  - Add `get_sync_driver(self, name: str = "default") -> object` that instantiates and caches `SyncPostgresDriver(config, dialer=...)`, `SyncMysqlDriver(config)`, `SyncSqliteDriver(config)`, `SyncRedisDriver(config)`, `SyncValkeyDriver(config)`, `SyncOracleDriver(config)`, `CloudSqlDialer(config)`, or `AlloyDbDialer(config)`.
  - In both `get_driver` and `get_sync_driver`, when `isinstance(config, PostgresConfig)` and `(dialer_cfg := config.to_cloud_dialer_config()) is not None`, instantiate `CloudSqlDialer(dialer_cfg)` or `AlloyDbDialer(dialer_cfg)` and pass `dialer=dialer` to `AsyncPostgresDriver` / `SyncPostgresDriver`.
- [ ] 2. Create and run integration tests in `src/py/tests/unit/data/test_postgres_driver.py` and `src/py/tests/unit/data/test_cloud_dialers.py` covering end-to-end composition and refusal paths:
  - `test_database_registry_attaches_cloudsql_and_alloydb_dialers_to_postgres_drivers`: registers `PostgresConfig(dsn="postgresql://app@127.0.0.1:5432/db", cloud_sql_instance="proj:us-central1:pg1", enable_iam_auth=True)` and `PostgresConfig(dsn="postgresql://app@127.0.0.1:5432/db", alloydb_instance_uri="projects/p/locations/l/clusters/c/instances/i")` in `DatabaseRegistry` and verifies both `get_driver` and `get_sync_driver` attach the matching `CloudSqlDialer` / `AlloyDbDialer` and enable `alloydb.enable_columnar_engine = "on"` in `build_session_gucs()`.
  - `test_end_to_end_mtls_loopback_handshake_for_cloudsql_and_alloydb`: runs a local loopback TLS 1.3 server thread with ephemeral RSA certificates generated via `cryptography.x509`, verifies `CloudSqlDialer.connect_sync` and `AlloyDbDialer.connect_sync` complete TLS 1.3 mTLS negotiation and AlloyDB `MetadataExchange`, and proves refusal (`PermissionError` / `ssl.SSLError`) when an expired IAM token, an untrusted client certificate, or an AlloyDB `ERROR` response frame (`code=2`) is injected.
  - `test_postgresql_vtb_dialect_and_binary_copy_arrow_pipeline`: connects via `DBAPIModule(paramstyle="pyformat").connect("postgresql+vtb://localhost:5432/app", driver=...)`, executes `PostgresVtbDialect.compile_insert_returning_sentinel`, `PostgresVtbDialect.compile_delete_using`, `Vector(3)` bind/result round-trips, `BinaryJson` `\x01` zero-copy memoryview decoding, and `SyncPostgresDriver.stream_arrow_batches`, and verifies `ValueError` refusal when a corrupted `PGCOPY` header is injected.
- [ ] 3. Commit: `test(db): add Postgres, Cloud SQL/AlloyDB dialer, and postgresql+vtb acceptance suite` (signed), staging `src/py/vertebra/db/_registry.py`, `src/py/tests/unit/data/test_postgres_driver.py`, and `src/py/tests/unit/data/test_cloud_dialers.py`.

## Verification
- **Strategy:** `integration_acceptance` — verifies composition of `DatabaseRegistry`, `SyncPostgresDriver`/`AsyncPostgresDriver`, `CloudSqlDialer`/`AlloyDbDialer`, and `PostgresVtbDialect` alongside injected TLS/protocol refusal states.
- **Initial evidence:** `uv run pytest src/py/tests/unit/data/test_postgres_driver.py src/py/tests/unit/data/test_cloud_dialers.py -q` → fails before the task.
- **Final evidence:** `uv run pytest src/py/tests/unit/data/test_postgres_driver.py src/py/tests/unit/data/test_cloud_dialers.py src/py/tests/unit/extensions/test_sqlalchemy.py -q && uv run ruff check src/py/vertebra/db/ src/py/vertebra/extensions/sqlalchemy/ src/py/tests/unit/data/ && uv run mypy src/py/vertebra/db/ src/py/vertebra/extensions/sqlalchemy/` → all exit 0.
- **Gate proof:** Injecting an AlloyDB `MetadataExchangeResponse` with status `2` (`ERROR`) and message `"IAM token expired"` into `AlloyDbDialer.connect_sync` raises `PermissionError: AlloyDB MetadataExchange failed (code=2): IAM token expired`; injecting a truncated `PGCOPY` stream into `SyncPostgresDriver.parse_pgcopy_binary_rows` raises `ValueError: Invalid PGCOPY binary signature`.

- [ ] `make lint` exits 0; no new `# ` comments, nested imports, aliases, or private-module imports.
