# 1.3 SQLAlchemy 2.1 PostgresVtbDialect (postgresql+vtb) with Vector, BinaryJson, RETURNING sentinel, and DELETE USING

## Objective
Implement `PostgresVtbDialect` (and `SqliteVtbDialect`) in `src/py/vertebra/extensions/sqlalchemy/dialects.py`, route `postgresql+vtb://` and `postgresql+vertebra://` URLs in `DBAPIConnection` through `SyncPostgresDriver` with cursor column descriptions (`DBAPICursor.description`), integrate `Vector` (`pgvector`), `BinaryJson` (`JSONB`), `InsertSentinelSpec` (`INSERT ... RETURNING`), and `DeleteUsingClause` (`DELETE ... USING`), and align `[project.entry-points."sqlalchemy.dialects"]` in `pyproject.toml`.

## Context
- `pyproject.toml:22-30` declares entry points pointing to `PostgresVertebraDialect`, `OracleVertebraDialect`, `MysqlVertebraDialect`, and `SqliteVertebraDialect`, none of which exist in `src/py/vertebra/extensions/sqlalchemy/dialects.py` (`FW-44`).
- `src/py/vertebra/extensions/sqlalchemy/dialects.py:101-150` (`DBAPIConnection`) only creates a driver when `isinstance(self._config, SqliteConfig)` (`:109-111`), returning `[]` for `postgresql+vtb://` connections (`:136`).
- `src/py/vertebra/extensions/sqlalchemy/dialects.py:48-73` (`DBAPICursor`) leaves `self.description = None` after `execute()`, which breaks SQLAlchemy 2.1 `Result` column mapping.
- Note on `pyproject.toml`: modified after Task `1.1` (`depends_on: [db-postgres-and-cloud-dialers:1.1]`), updating lines `22-30` (`[project.entry-points."sqlalchemy.dialects"]`).
- Strategy `behavior_tdd` applies because this task adds `PostgresVtbDialect`, PostgreSQL `DBAPIConnection` execution, and cursor metadata population.
