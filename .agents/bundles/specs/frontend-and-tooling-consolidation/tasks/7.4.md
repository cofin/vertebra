# Task 7.4 — Bound `SsrPool` cache, add Condvar slot checkout, and unify the SSR API on `SsrPool`

## Objective

Replace the unbounded `DashMap` in `SsrPool` with a bounded LRU cache (`FE-04`), replace immediate `PoolExhausted` failure with a `Condvar`-backed bounded wait (`FE-05`), share `bundle_source` via `Arc<str>` and cache the `__ssr_render` JS function handle per slot (`FE-06`), make `SsrPool` the single SSR pyclass surface used directly by `NativeSsrClient` (`FE-07`), trim unused `rquickjs`/`dashmap`/`crossbeam-queue` dependencies (`FE-10`), and add concurrent SSR pool, cache-eviction, and Criterion benchmark coverage (`TST-11`).

## Context

- `src/rs/vertebra-bundler/src/ssr.rs:63,152-157,246-253` stores every rendered page in `cache: DashMap<u64, CachedRender>` with no maximum entry count (`FE-04`).
- `ssr.rs:159` pops from `available: ArrayQueue<usize>` and immediately returns `Err(BundlerError::PoolExhausted)` when all `pool_size` slots are busy (`FE-05`).
- `ssr.rs:59,171-208` stores `bundle_source: RwLock<String>`, clones the entire `String` on every slot build, and looks up `globals.get("__ssr_render")` + `JSON.parse` on every render (`FE-06`).
- `src/rs/vertebra-bundler/src/bundler.rs:28,152-206` duplicates the entire `SsrPool` API on `Bundler` (`init_ssr`, `ssr_render`, `ssr_invalidate`, `ssr_shutdown`) and converts `SsrResult` into a `HashMap<String, Py<PyAny>>` on every call (`FE-07`).
- `src/rs/vertebra-bundler/Cargo.toml:33` enables `rquickjs` features `["bindgen", "classes", "properties", "parallel"]` when `ssr.rs` only uses `Runtime`, `Context`, `Function`, `Object`, and `Value`, and `ssr.rs:48` has `unsafe impl Send for SlotEngine {}` (`FE-10`).

## Steps

1. Write failing Rust and Python tests first (`regression_tdd`, `TST-11`):
   - In `src/rs/vertebra-bundler/src/ssr.rs` tests:
     - `test_ssr_pool_concurrent_checkout_waits_for_slot`: create a 2-slot `SsrPool`, spawn 8 threads that each call `pool.render("App", r#"{"id":1}"#)` concurrently, and assert all 8 succeed without `PoolExhausted`.
     - `test_ssr_pool_cache_bounded_eviction`: render 300 distinct props payloads on a pool with max cache capacity `256` and assert `pool.cache_len() <= 256`.
   - In `src/py/tests/unit/framework/test_ssr.py`: update `NativeSsrClient` tests to verify direct `SsrPool` instantiation and `SsrResult(head, body)` attribute access.
2. In `src/rs/vertebra-bundler/Cargo.toml`:
   - Remove `dashmap = { workspace = true }` and `crossbeam-queue = { workspace = true }` from `[dependencies]`.
   - Trim `rquickjs` features to `["parallel"]` (retaining `"bindgen"` only if required by the workspace `rquickjs 0.14` build script).
   - Register the Criterion benchmark:
     ```toml
     [dev-dependencies]
     criterion = { workspace = true }
     tempfile = "3"

     [[bench]]
     name = "ssr_render"
     harness = false
     ```
3. In `src/rs/vertebra-bundler/src/ssr.rs`:
   - Remove `unsafe impl Send for SlotEngine {}` if `rquickjs::Runtime` and `rquickjs::Context` are `Send` under the `parallel` feature; if `SlotEngine` adds `rquickjs::Persistent<Function<'static>>` that is not `Send`, keep `SlotEngine` holding `Runtime` + `Context` with a pre-installed `__vtb_call_ssr(component, page_json)` wrapper function evaluated once at `SlotEngine::new` so `SlotEngine::render` invokes `__vtb_call_ssr` in a single step without re-evaluating `JSON.parse` shims.
   - Change `bundle_source` from `RwLock<String>` to `RwLock<Arc<str>>` so slot rebuilds clone the `Arc<str>` in $O(1)$ without copying the bundle string (`FE-06`).
   - Replace `available: ArrayQueue<usize>` with `checkout: (Mutex<VecDeque<usize>>, Condvar)` and `acquire_timeout: Duration` (default `Duration::from_millis(500)`). On checkout, wait on the `Condvar` until a slot index is available or `acquire_timeout` elapses, returning `Err(BundlerError::PoolExhausted)` only on timeout; on slot return (via an RAII `SlotLease` drop guard), push the slot index back and call `condvar.notify_one()` (`FE-05`).
   - Replace `cache: DashMap<u64, CachedRender>` with a bounded `Mutex<BoundedRenderCache>` (capacity `256`, TTL `Duration::from_secs(60)`) that evicts expired entries first and the oldest entry when full (`FE-04`).
4. In `src/rs/vertebra-bundler/src/bundler.rs`, `src/py/vertebra/_bundler.pyi`, and `src/py/vertebra/framework/ssr/__init__.py` (`FE-07`):
   - Remove `ssr_pool: Mutex<Option<Arc<SsrPool>>>` and the 4 duplicate methods (`init_ssr`, `ssr_render`, `ssr_invalidate`, `ssr_shutdown`) from `Bundler` in `bundler.rs`.
   - In `src/py/vertebra/_bundler.pyi`: remove `Bundler.init_ssr`, `Bundler.ssr_render`, `Bundler.ssr_invalidate`, and `Bundler.ssr_shutdown` stubs, and update the `SsrPool` class stub (`render(self, component: str, page_json: str) -> SsrResult`, `invalidate(self) -> None`, `shutdown(self) -> None`, `cache_len(self) -> int`).
   - In `src/py/vertebra/framework/ssr/__init__.py` (consolidated in `5.5`), change `NativeSsrClient` to hold `self._pool = bundler_mod.SsrPool(bundle_path, pool_size)`, call `res = self._pool.render(page.get("component", ""), encode_json(page))` reading `SsrResult(head=res.head, body=res.body)` directly, call `self._pool.invalidate()` in `invalidate`, and call `self._pool.shutdown()` in `stop`.
5. Create `src/rs/vertebra-bundler/benches/ssr_render.rs` benchmarking `SsrPool::render` on both cache-hit and cache-miss (`invalidate()` before render) paths using Criterion.

## Acceptance Criteria

- [x] `SsrPool` bounds its render cache to at most 256 entries with 60 s TTL expiration (`FE-04`).
- [x] `SsrPool::render` blocks on a `Condvar` up to 500 ms for a free QuickJS slot and releases the slot via an RAII guard on return or panic (`FE-05`).
- [x] `SsrPool` stores `bundle_source` as `Arc<str>` without per-slot `String` cloning (`FE-06`).
- [x] Duplicate `Bundler::init_ssr`/`ssr_render`/`ssr_invalidate`/`ssr_shutdown` methods are removed, `src/py/vertebra/_bundler.pyi` stubs are updated, and `NativeSsrClient` in `src/py/vertebra/framework/ssr/__init__.py` uses `SsrPool` and `SsrResult.head`/`.body` directly (`FE-07`).
- [x] `src/rs/vertebra-bundler/benches/ssr_render.rs` compiles and passes `--test`, and all Rust/Python SSR tests pass (`TST-11`).
