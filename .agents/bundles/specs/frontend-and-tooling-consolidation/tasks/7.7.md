# Task 7.7 — Fix `@vertebra/client` `tsup.config.ts` entry points, `WasmClient` `.d.ts` return type, and CI `make ts-build` gate

## Objective

Fix the broken `tsup.config.ts` entry list (`src/react/index.tsx`, `src/wasm.ts`, `src/arrow.ts`) and `package.json` `./hmr` export (`FE-28`, `FE-29`), fix the TypeScript `TS2739` declaration build failure in `src/wasm.ts:41` (`FE-30`), and add `make ts-build` to `.github/workflows/ci.yml` (`FE-31`).

## Context

- `src/ts/vertebra-client/tsup.config.ts:11` specifies `"src/react/index.ts"`, but the actual source file is `src/ts/vertebra-client/src/react/index.tsx`. `tsup` silently ignores the missing path and never emits `dist/react/index.js` or `dist/react/index.d.ts`, breaking `@vertebra/client/react` (`package.json:18-21`) (`FE-28`).
- `src/ts/vertebra-client/package.json:42-49` exports `./wasm` (`./dist/wasm.js`, `./dist/wasm.d.ts`) and `./arrow` (`./dist/arrow.js`, `./dist/arrow.d.ts`), but `tsup.config.ts:8-21` omits `"src/wasm.ts"` and `"src/arrow.ts"`. Conversely, `tsup.config.ts:17` builds `"src/hmr/index.ts"`, which has no `./hmr` entry in `package.json` `exports` (`FE-29`).
- `src/ts/vertebra-client/src/wasm.ts:37-42` declares `instantiateBytes(bytes: Uint8Array): Promise<WebAssembly.WebAssemblyInstantiatedSource>` and returns `WebAssembly.instantiate(bytes, this.baseImports)`. Under `@types/node` `^26.6.5` / TypeScript `5.9.3`, `WebAssembly.instantiate(BufferSource, Imports)` resolves to `Promise<WebAssembly.Instance>` when passed a `Uint8Array` (unless compiled from `WebAssembly.compile` or normalized), causing `tsup --dts` to fail with `error TS2739: Type 'Instance' is missing the following properties from type 'WebAssemblyInstantiatedSource': instance, module` (`FE-30`).
- `.github/workflows/ci.yml:124-135` (`test-typescript`) runs `make ts-install` and `make ts-test` without `make ts-build`, and `lint` (`ci.yml:45-61`) runs `make lint-all` (`biome check .` without `tsc --noEmit` or `tsup`), so the broken TypeScript build was never caught in CI (`FE-31`).

## Steps

1. Reproduce the failing build first (`regression_tdd`):
   - Run `make ts-build` and confirm that `tsup` fails in the `DTS` step on `src/wasm.ts:41` (`TS2739`) and that `dist/react/index.js`, `dist/wasm.js`, and `dist/arrow.js` are missing.
2. In `src/ts/vertebra-client/src/wasm.ts:37-42` (`FE-30`):
   - Compile the validated `Uint8Array` via `const module = await WebAssembly.compile(bytes);` and instantiate via `const instance = await WebAssembly.instantiate(module, this.baseImports); return { module, instance };` so `instantiateBytes` deterministically returns `Promise<WebAssembly.WebAssemblyInstantiatedSource>` across all DOM and Node TypeScript lib definitions.
3. In `src/ts/vertebra-client/tsup.config.ts:8-21` (`FE-28`, `FE-29`):
   - Change `"src/react/index.ts"` to `"src/react/index.tsx"`.
   - Add `"src/wasm.ts"` and `"src/arrow.ts"` to the `entry` array.
4. In `src/ts/vertebra-client/package.json:9-62` (`FE-29`):
   - Add `"./hmr": { "types": "./dist/hmr/index.d.ts", "import": "./dist/hmr/index.js" }` to `"exports"`.
5. In `.github/workflows/ci.yml:124-135` (`FE-31`):
   - Add a `- name: Build TypeScript package` step running `make ts-build` before `make ts-test` in the `test-typescript` job.
6. In `src/ts/vertebra-client/tests/wasm.test.ts`:
   - Add a test asserting that `instantiateBytes` returns an object with both `module` (`WebAssembly.Module`) and `instance` (`WebAssembly.Instance`) and that every subpath declared in `package.json#exports` has a corresponding built `.js` and `.d.ts` file in `dist/` after `bun run build`.
