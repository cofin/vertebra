# 4.9 RSGI protocol

## Objective

Split `rsgi_scope.rs` and `rsgi_protocol.rs` into `src/rs/vertebra-py/src/rsgi/{mod,scope,http}.rs`, fix `RsgiHttpProtocol.client_disconnect()` so it waits until explicit disconnect signaling instead of resolving immediately (`PYB-37`), stream `RsgiTransport.send_bytes`/`send_str` chunks as `FrameFlags::STREAMING` frames (and `std::mem::take` buffered chunks in non-transport unit mode instead of copying) (`PYB-37`), deduplicate `RsgiAdapter.run_single` and `handle_http` onto `request.rsgi_scope()` and `request.rsgi_protocol()` while deleting the `handle_request` alias (`PYB-36`), share a single frozen `RsgiDone` awaitable for `None`-returning operations (`PYB-39`), and move the in-memory `RsgiWebsocketProtocol` test double out of the production `_vertebra` module into `test_rsgi_protocol.py` (`PYB-38`).

## Context

- **`PYB-37` (`src/rs/vertebra-py/src/rsgi_protocol.rs:35-62,124-126,244-258`):** `RsgiHttpProtocol.client_disconnect()` returns `_RsgiReadyAwaitable::none()`, which resolves on the very first `await` tick—causing any RSGI application using `asyncio.wait({task, protocol.client_disconnect()})` to abort the request immediately as if the client disconnected. In addition, `response_stream` buffers all chunks in `Arc<Mutex<Vec<u8>>>` and `take_response` copies the buffer a second time via `Bytes::copy_from_slice(&buf)`.
- **`PYB-36` (`src/py/vertebra/server/_rsgi/_adapter.py:89-158`, `src/rs/vertebra-py/src/request.rs:246-251`):** `RsgiAdapter.run_single` reads `request.body` (allocating `PyBytes`) and passes it into `RsgiHttpProtocol(body=...)` (which copies it into `Bytes` a second time), ignoring `request.rsgi_protocol()` which slices the slab directly. `handle_request` is an alias for `run_single`, and `handle_http` duplicates `run_single`.
- **`PYB-38` (`src/rs/vertebra-py/src/rsgi_protocol.rs:271-353`):** `RsgiWebsocketProtocol` is an in-memory mock (`incoming: Vec<...>`, `sent_messages()`) with zero production callers.
- **`PYB-39` (`src/rs/vertebra-py/src/rsgi_protocol.rs:13,52-62,318-353`) & `PYB-49` (RSGI mutex half, `rsgi_protocol.rs:130-134,232-240`):** Every `send_bytes` and `send_str` allocates a new `_RsgiReadyAwaitable` pyclass instance on the heap, and `self.state.lock()` uses `if let Ok(mut st) = ...` which silently drops operations when poisoned.
- **Symbol overlap note (depends on 4.8):** Moves `rsgi_scope.rs` (touched in 4.4) and `rsgi_protocol.rs` (touched in 4.1, 4.3) into `rsgi/`, updates `lib.rs`, `request.rs`, `_vertebra.pyi`, and `_rsgi/_adapter.py`.
- **Strategy justification:** `regression_tdd` is required because awaiting `protocol.client_disconnect()` currently resolves immediately while the request is still active.

## Steps

- [x] 1. In `src/py/tests/unit/server/test_rsgi_protocol.py`, add a failing regression test `test_rsgi_client_disconnect_remains_pending_until_signaled` that starts an async task awaiting `protocol.client_disconnect()`, yields to the event loop (`await asyncio.sleep(0)`), asserts `not task.done()`, then calls `protocol.notify_disconnect()` and asserts `await task is None`.
- [x] 2. Split `src/rs/vertebra-py/src/rsgi_scope.rs` and `src/rs/vertebra-py/src/rsgi_protocol.rs` into `src/rs/vertebra-py/src/rsgi/{mod,scope,http}.rs` (deleting `rsgi_scope.rs` and `rsgi_protocol.rs`):
  - In `rsgi/http.rs` (`PYB-37`): back `client_disconnect(&self, py: Python<'_>) -> PyResult<Py<PyAny>>` with an `asyncio.Future` created lazily on the running event loop and stored on `RsgiHttpProtocol`, resolved only when `notify_disconnect(&self, py: Python<'_>)` is called (or when the request context closes).
  - In `RsgiTransport` (`PYB-37`): when SHM/bridge streaming is active (`request_id != 0`), emit `HEADERS_SENT | STREAMING` on `response_stream(status, headers)`, `STREAMING` frames on `send_bytes`/`send_str` (detached via `ResponseSubmitter`), and `STREAMING | FINAL` when the handler finishes; in buffered fallback mode, `std::mem::take(&mut *buf)` into `Bytes::from` without copying, and convert mutex poisoning into `PyRuntimeError` (`.map_err(|_| PyRuntimeError::new_err("RSGI state lock poisoned"))?`) instead of ignoring it with `if let Ok(...)` (`PYB-49` RSGI half).
  - Replace per-call `_RsgiReadyAwaitable::none()` allocations with a process-wide frozen `RsgiDone` singleton stored in `PyOnceLock<Py<RsgiDone>>` (`PYB-39`).
  - Remove `RsgiWebsocketProtocol` from `src/rs/vertebra-py/` and `src/py/vertebra/_vertebra.pyi`, and replace its usage in `src/py/tests/unit/server/test_rsgi_protocol.py` with a local Python fixture class (`PYB-38`).
- [x] 3. In `src/py/vertebra/server/_rsgi/_adapter.py` (`PYB-36`):
  - Update `RsgiAdapter.run_single` to call `scope = request.rsgi_scope(self._mount_prefix)` and `proto = request.rsgi_protocol()` directly (avoiding the double body copy).
  - Delete the `handle_request` alias, and make `handle_http(method, path, query_string, headers, body)` construct `Request.from_parts(method, path, query_string, headers, body)` and delegate to `self.run_single(req)`.
- [x] 4. Update `src/rs/vertebra-py/src/lib.rs`, `src/rs/vertebra-py/src/request.rs`, and `src/py/vertebra/_vertebra.pyi` for the `rsgi` module changes.
- [x] 5. Commit: `fix(rsgi): await real client_disconnect, stream RSGI chunks, and deduplicate RsgiAdapter` (signed), staging exactly the paths in `files`.

## Verification

- **Strategy:** `regression_tdd` — `client_disconnect()` previously resolved immediately on first poll; the new test fails before the fix and passes once backed by a pending future resolved on disconnect.
- **Initial evidence:** `uv run pytest src/py/tests/unit/server/test_rsgi_protocol.py -k "client_disconnect_remains_pending" -q` → fails because `task.done()` is immediately `True`.
- **Final evidence:** `make dev && cargo test --manifest-path src/rs/Cargo.toml -p vertebra-py && uv run pytest src/py/tests/unit/server/test_rsgi_protocol.py -q && uv run python -m mypy.stubtest vertebra._vertebra && make lint` → exits 0.
