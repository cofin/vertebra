# 4.5 Single WSGI path

## Objective

Split `wsgi_environ.rs` and `wsgi_worker.rs` into `src/rs/vertebra-py/src/wsgi/{mod,environ,input,runner}.rs`, fix `WsgiEnviron` to combine duplicate HTTP headers with `", "` per PEP 3333 consistently before and after key iteration (`PYB-29`, `PYB-30`), look up `sys.stderr` dynamically for `wsgi.errors` (`PYB-50`), avoid holding a `std::sync::Mutex` across Python C-API calls in `WsgiStartResponse` (`PYB-49`), make native `run_wsgi_callable` the sole WSGI execution path while deleting Python `_wsgi/_environ.py` and `_wsgi/_runner.py` (`PYB-31`), and make `LargeBodyBypass` in `_wsgi/_frameworks.py` stream `wsgi.input` directly from the native `WsgiInput` slab cursor without materializing the body (`PYB-33`).

## Context

- **`PYB-29` & `PYB-30` (`src/rs/vertebra-py/src/wsgi_environ.rs:286-298,338-430,578-580`):** Before `ensure_headers` runs, `WsgiEnviron.__getitem__("HTTP_X_FOO")` returns the first matching header; after `keys()` or `len()` triggers `ensure_headers`, it builds a `HashMap<String, String>` where the last duplicate overwrites earlier ones. PEP 3333 requires combining multiple headers of the same name with `", "`. Furthermore, `__len__` and `__iter__` call `collect_keys`, formatting every `HTTP_*` key into a new `String` on every call.
- **`PYB-31` (`src/py/vertebra/server/_wsgi/_environ.py:34-180`, `_wsgi/_runner.py:34-112`, `_wsgi/_adapter.py:30-120`, `src/rs/vertebra-py/src/wsgi_worker.rs:57-128`):** Three WSGI environs/runners exist (`WsgiEnviron` in Rust, `WsgiEnviron`/`BodyStream` in Python, `run_wsgi_callable` in Rust used only by tests, `WsgiAdapter.run_environ` in Python, and an unused `WsgiRunner` loop).
- **`PYB-33` (`src/py/vertebra/server/_wsgi/_extensions.py:45-67`):** `LargeBodyBypass` parses `CONTENT_LENGTH` and only logs a debug message without changing `wsgi.input` handling.
- **`PYB-49` (`src/rs/vertebra-py/src/wsgi_worker.rs:35-42`):** `WsgiStartResponse.__call__` locks `self.state.lock()` and then invokes `exc.get_item(1)` and `PyErr::from_value` while holding the Rust mutex, risking lock-order deadlocks with the GIL on 3.14t.
- **`PYB-50` (`src/rs/vertebra-py/src/wsgi_environ.rs:16,329-334`):** `wsgi.errors` caches `sys.stderr` once per process in a `PyOnceLock`, ignoring later `sys.stderr` redirection in tests or logging setups.
- **Symbol overlap note (depends on 4.4):** Splits `wsgi_environ.rs` and `wsgi_worker.rs` (touched in 4.1, 4.3, 4.4) into `wsgi/`, updates `request.rs` (`wsgi_environ` import), and updates `server/_native.py` to remove `_wsgi/_runner.py` imports.
- **Strategy justification:** `regression_tdd` is required because duplicate HTTP headers currently lose values and return different results before vs after `keys()`/`len()`, and `wsgi.errors` ignores `sys.stderr` reassignment.

## Steps

- [x] 1. In `src/py/tests/unit/server/test_wsgi.py`, add three failing regression tests:
  - `test_wsgi_environ_combines_duplicate_headers_consistently`: builds a `Request` with two `Accept: text/html` and `Accept: application/json` headers (and two `X-Custom` headers) and asserts `env["HTTP_ACCEPT"] == "text/html, application/json"` both before and after calling `len(env)` and `list(env.keys())`.
  - `test_wsgi_errors_reflects_reassigned_stderr`: monkeypatches `sys.stderr` to a `StringIO` buffer after importing `_vertebra`, reads `env["wsgi.errors"]`, writes to it, and asserts the new `StringIO` receives the output.
  - `test_large_body_bypass_streams_from_slab_without_full_read`: wraps a WSGI app in `LargeBodyBypass(threshold=64)`, sends a 256-byte body, reads two 32-byte chunks via `env["wsgi.input"].read(32)`, and asserts `wsgi.input` is the zero-copy `WsgiInput` positioned at byte 64 without pre-buffering.
- [x] 2. Split `src/rs/vertebra-py/src/wsgi_environ.rs` and `src/rs/vertebra-py/src/wsgi_worker.rs` into `src/rs/vertebra-py/src/wsgi/{mod,environ,input,runner}.rs` (deleting `wsgi_environ.rs` and `wsgi_worker.rs`):
  - In `wsgi/environ.rs` (`PYB-29`, `PYB-30`, `PYB-50`): build the CGI header index once in `OnceLock<Vec<(Box<str>, Box<str>)>>`, combining duplicate header names with `", "` in wire order; have `__getitem__`, `__contains__`, `__len__`, and `__iter__` read from that single precomputed slice; and look up `py.import("sys")?.getattr("stderr")` on `"wsgi.errors"` access instead of caching in `PyOnceLock`.
  - In `wsgi/input.rs`: keep `WsgiInput` (zero-copy cursor over the `BatchSnapshot` body slice) and `WsgiFileWrapper`.
  - In `wsgi/runner.rs` (`PYB-49`): in `WsgiStartResponse::__call__`, extract `status_code`, `response_headers`, and any `exc_info` `PyErr` *before* acquiring `self.state.lock()` (returning `PyRuntimeError` if the mutex is poisoned), and invoke `PyErr::restore` after releasing the mutex guard.
- [x] 3. Consolidate the Python WSGI package (`PYB-31`, `PYB-33`):
  - Delete `src/py/vertebra/server/_wsgi/_environ.py` and `src/py/vertebra/server/_wsgi/_runner.py`.
  - Rename `src/py/vertebra/server/_wsgi/_extensions.py` to `src/py/vertebra/server/_wsgi/_frameworks.py`. In `LargeBodyBypass`, when `CONTENT_LENGTH > self.threshold`, set `environ["vertebra.large_body_bypass"] = True` and ensure `environ["wsgi.input"]` is the unbuffered slab-backed `WsgiInput` cursor (exposing `remaining_bytes`) rather than reading the payload into memory.
  - Update `src/py/vertebra/server/_wsgi/_adapter.py` so `WsgiAdapter.__call__` and `run_single` delegate directly to native `run_wsgi_callable(self._app, request.wsgi_environ(...), request.request_id)` (with `SyntheticRequest` via `WsgiEnviron.from_parts` when called from dict test helpers).
  - Update `src/py/vertebra/server/_wsgi/__init__.py` and `src/py/vertebra/server/_native.py` to drop `WsgiRunner`, `BodyStream`, and Python `WsgiEnviron` imports.
- [x] 4. Update `src/rs/vertebra-py/src/lib.rs`, `src/rs/vertebra-py/src/request.rs`, and `src/py/vertebra/_vertebra.pyi` to match the `wsgi/` module exports.
- [x] 5. Commit: `fix(wsgi): combine duplicate headers per PEP 3333 and unify on native run_wsgi_callable` (signed), staging exactly the paths in `files`.
