# 4.4 Shared request primitives

## Objective

Merge `src/rs/vertebra-py/src/batch.rs` into `src/rs/vertebra-py/src/request.rs`, extract a single `SyntheticRequest::build` helper in `src/rs/vertebra-py/src/synthetic.rs` for all `from_parts` constructors (`PYB-43`), add `get_all` to `Headers` and delete the duplicate `RsgiHeaders` pyclass (`PYB-34`), make `HeadersIterator` advance over `iter_raw_headers` with interned header names (`PYB-44`), make `RsgiScope` lazy over `Arc<BatchSnapshot>` (`PYB-35`), and cache `Request.body` and `Request.headers` in `OnceLock` so repeated reads across ASGI/WSGI/RSGI do not re-copy the slab (`PYB-28`, `PYB-45`).

## Context

- **`PYB-43` (`src/rs/vertebra-py/src/asgi_scope.rs:219-299`, `src/rs/vertebra-py/src/request.rs:62-108`, `src/rs/vertebra-py/src/wsgi_environ.rs:438-501`):** Four separate constructors build synthetic single-node `BatchSnapshot`s and duplicate the HTTP method-tag table with inconsistent unknown-method fallbacks (`0`, `255`, `0`).
- **`PYB-34` & `PYB-44` (`src/rs/vertebra-py/src/rsgi_scope.rs:11-123`, `src/rs/vertebra-py/src/headers.rs:63-210`):** `RsgiHeaders` allocates `Vec<(String, String)>` eagerly and duplicates `Headers` except for `get_all`. `HeadersIterator::__next__` re-implements compact header byte parsing instead of using `RawHeaders` / `iter_raw_headers` and allocates an owned `String` on every key.
- **`PYB-35` (`src/rs/vertebra-py/src/rsgi_scope.rs:142-171`):** `RsgiScope::from_batch` eagerly allocates 8 `String`s plus `RsgiHeaders` for every request even when the handler only inspects `scope.path`.
- **`PYB-28` & `PYB-45` (`src/rs/vertebra-py/src/request.rs:47-54,139-147`, `src/py/vertebra/server/_asgi/_queues.py:58-68`):** `Request.headers` copies the header slice into a new `Bytes` and constructs a new `Headers` pyclass on every read; `Request.body` allocates a fresh `PyBytes` copy on every read, and `AsgiReceive` re-wraps it with `isinstance(..., bytes)`.
- **Symbol overlap note (depends on 4.3):** Updates `lib.rs`, `request.rs`, `asgi_scope.rs`, `wsgi_environ.rs`, `rsgi_scope.rs`, `transport.rs`, `_vertebra.pyi`, and `_asgi/_queues.py`.
- **Strategy justification:** `characterization` is used because `Request`, `Headers`, `AsgiScope`, `WsgiEnviron`, and `RsgiScope` preserve their Python-facing behavior while eliminating eager allocations and duplicate copies, gated by `make bench-micro`.

  ```rust
  impl SyntheticRequest {
      pub fn build(
          method: &str,
          path: &str,
          query: &str,
          headers: &[(&[u8], &[u8])],

  }
  ```

- [x] 2. Merge `src/rs/vertebra-py/src/batch.rs` into `src/rs/vertebra-py/src/request.rs` (delete `batch.rs`) and cache `body_cache: OnceLock<Py<PyBytes>>` and `headers_cache: OnceLock<Py<Headers>>` on `Request` (`PYB-28`, `PYB-45`). In `src/py/vertebra/server/_asgi/_queues.py:58-68`, read `self._request.body` directly without the redundant `isinstance` / `bytes(...)` re-wrap.

  - Add `pub fn get_all(&self, key: &str) -> Vec<String>` and `#[pyo3(signature = (key, default=None))] pub fn get(&self, key: &str, default: Option<&str>) -> Option<String>`.
