# 4.2 One response submit path

## Objective

Rename `src/rs/vertebra-py/src/api.rs` to `src/rs/vertebra-py/src/transport.rs`, unify `submit_results` and `submit_response` onto a single `ResponseSubmitter` (`PYB-05`), make `submit_raw_response` execute all ring/transport writes inside `py.detach` without double-encoding frames and propagate `TransportError` as `PyRuntimeError` (`PYB-03`), and add `Response.error(status, request_id)` in `src/rs/vertebra-py/src/response.rs` with interned static error bodies to support unified error handling.

## Context

- **`PYB-03` (`src/rs/vertebra-py/src/api.rs:346-363,414-419`):** `submit_raw_response` calls `send_shm_response_detached` and `send_response_bytes` while holding the GIL, ignores every transport failure with `let _ =`, and encodes the `ResponseSlot` frame twice (once into a `Vec<u8>` to return to Python even in SHM mode, and again inside `send_response`).
- **`PYB-05` (`src/rs/vertebra-py/src/api.rs:110-185,190-252`):** `submit_results` and `submit_response` duplicate SHM preparation, `(bool, TransportError)` error mapping (`:148-156` vs `:218-226`), and the `BatchBridge` fallback, and both emit the stale error string `"Transport not initialized — call init_batch_channel() first"` naming a function that no longer exists.
- **`Response.error` (Rust prerequisite for `PYB-14` in Task 4.7):** `src/rs/vertebra-py/src/response.rs` lacks a static constructor for standard `500`/`404`/`503` error responses, causing 14 Python call sites to allocate new error bodies and headers inline.
- **Symbol overlap note (depends on 4.1):** Renames `api.rs` (touched in 4.1 for `ring_name`) to `transport.rs`, updates `response.rs` (`Response::error`), and updates `_vertebra.pyi` (`Response.error` stub).
- **Strategy justification:** `regression_tdd` is required because `submit_raw_response` silently swallows transport errors (`PayloadTooLarge` / uninitialized transport) instead of raising `RuntimeError`.

## Steps

- [x] 1. In `src/py/tests/unit/server/test_zero_copy_buffer.py` and `src/py/tests/unit/ffi/test_ffi.py`, add two failing regression tests:
  - `test_submit_raw_response_raises_runtime_error_on_oversized_frame`: initializes an SHM transport, calls `submit_raw_response` with a body exceeding the maximum tier capacity, and asserts `pytest.raises(RuntimeError, match="PayloadTooLarge|too large")`.
  - `test_uninitialized_submit_error_names_init_transport`: calls `submit_response` when no transport or bridge is initialized and asserts the `RuntimeError` message references `init_transport()`.
- [x] 2. Rename `src/rs/vertebra-py/src/api.rs` to `src/rs/vertebra-py/src/transport.rs` and update `src/rs/vertebra-py/src/lib.rs` (`mod transport;`).
- [x] 3. In `src/rs/vertebra-py/src/transport.rs`, implement `ResponseSubmitter` (`PYB-05`):
  ```rust
  struct PreparedResponse {
      request_id: u64,
      status: u16,
      flags: FrameFlags,
      headers_raw: Bytes,
      body: Bytes,
  }
  ```
  Have both `submit_results` and `submit_response` extract `PreparedResponse` items and delegate to `ResponseSubmitter::submit(py, items)`:
  - When SHM `TRANSPORT` is active, write `ResponseSlot` frames inside `py.detach(|| ...)` and flush the response notifier once at the end of the slice.
  - When `BatchBridge::get()` is active, submit `BridgeResponse` items inside `py.detach(|| ...)`.
  - When neither is initialized, return `Err(PyRuntimeError::new_err("Transport not initialized — call init_transport() first"))`.
- [x] 4. Fix `submit_raw_response` in `src/rs/vertebra-py/src/transport.rs` (`PYB-03`):
  - When SHM `TRANSPORT` is initialized, encode each frame once directly into the ring inside `py.detach(|| ...)`, propagate any `TransportError` as `PyRuntimeError`, and return `Ok(Vec::new())`.
  - Only materialize and return `Vec<Py<PyBytes>>` frames when no transport is initialized (for unit tests inspecting wire framing).
- [x] 5. In `src/rs/vertebra-py/src/response.rs`, add `#[staticmethod] #[pyo3(signature = (status=500, request_id=0))] pub fn error(status: u16, request_id: u64) -> Self` using static `Bytes::from_static` bodies (`b"Internal Server Error"`, `b"Not Found"`, `b"Bad Gateway"`, `b"Service Unavailable"`) and pre-encoded `content-type: text/plain; charset=utf-8` headers, and add `Response.error` to `src/py/vertebra/_vertebra.pyi`.
- [x] 6. Commit: `fix(py): unify ResponseSubmitter in transport.rs and propagate detached submit_raw_response errors` (signed), staging exactly the paths in `files`.

## Verification

- **Strategy:** `regression_tdd` — `submit_raw_response` previously discarded `TransportError` with `let _ =` and `submit_response` emitted a stale `init_batch_channel()` error string; the new tests fail before the change and pass after.
- **Initial evidence:** `uv run pytest src/py/tests/unit/server/test_zero_copy_buffer.py src/py/tests/unit/ffi/test_ffi.py -k "oversized_frame or init_transport" -q` → fails before the fix (`submit_raw_response` does not raise `RuntimeError`, and error text says `init_batch_channel()`).
- **Final evidence:** `make dev && cargo test --manifest-path src/rs/Cargo.toml -p vertebra-py && uv run pytest src/py/tests/unit/ffi/test_ffi.py src/py/tests/unit/server/test_zero_copy_buffer.py -q && uv run python -m mypy.stubtest vertebra._vertebra` → exits 0.
