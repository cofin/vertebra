# Task 1.1: Wire `ValkeyConfig.build_handshake_commands`, GCP Memorystore IAM token provider, and bounded LRU `_client_cache` into `SyncValkeyDriver` and `AsyncValkeyDriver`

## Objective

Wire `ValkeyConfig.build_handshake_commands` (`src/py/vertebra/db/valkey.py:38-55`) into `SyncRedisDriver._connect_socket` and `AsyncRedisDriver._create_connection` (`src/py/vertebra/db/redis.py`) so live sockets execute both `HELLO 3` (with GCP Memorystore IAM token refresh when `enable_gcp_memorystore_iam=True`) and `CLIENT TRACKING ON ... BCAST`, and bound `_client_cache` in `SyncValkeyDriver` and `AsyncValkeyDriver` with an LRU `max_cached_keys: int = 4096` cap.

## Context

- `src/py/vertebra/db/valkey.py:38-55`: `ValkeyConfig.build_handshake_commands` builds `[HELLO 3 ..., CLIENT TRACKING ON [PREFIX ...] BCAST]`, but `SyncRedisDriver._connect_socket` and `AsyncRedisDriver._create_connection` only send `encode_hello3_handshake`.
- `src/py/vertebra/db/valkey.py:68-73, 138-143`: `self._client_cache: dict[str, bytes] = {}` has no upper bound.

## Steps

- [ ] 1. Add `max_cached_keys: int = 4096` and `iam_token_provider: Callable[[], str] | None = None` to `ValkeyConfig` (`src/py/vertebra/db/valkey.py:23-33`).
- [ ] 2. In `src/py/vertebra/db/redis.py`, add `_build_handshake_frames(self) -> list[bytes]` on `SyncRedisDriver` and `AsyncRedisDriver` (overridden by `SyncValkeyDriver` and `AsyncValkeyDriver` to call `self._valkey_config.build_handshake_commands(iam_token=...)`) and execute every handshake command sequentially on newly opened sockets.
- [ ] 3. Replace `_client_cache: dict[str, bytes]` in `SyncValkeyDriver` and `AsyncValkeyDriver` (`src/py/vertebra/db/valkey.py:68-130, 138-201`) with `collections.OrderedDict[str, bytes]`, calling `move_to_end(key)` on hit/set and `popitem(last=False)` when `len(self._client_cache) > self._valkey_config.max_cached_keys`.
- [ ] 4. Add unit tests in `src/py/tests/unit/db/test_redis_valkey.py` verifying live loopback socket execution of `HELLO 3` + `CLIENT TRACKING ON ... BCAST`, Memorystore IAM token injection, and `max_cached_keys` LRU eviction.

## Verification

- **Strategy**: `behavior_tdd` — New observable socket handshake sequence and bounded LRU client cache in `SyncValkeyDriver` / `AsyncValkeyDriver`.
- **Initial Failing Proof**: Connecting `SyncValkeyDriver` to a loopback socket server records only `HELLO 3` without `CLIENT TRACKING ON BCAST`, and inserting `> max_cached_keys` entries does not evict the oldest key.
- **Final Verification Commands**:
  ```bash
  uv run pytest src/py/tests/unit/db/test_redis_valkey.py -q
  ```

## Acceptance Criteria

- [ ] `crit-1`: Newly opened sockets in `SyncValkeyDriver` and `AsyncValkeyDriver` send both `HELLO 3` (with IAM token when configured) and `CLIENT TRACKING ON ... BCAST`.
- [ ] `crit-2`: `_client_cache` enforces `max_cached_keys` with LRU eviction on `get` and `set`.
- [ ] `crit-3`: `uv run pytest src/py/tests/unit/db/test_redis_valkey.py -q` passes with exit code 0.
