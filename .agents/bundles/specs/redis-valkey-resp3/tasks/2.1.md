# Task 2.1: Add multiplexed RESP3 `SUBSCRIBE`/`UNSUBSCRIBE` channel fan-out and end-to-end loopback socket tests for Redis and Valkey

## Objective

Implement multiplexed RESP3 Pub/Sub channel fan-out (`subscribe`, `unsubscribe`, `psubscribe`) in `SyncRedisDriver` and `AsyncRedisDriver` (`src/py/vertebra/db/redis.py`) so multiple concurrent consumers in the same worker share a single subscriber connection and receive per-channel `asyncio.Queue` / callback deliveries alongside RESP3 `invalidate` push frames.

## Context

- In RESP3 (`HELLO 3`), push frames (`>3\r\n$7\r\nmessage\r\n$<len>\r\n<channel>\r\n$<len>\r\n<payload>\r\n` and `>2\r\n$10\r\ninvalidate\r\n*1\r\n$<len>\r\n<key>\r\n`) share the same wire framing (`>` prefix) and can be demultiplexed by channel name onto registered subscriber queues.

## Steps

- [ ] 1. In `src/py/vertebra/db/redis.py`, add multiplexed channel subscription tables (`_channel_subscribers: dict[str, set[asyncio.Queue[bytes]]]`) to `AsyncRedisDriver` and `SyncRedisDriver` so `subscribe(channel)` sends `SUBSCRIBE <channel>` only when the first subscriber joins and `unsubscribe(channel)` sends `UNSUBSCRIBE <channel>` when the last subscriber leaves.
- [ ] 2. Route incoming `("push", ["message", channel, payload])` and `("push", ["pmessage", pattern, channel, payload])` frames in `_on_push_frame` to all subscriber queues registered for `channel` / `pattern` while simultaneously forwarding `("push", ["invalidate", keys])` frames to Valkey's client-side cache invalidation handler.
- [ ] 3. Add end-to-end loopback socket tests in `src/py/tests/unit/db/test_redis_valkey.py` verifying concurrent multi-subscriber channel fan-out and interleaved `invalidate` push frame handling on the same RESP3 connection.

## Verification

- **Strategy**: `behavior_tdd` — New observable multiplexed RESP3 pub/sub fan-out and interleaved push frame demultiplexing.
- **Initial Failing Proof**: Subscribing two async consumers to the same channel on `AsyncValkeyDriver` and receiving an interleaved `invalidate` push frame fails to deliver messages to both subscribers while evicting the cached key.
- **Final Verification Commands**:
  ```bash
  uv run pytest src/py/tests/unit/db/test_redis_valkey.py -q
  ```

## Acceptance Criteria

- [x] `crit-1`: Multiple subscribers to the same channel share a single `SUBSCRIBE` command on the upstream connection and each receive every published message.
- [x] `crit-2`: Interleaved RESP3 `invalidate` push frames evict keys from `SyncValkeyDriver`/`AsyncValkeyDriver` `_client_cache` without disrupting active Pub/Sub streams.
- [x] `crit-3`: `uv run pytest src/py/tests/unit/db/test_redis_valkey.py -q` passes with exit code 0.
