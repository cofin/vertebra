# 2.4 Streamable HTTP, SSE, and stdio transports plus `vtb mcp bridge` CLI and Rust `.well-known/mcp.json` discovery offload

## Objective
Implement `src/py/vertebra/agent/mcp/{client,stdio,bridge}.py`, upgrade `src/py/vertebra/cli/mcp.py` to use the async SSE/session/size-capped stdio-to-HTTP bridge (`vtb mcp bridge` and `vtb mcp serve`), delete the dead Rust `src/rs/vertebra-http/src/mcp_bridge.rs` stub (`MCP-03`), and update `src/rs/vertebra-http/src/discovery.rs` (`MCP-02`, `MCP-07`) so `WellKnownDiscoveryCache` accepts configurable protocol versions and SPA exclusion prefixes.

## Context
- `src/py/vertebra/cli/mcp.py:23-113` uses blocking `urllib.request.urlopen`, fails to parse `text/event-stream` SSE responses, drops `Mcp-Session-Id` headers, only reads `params.name` (wrong for `resources/read`, `tasks/*`, `skills/get`), lacks Base64 header encoding for non-ASCII names, and has no frame-size cap (`MCP-03`).
- `src/rs/vertebra-http/src/mcp_bridge.rs:1-78` is an unwired Rust struct with a dead `endpoint_url` field (`:32`) and no HTTP client (`MCP-03`).
- `src/rs/vertebra-http/src/discovery.rs:10,80-87` hardcodes `DEFAULT_SPA_EXCLUDED_PREFIXES` and `"2026-07-28"`, and `is_excluded_from_spa_fallback` does not accept custom configured prefixes (`MCP-02`, `MCP-07`).
- `behavior_tdd` applies because the new `MCPStreamableHttpClient`, `stdio.py`, `bridge.py`, and configurable Rust discovery cache add observable transport and wire behavior.
