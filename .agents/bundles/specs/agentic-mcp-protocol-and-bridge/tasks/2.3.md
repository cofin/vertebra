# 2.3 Async MCP `tasks/*` and queue bridge integration (`agent/mcp/tasks.py`)

## Objective
Create `src/py/vertebra/agent/mcp/tasks.py` and wire it into `MCPService` (`src/py/vertebra/agent/mcp/service.py`) to implement the `io.modelcontextprotocol/tasks` extension (`tasks/get`, `tasks/result`, `tasks/update`, `tasks/cancel`, `tasks/list`), persisting owner-scoped `TaskRecord` envelopes in `ResponseCacheStore` (`MemoryStore`) and dispatching background tool/agent jobs onto `vertebra.framework.queues.QueueService` under the `"agent"` concurrency lane.

## Context
- `litestar_mcp/mcp/tasks.py:27-342` implements `TaskRecord` and `MCPTaskStore` supporting `working`, `input_required`, `completed`, `failed`, and `cancelled` states, TTL expiry, cooperative cancellation, human-in-the-loop `tasks/update` input resumption, and `QueueService` background job dispatch.
- `src/py/vertebra/framework/queues/__init__.py:25-125` defines `TaskLane = Literal["cpu", "io", "agent"]`, `TaskDef`, and `QueueService`, which currently has no agentic consumer.
- All task operations (`tasks/get`, `tasks/result`, `tasks/update`, `tasks/cancel`, `tasks/list`) must enforce caller ownership (`AgentContext.identity.owner_key()`) so one tenant/user cannot inspect or cancel another caller's task.
- `behavior_tdd` applies because `tasks.py` introduces durable async task state transitions, owner isolation, and queue execution.

## Steps
- [ ] 1. Create `src/py/vertebra/agent/mcp/tasks.py` defining `MCPTaskStatus = Literal["working", "input_required", "completed", "failed", "cancelled"]`, `MCPTaskConfig(msgspec.Struct, frozen=True, gc=False, kw_only=True)` (`enabled: bool = True`, `default_ttl_ms: int = 300_000`, `max_ttl_ms: int = 3_600_000`, `poll_interval_ms: int = 1_000`), `TaskLookupError`, `TaskStateError`, `TaskRecord(msgspec.Struct, frozen=True, gc=False, kw_only=True)`, and `MCPTaskStore`:
  ```python
  class TaskRecord(msgspec.Struct, frozen=True, gc=False, kw_only=True):
      """Immutable snapshot of an MCP io.modelcontextprotocol/tasks execution record."""

      task_id: str
      owner_id: str | None
      tool_name: str
      status: MCPTaskStatus
      created_at_iso: str
      last_updated_at_iso: str
      ttl_ms: int
      poll_interval_ms: int = 1000
      status_message: str | None = None
      input_requests: dict[str, dict[str, Any]] | None = None
      result: dict[str, Any] | None = None
      error: dict[str, Any] | None = None

      @property
      def is_terminal(self) -> bool:
          return self.status in ("completed", "failed", "cancelled")
  ```
  - Implement `MCPTaskStore.create`, `get`, `list_for_owner` (with cursor pagination), `wait_for_result`, `require_input`, `wait_for_input`, `submit_input` (`tasks/update`), `cancel` (signaling `CancellationToken` and cancelling the active `anyio` task scope or queued job), `complete`, and `fail`.
  - Integrate with `QueueService`: when `MCPTaskStore(queue_service=...)` is configured, register an internal `"mcp.execute_task"` `TaskDef(lane="agent")` and enqueue background tool invocations through `queue_service.enqueue("mcp.execute_task", ...)` while propagating the caller's `TraceContext` and `CallerIdentity`.
