# 3.6 Ingress pipeline core

## Objective

Split `src/rs/vertebra-http/src/response.rs` into `src/rs/vertebra-http/src/ingress/{mod,pipeline,health}.rs` (`HTTP-40`) and build an `ingress::Pipeline` from `ServerConfig` that runs ordered request interceptors and response filters (`HTTP-02`). Hold a single `Arc<HealthEndpoint>` in `ServerState` so draining transitions (`503`) are observable on `/readyz` (`HTTP-05`), assign batcher shards once per accepted connection (`HTTP-31`), deduplicate `RejectionReason::status()` (`HTTP-13`), unify the two compression APIs into `ResponseCompressor` (`HTTP-04`), and wire `CorsPolicy` deserialized from the Python offload spec JSON (`HTTP-03`).

## Context

- **`HTTP-02` & `HTTP-40` (`src/rs/vertebra-http/src/response.rs:1-317`):** `response.rs` mixes top-level `handle`, health JSON, `RejectionReason` mapping, and header encoding, while `cors`, `compression`, `payload`, `multipart`, `discovery`, `profile`, `assets`, and `access_log` are never called by `handle`.
- **`HTTP-05` (`src/rs/vertebra-http/src/response.rs:87-97`, `src/rs/vertebra-http/src/health.rs:41-70`):** `HealthEndpoint::default().try_intercept(path)` allocates two `String`s on every request and discards the temporary instance, so `set_state(HealthState::Draining)` is never observable; `/__vertebra/health` is handled in two places.
- **`HTTP-13` (`src/rs/vertebra-http/src/backpressure/mod.rs:89-97`, `src/rs/vertebra-http/src/response.rs:208-223`):** `RejectionReason::status` is unused because `rejection_response` duplicates the `match`.
- **`HTTP-31` (`src/rs/vertebra-http/src/server.rs:41-47`):** `ServerState::get_collector` performs a contended global `next_shard.fetch_add(1)` on every request instead of once per accepted connection.
- **`HTTP-03` (`src/rs/vertebra-http/src/cors.rs:5-108`):** `CorsOffloadConfig` lacks `allow_origin_regex`, has no JSON deserializer for the spec emitted by `src/py/vertebra/extensions/litestar/offload.py:49-58`, and allocates strings (`join(", ")`) on every preflight.
- **`HTTP-04` (`src/rs/vertebra-http/src/compression.rs:8-346`):** Two parallel compression APIs (`CompressionConfig`/`compress_response_body` and `CompressionOffloadConfig`/`compress_if_eligible`) duplicate encoder code, and the second API matches `"br;q=0"` via naive `contains("br")`.
- **Symbol overlap note (depends on 3.5):** Moves `response.rs`, `health.rs`, `cors.rs`, `compression.rs`, `payload.rs`, and `multipart.rs` into `ingress/`, updates `BackpressureController::RejectionReason` in `backpressure/mod.rs`, and updates `ServerState` in `server.rs` (shard-per-connection and `Arc<HealthEndpoint>`) and `config.rs` (offload JSON env vars `VERTEBRA_CORS_SPEC` and `VERTEBRA_COMPRESSION_SPEC`).
- **Strategy justification:** `integration_acceptance` is required because this task wires existing health, backpressure, CORS, compression, and payload modules into `ingress::handle` and must prove both normal interception/filtering and negative refusal states (`503` when `HealthEndpoint` is draining, `413` on oversized decompressed payload, `q=0` encoding rejection).

## Steps

- [x] 1. In `src/rs/vertebra-http/src/backpressure/mod.rs`, implement `pub const fn status(self) -> StatusCode` and `pub const fn reason_phrase(self) -> &'static str` on `RejectionReason` (`HTTP-13`) and call them from `rejection_response` in `src/rs/vertebra-http/src/ingress/mod.rs`.
- [x] 2. Move `src/rs/vertebra-http/src/health.rs` to `src/rs/vertebra-http/src/ingress/health.rs` (`HTTP-05`, `HTTP-40`):
  - Store `liveness_path: Box<str>` and `readiness_path: Box<str>` on `HealthEndpoint` and merge the `/__vertebra/health` backpressure JSON responder (`response.rs:225-253`) into `HealthEndpoint::try_intercept(&self, path: &str, bp: Option<BackpressureMetricsSnapshot>) -> Option<HttpResponse>`.
  - Hold `pub health: Arc<HealthEndpoint>` on `ServerState` (`src/rs/vertebra-http/src/server.rs:23-39`) and call `state.health.set_state(HealthState::Draining)` when the shutdown signal fires before stopping the accept loop.
- [x] 3. In `src/rs/vertebra-http/src/server.rs:41-47,141-197` (`HTTP-31`), select `let collector = state.next_collector().clone();` once per accepted TCP connection in the accept loop and pass `&collector` into `ingress::handle(req, &state, &collector)`.
- [x] 4. Move `src/rs/vertebra-http/src/cors.rs` to `src/rs/vertebra-http/src/ingress/cors.rs` (`HTTP-03`) and replace `CorsOffloadConfig` with `CorsPolicy`:
  - Deserialize from the JSON spec in `VERTEBRA_CORS_SPEC` (supporting `allow_origins`, `allow_origin_regex` compiled once with `regex::Regex`, `allow_methods`, `allow_headers`, `expose_headers`, `allow_credentials`, `max_age`).
  - Precompute `HeaderValue` fields for `access-control-allow-methods`, `access-control-allow-headers`, `access-control-expose-headers`, and `access-control-max-age` at construction time so `intercept_preflight` and `apply_response_headers` perform zero string joins per request.
- [x] 5. Move `src/rs/vertebra-http/src/compression.rs` to `src/rs/vertebra-http/src/ingress/compression.rs` (`HTTP-04`) and merge the two compression APIs into a single `ResponseCompressor`:
  ```rust
  pub struct ResponseCompressor {
      codecs: Vec<ResponseCodec>,
      min_size: usize,
      gzip_level: u32,
      brotli_quality: u32,
      zstd_level: i32,
      excluded_paths: Vec<Box<str>>,
  }
  ```
  Use the RFC 9110 q-value parser in `negotiate(&self, headers: &HeaderMap, path: &str) -> Option<ResponseCodec>` (rejecting `q=0`), deserialize from `VERTEBRA_COMPRESSION_SPEC` or `ServerConfig`, and delete `CompressionBackend`, `CompressionOffloadConfig`, and `compress_if_eligible`.
- [x] 6. Move `src/rs/vertebra-http/src/payload.rs` and `src/rs/vertebra-http/src/multipart.rs` into `src/rs/vertebra-http/src/ingress/payload.rs` and `src/rs/vertebra-http/src/ingress/multipart.rs`, and create `src/rs/vertebra-http/src/ingress/pipeline.rs` and `src/rs/vertebra-http/src/ingress/mod.rs` (deleting `src/rs/vertebra-http/src/response.rs`, `health.rs`, `cors.rs`, `compression.rs`, `payload.rs`, `multipart.rs`):
  - `Pipeline` owns `health: Arc<HealthEndpoint>`, `cors: Option<CorsPolicy>`, `compressor: Option<ResponseCompressor>`, `payload_limits: PayloadLimits`, and `guards: Option<GuardChain>` (wrapping `vertebra_core::guards::{JwtValidator, RateLimiter}` configured from `VERTEBRA_GUARDS_SPEC` per Decision D4 so offloaded Litestar/native route guards reject unauthorized `401`/`403` or rate-limited `429` requests in Rust before touching SHM or the Python event loop).
  - `ingress::handle` runs `state.pipeline.intercept_request(&parts)` (health probe, CORS `OPTIONS` preflight) -> admission control -> route lookup -> bounded request body read & `Content-Encoding` decompression via `payload_limits.read_and_decode` (returning `413 Payload Too Large` or `400 Bad Request` on violation) -> batcher send -> `state.pipeline.finish_response(&parts, &mut resp)` (CORS response headers, `ResponseCompressor` on unary bodies).
- [x] 7. Add integration tests in `src/rs/vertebra-http/tests/ingress_fastpath_tests.rs` and `src/rs/vertebra-http/tests/test_server.rs` exercising `ingress::handle` end-to-end:
  - `handle_serves_cors_preflight_and_attaches_origin_headers`
  - `handle_compresses_eligible_response_and_honors_q_zero`
  - `handle_readiness_returns_503_after_draining_transition`
  - `handle_rejects_oversized_compressed_request_payload_with_413`
- [x] 8. Commit: `refactor(http): introduce ingress::Pipeline wiring health, CORS, compression, and payload limits` (signed), staging exactly the paths in `files`.

## Verification

- **Strategy:** `integration_acceptance` — composes health, CORS, compression, and payload limits inside `ingress::handle` and verifies both positive interception/filtering and negative refusal states (`503` draining, `413` decompression bomb, `q=0` exclusion).
- **Initial evidence:** `cargo test --manifest-path src/rs/Cargo.toml -p vertebra-http --test ingress_fastpath_tests --test test_server` → green baseline before pipeline wiring.
- **Final evidence:** `cargo test --manifest-path src/rs/Cargo.toml -p vertebra-http --features tls,compression --test ingress_fastpath_tests --test test_server` → exits 0 with all 4 new pipeline integration tests passing.
- **Gate proof:** Calling `state.health.set_state(HealthState::Draining)` causes `GET /readyz` through `ingress::handle` to return `503 Service Unavailable` while `GET /healthz` and `GET /__vertebra/health` still return `200 OK`; sending a gzip-compressed request body that expands past `PayloadLimits.max_decompressed_bytes` returns `413 Payload Too Large`; sending `Accept-Encoding: br;q=0, gzip;q=1.0` never selects Brotli.

- [x] `src/rs/vertebra-http/src/response.rs`, `health.rs`, `cors.rs`, `compression.rs`, `payload.rs`, and `multipart.rs` are moved under `src/rs/vertebra-http/src/ingress/`.
- [x] `ServerState` holds a single `Arc<HealthEndpoint>` and `ingress::Pipeline`, and assigns batcher shards once per connection.
- [x] Only one compression type (`ResponseCompressor`) and one CORS type (`CorsPolicy`) exist in `vertebra-http`.
- [x] `make lint` exits 0; no new `# ` comments, nested imports, aliases, or private-module imports.
