# 3.8 Connection protocols

## Objective

Move `server.rs`, `tls.rs`, `h2c.rs`, and `http3.rs` into `src/rs/vertebra-http/src/server/{mod,tls,tls_identity,h2c,http3}.rs`: remove the discarded per-connection `detect_cleartext_protocol` `peek` syscall (`HTTP-25`), share a preconfigured `AutoBuilder` and generic `serve_connection` across plain and TLS sockets (`HTTP-26`), precompute the `Alt-Svc` `HeaderValue` and spawn `serve_http3_endpoint` from `run_with_listener` when HTTP/3 is enabled (`HTTP-28`), and replace the hand-rolled 70-line SHA-256 and short-length DER scanner in `tls.rs` with `vertebra_core::util::crypto::sha256_hex` and a multi-byte ASN.1 DER TLV walker wired into TLS connection serving (`HTTP-32`).

## Context

- **`HTTP-25` (`src/rs/vertebra-http/src/server.rs:148`, `src/rs/vertebra-http/src/h2c.rs:64-223`):** Every cleartext TCP connection runs `let _ = detect_cleartext_protocol(&stream).await?`, costing an extra `peek` syscall and waiting for the first client bytes even though `hyper_util::server::conn::auto::Builder` already detects the HTTP/2 prior-knowledge preface. Meanwhile `parse_h2c_upgrade_headers`, `build_h2c_switching_protocols_response`, `decode_base64url`, and `PrependStream` in `h2c.rs` have zero callers outside tests.
- **`HTTP-26` (`src/rs/vertebra-http/src/server.rs:100,141-197`):** `AutoBuilder::new(TokioExecutor::new())` is constructed per connection in both plain and TLS loops, the TLS loop omits all HTTP/2 window and stream settings configured on the plain loop (`:153-158`), and `service_fn` closures are duplicated.
- **`HTTP-28` (`src/rs/vertebra-http/src/response.rs:187-193`, `src/rs/vertebra-http/src/http3.rs:54-66,125,249`):** `serve_http3_endpoint` is never started by `server.rs`, yet `handle` formats a fresh `Alt-Svc` `String` and `HeaderValue` on every response when `config.http3.enabled` is true. `http3.rs:249` also copies request body chunks twice (`copy_to_bytes` then `extend_from_slice`).
- **`HTTP-32` (`src/rs/vertebra-http/src/tls.rs:125,191-312,398`):** `tls.rs` contains a 70-line hand-rolled SHA-256 (`:242-312`) that clones the certificate (`data.to_vec()`), and its DER CN/SAN scanner (`:191-240`) only handles short-form lengths `< 128` bytes and raw OID substring matches. Neither `peer_identity` (`:398`) nor `normalize_trusted_proxy_headers` (`:125`) is called from `serve_tls`.
- **Symbol overlap note (depends on 3.7):** Moves `server.rs` (touched in 3.6 for shard-per-connection) to `server/mod.rs` and hooks `alt_svc: Option<HeaderValue>` into `ingress/pipeline.rs` (`finish_response`).
- **Strategy justification:** `characterization` is used because HTTP/1.1, HTTP/2 (cleartext and TLS), mTLS identity extraction, and HTTP/3 over QUIC preserve their protocol contracts while removing duplicated connection setup and hand-rolled crypto, verified by the `h2c_and_mtls_tests`, `test_tls`, and `http3_quic_tests` suites.

## Steps

- [x] 1. Create `src/rs/vertebra-http/src/server/h2c.rs` (deleting `src/rs/vertebra-http/src/h2c.rs`, `HTTP-25`): remove `detect_cleartext_protocol` from the accept path (`AutoBuilder` natively handles HTTP/2 prior-knowledge preface), delete the hand-rolled `decode_base64url` (`base64` workspace crate is already present), and keep `parse_h2c_upgrade_headers` and `build_h2c_switching_protocols_response` using `base64::engine::general_purpose::URL_SAFE_NO_PAD`.
- [x] 2. Split `src/rs/vertebra-http/src/tls.rs` into `src/rs/vertebra-http/src/server/tls.rs` (`TlsAcceptor`, `MtlsConfig`) and `src/rs/vertebra-http/src/server/tls_identity.rs` (deleting `src/rs/vertebra-http/src/tls.rs`, `HTTP-32`):
  - Delete the hand-rolled SHA-256 (`tls.rs:242-312`) and call `vertebra_core::util::crypto::sha256_hex(der_bytes)` (from Chapter 2 Task 2.9).
  - Replace the short-length byte scan (`tls.rs:191-240`) with an ASN.1 DER TLV length reader supporting both short-form (`len < 0x80`) and long-form multi-byte lengths (`0x81..=0x84`) so certificates and SAN extensions `>= 128` bytes parse accurately.
  - Add a unit test in `src/rs/vertebra-http/tests/h2c_and_mtls_tests.rs` (`mtls_der_long_form_san_and_sha256_fingerprint`) with a certificate containing a `> 128`-byte SAN extension.
- [x] 3. Move `src/rs/vertebra-http/src/http3.rs` to `src/rs/vertebra-http/src/server/http3.rs` (`HTTP-28`):
  - Precompute `alt_svc_header: Option<HeaderValue>` once in `Pipeline::new` only when the `http3` feature is compiled AND an HTTP/3 listener is actually bound.
  - Replace the double copy `copy_to_bytes` + `extend_from_slice` (`http3.rs:249`) with `BytesMut::put(chunk.chunk())`.
  - When `#[cfg(feature = "http3")]` and `state.config.http3.enabled`, spawn `serve_http3_endpoint` inside `server::run_with_listener` bound to the UDP socket address and cancelled via `CancellationToken`.
- [x] 4. Move `src/rs/vertebra-http/src/server.rs` to `src/rs/vertebra-http/src/server/mod.rs` (`HTTP-26`):
  - Build one `hyper_util::server::conn::auto::Builder<TokioExecutor>` on `ServerState` configured with HTTP/1.1 `pipeline_flush(true)` and HTTP/2 window/stream/keepalive settings so both plain and TLS connections share identical settings.
  - Write a single generic `async fn serve_connection<I>(io: I, state: Arc<ServerState>, collector: mpsc::Sender<PendingRequest>, peer_cert: Option<ClientIdentity>)` where `I: AsyncRead + AsyncWrite + Unpin + Send + 'static`, inserting `peer_cert` into request extensions and normalizing trusted proxy headers when `state.config.trusted_proxies` is non-empty.
- [x] 5. Update `src/rs/vertebra-http/src/lib.rs`, `src/rs/vertebra-http/src/ingress/mod.rs`, and `src/rs/vertebra-http/src/ingress/pipeline.rs` to use `crate::server::{...}` and the precomputed `alt_svc_header`.
- [x] 6. Commit: `refactor(http): unify plain/TLS serve_connection, wire HTTP/3 listener, and harden DER/SHA-256 identity` (signed), staging exactly the paths in `files`.

## Acceptance Criteria

- [x] `server.rs`, `tls.rs`, `h2c.rs`, and `http3.rs` at the crate root are replaced by `src/rs/vertebra-http/src/server/{mod,tls,tls_identity,h2c,http3}.rs`.
- [x] Plain and TLS connections share a single `AutoBuilder` configuration and generic `serve_connection` helper, with no per-connection `peek` syscall in `server/mod.rs`.
- [x] `Alt-Svc` is precomputed as a `HeaderValue` and is emitted only when the HTTP/3 endpoint is active.
- [x] Hand-rolled SHA-256 and `decode_base64url` are deleted in favor of `vertebra_core::util::crypto::sha256_hex` and `base64`.
- [x] `make lint` exits 0; no new `# ` comments, nested imports, aliases, or private-module imports.
