# 3.10 Config, main, dependencies, and MCP bridge removal

## Objective

Delete the stub `src/rs/vertebra-http/src/mcp_bridge.rs` module and its tests (`HTTP-01`, `MCP-03`), ensure any MCP protocol version header in Rust comes from `ServerConfig` rather than a hardcoded literal (`MCP-02`), wire live `ServerConfig` fields (`keepalive_timeout`, `max_connections`, `h2_keep_alive_interval_ms`, `enable_h2c_upgrade`, `trusted_proxies`, `mtls`) into `server/mod.rs` and delete dead config fields (`HTTP-24`), deduplicate Python `AppSpec` loading and conditional `BatchBridge::init` in `src/rs/vertebra-http/src/main.rs` (`HTTP-37`), and trim unused dependencies and oversized features in `src/rs/vertebra-http/Cargo.toml` (`HTTP-38`).

## Context

- **`HTTP-01` & `MCP-03` (`src/rs/vertebra-http/src/mcp_bridge.rs:1-78`, `src/rs/vertebra-http/tests/mcp_discovery_bridge_tests.rs:48-88`):** `McpStdioBridge::run_with_responder` is a blocking `BufReader::lines` stub that never reads `McpBridgeConfig.endpoint_url` (`:32`) and has no non-test callers; under Decision D2, `vtb mcp bridge` delegates to `litestar_mcp.mcp.bridge.run_bridge` in Python (Chapter 5 Task 5.8).
- **`MCP-02` (`src/rs/vertebra-http/src/ingress/discovery.rs` / `config.rs`):** Any MCP protocol version header emitted by Rust must read `config.mcp_protocol_version` (from `VERTEBRA_MCP_PROTOCOL_VERSION`, defaulting to `"2026-07-28"` in `config.rs` only as fallback when Python does not supply one) rather than embedding divergent literals across layers.
- **`HTTP-24` (`src/rs/vertebra-http/src/config.rs:15-53,167`):** `worker_threads`, `batch_size`, `batch_timeout`, `keepalive_timeout`, `max_connections`, `thread_count`, `h2_keep_alive_interval_ms`, `enable_h2c_upgrade`, `trusted_proxies`, and `workers.app_path` are unread outside `config.rs`.
- **`HTTP-37` (`src/rs/vertebra-http/src/main.rs:43-51,74,118-130,181,198-217`):** `main.rs` duplicates `module:attr` splitting (`splitn(2, ':')`) and raw-callable wrapping in two places, initializes `BatchBridge::init` even when running in `Topology::Shm`, skips `HEAD` and `OPTIONS` when registering mount routes, and ships hardcoded `/hello` and `/echo` routes in the non-Python build.
- **`HTTP-38` (`src/rs/vertebra-http/Cargo.toml`):** `tokio-test` dev-dependency is unused; `serde_json` and `rustls-pemfile` are duplicated in `[dev-dependencies]`; `hyper` and `hyper-util` enable `features = ["full"]`; `brotli`, `flate2`, and `zstd` are unconditional instead of gated behind `compression`; `tracing-subscriber` is a library dependency used only by `main.rs`.
- **Symbol overlap note (depends on 3.9):** Cleans up `lib.rs`, `config.rs`, `main.rs`, and `server/mod.rs` after Tasks 3.6–3.9 have landed their modules.
- **Strategy justification:** `characterization` is used because server startup, configuration loading, and build targets preserve their runtime behavior while deleting dead stubs, wiring connection settings, and trimming Cargo dependencies.

## Steps

- [x] 1. Delete `src/rs/vertebra-http/src/mcp_bridge.rs`, remove `pub mod mcp_bridge;` from `src/rs/vertebra-http/src/lib.rs`, and delete the `McpStdioBridge` and `extract_mcp_observability_headers` test cases from `src/rs/vertebra-http/tests/mcp_discovery_bridge_tests.rs` (if Task 3.7 Outcome B also deleted `discovery.rs`, delete `tests/mcp_discovery_bridge_tests.rs` completely) (`HTTP-01`, `MCP-03`).
- [x] 2. In `src/rs/vertebra-http/src/config.rs` and `src/rs/vertebra-http/src/server/mod.rs` (`HTTP-24`, `MCP-02`):
  - Delete redundant fields `batch_timeout`, `thread_count`, and `workers.app_path` (keeping a single `app_spec: Option<AppSpec>` and `batch_limit: BatchLimit` on `ServerConfig`).
  - Wire `keepalive_timeout` (`http1().keep_alive(true)`), `h2_keep_alive_interval_ms` (`http2().keep_alive_interval(...)`), `max_connections` (an `Arc<tokio::sync::Semaphore>` in the accept loop), `enable_h2c_upgrade`, `trusted_proxies`, and `MtlsConfig::from_env()` in `server/mod.rs`.
  - Parse `AppSpec { pub module: String, pub attr: String }` once in `ServerConfig::from_env()` from `VERTEBRA_APP` / `VERTEBRA_PYTHON_APP`, returning a descriptive `ConfigError` when `:` is missing or either half is empty.
- [x] 3. Refactor `src/rs/vertebra-http/src/main.rs` (`HTTP-37`):
  - Write a single `#[cfg(feature = "python")] fn load_app<'py>(py: Python<'py>, spec: &AppSpec) -> PyResult<Bound<'py, PyAny>>` used by both route extraction and embedded worker startup.
  - Register all 9 standard methods (`GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `HEAD`, `OPTIONS`, `TRACE`, `CONNECT`) for mounted sub-applications (`main.rs:211-217`).
  - Call `BatchBridge::init` only when `config.topology == Topology::Embedded`.
  - Remove the demo `/hello` and `/echo` routes from the non-Python build (`main.rs:118-120`), starting with an empty `RouteTable` (health and configured static/ingress endpoints remain active).
- [x] 4. Trim `src/rs/vertebra-http/Cargo.toml` (`HTTP-38`):
  - Remove `tokio-test`, and remove the duplicate `serde_json` and `rustls-pemfile` entries from `[dev-dependencies]`.
  - Narrow `hyper` to `features = ["server", "http1", "http2"]` and `hyper-util` to `features = ["server", "server-auto", "http1", "http2", "tokio"]`.
  - Gate `brotli`, `flate2`, and `zstd` under the `compression` feature (included in `default = ["python", "compression"]`) and gate ` ingress/compression.rs` codec branches accordingly.
- [x] 5. Commit: `refactor(http): remove mcp_bridge stub, wire ServerConfig, and trim Cargo dependencies` (signed), staging exactly the paths in `files`.
