# 3.4 SHM streaming responses

## Objective

Make multi-frame SHM streaming responses (`FrameFlags::STREAMING`, `HEADERS_SENT`, `TRAILERS`, `FINAL`, `ERROR`) work end-to-end in production by extending `InFlightRequests` to hold both unary oneshot senders and active streaming frame senders, routing `ResponseSlotView` frames in `shm_reader.rs` through `ShmDispatcher`, and deleting the dead `PendingRequests` / `PendingResponder` `DashMap` (`HTTP-06`). Parse response headers once directly from `ResponseSlotView` into `http::HeaderMap` on `PendingResponse` so `build_response` assigns `*resp.headers_mut() = headers` without re-encoding or re-parsing (`HTTP-10`).

## Context

- **`HTTP-06` (`src/rs/vertebra-http/src/dispatcher/shm.rs:248-343`, `src/rs/vertebra-http/src/dispatcher/shm_reader.rs:35-112,267-295`):** `Dispatcher::handle_raw_response_slot` (`dispatcher/mod.rs:229`) has zero production callers. After Chapter 2 Task 2.5 standardizes the response rings on `ResponseSlot` / `ResponseSlotView`, `shm_reader::drain_worker` still only completes unary responses and cannot keep a correlation slot open across multiple `FrameFlags::STREAMING` chunks. Meanwhile `PendingRequests` (`shm_reader.rs:45-112`) is a standalone `DashMap` used only by `tests/streaming_body_tests.rs:111`.
- **`HTTP-10` (`src/rs/vertebra-http/src/dispatcher/shm.rs:256-298`, `src/rs/vertebra-http/src/main.rs:93`, `src/rs/vertebra-http/src/response.rs:285-313`):** `handle_raw_response_slot` parses the slot three times (`peek_request_id`, `peek_flags`, `decode_from`), converts headers through `Vec<(String, String)>` -> `Vec<(Vec<u8>, Vec<u8>)>` -> compact `Bytes`, copies the whole raw frame with `raw_slot.to_vec()`, and then `build_response` iterates `iter_raw_headers` to parse every `HeaderName`/`HeaderValue` a third time.
- **Symbol overlap note (depends on 3.3):** Modifies `dispatcher/{correlation,shm,shm_reader,mod}.rs`, `body.rs`, `response.rs`, and `main.rs` on top of Task 3.3's `DispatchBackend` and `shm_reader.rs` move.
- **Strategy justification:** `regression_tdd` is required because SHM workers sending multi-frame `FrameFlags::STREAMING` responses (`HEADERS_SENT` -> data chunks -> `TRAILERS` -> `FINAL`) fail to stream through `ShmDispatcher` + `shm_reader` today.

## Steps

- [x] 1. In `src/rs/vertebra-http/tests/streaming_body_tests.rs`, write a failing integration test `shm_multi_frame_streaming_with_trailers_end_to_end` that creates a `RingPair` and `ShmDispatcher`, dispatches a request, writes three `ResponseSlot` frames into the worker's `TieredRingSet` (`HEADERS_SENT | STREAMING` with status `200` and header `x-stream: 1`, `STREAMING` with body chunk `"part-1"`, `STREAMING | TRAILERS` with trailer `grpc-status: 0`, and `STREAMING | FINAL` with body chunk `"part-2"`), runs `drain_worker`, and awaits the resulting `HttpResponse` body frames to assert both data chunks and trailers arrive in order.
- [x] 2. In `src/rs/vertebra-http/src/body.rs`, change `PendingResponse` (`HTTP-10`) from `headers_mp: Bytes` to `pub headers: HeaderMap` and add a helper `decode_header_map(raw: RawHeaders<'_>) -> HeaderMap` that preallocates `HeaderMap::with_capacity` and parses `HeaderName::from_bytes` and `HeaderValue::from_bytes` once. Move `build_response` from `src/rs/vertebra-http/src/response.rs:285-313` into `src/rs/vertebra-http/src/body.rs` so it sets `*resp.headers_mut() = pending.headers`. Update `src/rs/vertebra-http/src/main.rs:89-99` (bridge response reader) to decode `BridgeResponse.headers_raw` via `decode_header_map`.
- [x] 3. In `src/rs/vertebra-http/src/dispatcher/correlation.rs`, extend `CorrelationEntry` to support both unary awaiting and active streaming (`HTTP-06`):
  ```rust
  pub enum CorrelationState {
      AwaitingInitial(oneshot::Sender<PendingResponse>),
      Streaming(mpsc::Sender<Result<Frame<Bytes>, Infallible>>),
  }
  ```
  Add `InFlightRequests::deliver_slot(&mut self, id: CorrelationId, slot: &ResponseSlotView<'_>) -> bool`:
  - When the entry is `AwaitingInitial(reply)` and `!slot.flags.is_streaming()`, remove the entry, return the slot index to `free_list`, and send `PendingResponse { status: slot.status, headers: decode_header_map(slot.headers), body: Bytes::copy_from_slice(slot.body), stream_rx: None }`.
  - When the entry is `AwaitingInitial(reply)` and `slot.flags.is_streaming()`, create `let (tx, rx) = mpsc::channel(64)`, send `PendingResponse { status: slot.status, headers: decode_header_map(slot.headers), body: Bytes::new(), stream_rx: Some(rx) }` over `reply`, emit the initial `slot.body` (if non-empty) or trailers to `tx`, and if `slot.flags.is_terminal()` (`FINAL` or `ERROR`) release the slot immediately; otherwise transition the entry in place to `CorrelationState::Streaming(tx)`.
  - When the entry is `Streaming(tx)`, forward `Frame::trailers(decode_header_map(slot.headers))` when `slot.flags.contains(FrameFlags::TRAILERS)` and `Frame::data(Bytes::copy_from_slice(slot.body))` when `!slot.body.is_empty()`; if `slot.flags.is_terminal()` or `tx.try_send` reports a closed receiver, remove the entry and push the slot index back onto `free_list`.
- [x] 4. In `src/rs/vertebra-http/src/dispatcher/shm.rs` and `src/rs/vertebra-http/src/dispatcher/shm_reader.rs`:
  - Delete `PendingResponder` and `PendingRequests` (`shm_reader.rs:35-112`) and delete the old `handle_raw_response_slot` task-spawning implementation (`shm.rs:248-343`).
  - Update `drain_worker` in `shm_reader.rs` to read borrowed `ResponseSlotView` frames from `RingPair::response_rings` and pass them to `shm_dispatcher.deliver_response_slot(&view)`.
- [x] 5. Update existing tests in `src/rs/vertebra-http/tests/streaming_body_tests.rs` to exercise `InFlightRequests` and `ShmDispatcher` instead of the deleted `PendingRequests`.
- [x] 6. Commit: `fix(http): route SHM streaming frames through InFlightRequests and parse headers once` (signed), staging exactly the paths in `files`.

## Verification

- **Strategy:** `regression_tdd` — multi-frame SHM streaming responses were unreachable in `drain_worker`, so the new end-to-end SHM streaming test fails before the fix and passes once `InFlightRequests::deliver_slot` is wired.
- **Initial evidence:** `cargo test --manifest-path src/rs/Cargo.toml -p vertebra-http --test streaming_body_tests shm_multi_frame_streaming_with_trailers_end_to_end` → fails before the change because `drain_worker` does not route multi-frame `STREAMING` slots into `stream_rx`.
- **Final evidence:** `cargo test --manifest-path src/rs/Cargo.toml -p vertebra-http --features tls,compression --test streaming_body_tests --test test_dispatcher --test test_server` → exits 0 with `shm_multi_frame_streaming_with_trailers_end_to_end` passing.
