# 3.3 Dispatcher backend, lifecycle, and worker supervision

## Objective

Replace `Dispatcher`'s mode enum and `Option` fields with `DispatchBackend` (`HTTP-18`), lock correlation shards once per shard per batch/drain (`HTTP-20`), replace the per-batch `HashMap` in `dispatch_shm` with a reusable worker-indexed `ShmBatchScratch` (`HTTP-21`), and move `response_reader.rs` to `dispatcher/shm_reader.rs` with `Weak` sweeper references and `tokio::select!` cancellation (`HTTP-22`). Split `ring_factory.rs` into `workers/{mod,factory,supervisor}.rs` and wire `WorkerLifecycle`, `InFlightRequests::sweep_for_worker`, `RingPair::reclaim`, `cleanup_stale_shm`, and `install_panic_cleanup_hook` into `workers::Supervisor` and `main.rs` (`HTTP-23`, `OKF-07`).

## Context

- **`HTTP-18` (`src/rs/vertebra-http/src/dispatcher/mod.rs:47-129,170-226`):** `Dispatcher` wraps `Arc<Inner>` (often inside another `Arc<Dispatcher>`) with `pending: DashMap`, `direct_tx: Option`, `shm_dispatcher: Option`, and `mode: DispatchMode`, allocating the `DashMap` even in SHM and Direct modes.
- **`HTTP-20` & `HTTP-21` (`src/rs/vertebra-http/src/dispatcher/shm.rs:86,157,179-181,350,388`, `dispatcher/mod.rs:205`):** `dispatch_shm` locks `correlation_shards[shard_idx]` once per request and allocates `HashMap<(usize, u32), ShmDispatchBatch>` per batch; `complete_many` locks a shard mutex per response.
- **`HTTP-22` (`src/rs/vertebra-http/src/dispatcher/shm.rs:58-68`, `src/rs/vertebra-http/src/response_reader.rs:204-230`, `src/rs/vertebra-http/src/main.rs:261`, `src/rs/vertebra-http/src/dispatcher/correlation.rs:95-125`):** `ShmDispatcher::new` spawns an infinite sweeper task holding `Arc<Self>` (leaking the dispatcher and requiring a Tokio runtime at construction time), `sweep_expired` allocates an unused `Vec<u64>`, `response_reader.rs` checks `shutdown.is_cancelled()` only before `readable().await` without `tokio::select!`, and `main.rs:261` never cancels its `CancellationToken`.
- **`HTTP-23` / `OKF-07` (`src/rs/vertebra-http/src/ring_factory.rs:180-330`, `src/rs/vertebra-http/src/dispatcher/correlation.rs:131-157`):** `WorkerLifecycle`, `sweep_for_worker`, `RingPair::reclaim`, `cleanup_stale_shm`, and `install_panic_cleanup_hook` have zero production callers; when a worker process crashes, in-flight requests hang until the 30-second timeout instead of immediately failing with `502 Bad Gateway` and respawning the worker. Also `ring_factory::WorkerState` collides with `dispatcher::types::WorkerState`.
- **Symbol overlap note (depends on 3.2):** Updates `dispatcher/{mod,shm,types,correlation}.rs`, `main.rs`, and `lib.rs` on top of Task 3.2's `Batch` and `CorrelationId` changes.
- **Strategy justification:** `integration_acceptance` is required because this task wires existing supervision, correlation sweep, ring reclamation, and cancellation contracts together and must prove both normal operation and negative refusal/recovery states (worker crash -> immediate 502 + ring reclaim, and shutdown token cancellation -> bounded task exit).

## Steps

- [x] 1. Refactor `src/rs/vertebra-http/src/dispatcher/mod.rs` and `src/rs/vertebra-http/src/dispatcher/bridge.rs` (`HTTP-18`):
  ```rust
  pub struct BridgeCorrelation {
      pending: DashMap<u64, oneshot::Sender<PendingResponse>>,
      next_id: AtomicU64,
  }

  pub enum DispatchBackend {
      Direct(mpsc::Sender<Batch>),
      Bridge(Arc<BridgeCorrelation>),
      Shm(Arc<ShmDispatcher>),
  }

  pub struct Dispatcher {
      backend: DispatchBackend,
      backpressure: Option<Arc<BackpressureController>>,
  }
  ```
  Implement `dispatch`, `complete`, and `complete_many` by matching on `&self.backend`.
- [x] 2. In `src/rs/vertebra-http/src/dispatcher/types.rs` and `src/rs/vertebra-http/src/dispatcher/shm.rs`, rename `ring_factory::WorkerState` to `WorkerHealth` (`HTTP-23`) and add `ShmBatchScratch` (`HTTP-21`): a preallocated `Vec<ShmDispatchBatch>` indexed by `worker_idx` whose buffers (`nodes`, `components`, `correlation_ids`) are `clear()`ed after flush rather than reallocated in a `HashMap`.
- [x] 3. In `src/rs/vertebra-http/src/dispatcher/shm.rs` (`HTTP-20`), allocate correlation IDs for a worker's batch under a single lock acquisition on `correlation_shards[shard_idx]` per batch (selecting `shard_idx = batch_seq & self.shard_mask` for the batch), and in `ShmDispatcher::complete_many` sort or bucket incoming completions by `id.shard()` so each touched shard mutex is locked once per drain pass.
- [x] 4. Fix background task lifecycles (`HTTP-22`):
  - Remove the `tokio::spawn` inside `ShmDispatcher::new` (`shm.rs:58-68`) and add `pub fn spawn_sweeper(self: &Arc<Self>, shutdown: CancellationToken) -> tokio::task::JoinHandle<()>` holding `Arc::downgrade(self)` (`Weak<ShmDispatcher>`), exiting when `Weak::upgrade` returns `None` or `shutdown.cancelled()` resolves.
  - Change `InFlightRequests::sweep_expired(&mut self, timeout: Duration) -> usize` and `sweep_for_worker(&mut self, worker_id: u32) -> usize` in `src/rs/vertebra-http/src/dispatcher/correlation.rs:95-157` to send `504 Gateway Timeout` / `502 Bad Gateway` inline and return the swept count without allocating a `Vec<u64>`.
  - Move `src/rs/vertebra-http/src/response_reader.rs` to `src/rs/vertebra-http/src/dispatcher/shm_reader.rs` (delete `response_reader.rs`) and wrap both the Unix `AsyncFd::readable()` wait and the non-Unix backoff wait in `tokio::select! { biased; _ = shutdown.cancelled() => break, ... }`.
- [x] 5. Split `src/rs/vertebra-http/src/ring_factory.rs` into `src/rs/vertebra-http/src/workers/mod.rs`, `src/rs/vertebra-http/src/workers/factory.rs` (`RingFactory`, `cleanup_stale_shm`, `install_panic_cleanup_hook`), and `src/rs/vertebra-http/src/workers/supervisor.rs` (delete `ring_factory.rs`) (`HTTP-23`, `OKF-07`):
  - Implement `workers::Supervisor::spawn(factory: Arc<Mutex<RingFactory>>, shm: Arc<ShmDispatcher>, shutdown: CancellationToken) -> tokio::task::JoinHandle<()>` that polls `WorkerLifecycle::check_alive` every 100 ms until `shutdown.cancelled()`, and on worker exit: (a) calls `shm.sweep_worker(worker_id)` to immediately fail in-flight requests for that worker with `502 Bad Gateway`, (b) calls `ring_pair.reclaim()` to reset ring indices and clear poison flags, (c) records the crash in `WorkerLifecycle`, and (d) respawns the worker after `respawn_delay()` if `!circuit_breaker_tripped()`.
  - Wire `cleanup_stale_shm()`, `install_panic_cleanup_hook()`, `shm.spawn_sweeper(shutdown.clone())`, `Supervisor::spawn(...)`, and `shutdown.cancel()` (after `run_with_collector` returns) in `src/rs/vertebra-http/src/main.rs:235-325`.
- [x] 6. Add two integration tests in `src/rs/vertebra-http/tests/test_dispatcher.rs`:
  - `shm_worker_crash_sweeps_inflight_with_502_and_reclaims_rings`: dispatches an in-flight request to worker 0, simulates worker 0 crash via `Supervisor::handle_worker_exit(0)`, and asserts the caller receives `502 Bad Gateway` within 50 ms and the ring pair is reclaimed.
  - `shm_reader_and_sweeper_exit_on_cancellation`: spawns `spawn_sweeper` and `spawn_response_readers`, cancels the `CancellationToken`, and asserts all `JoinHandle`s complete within 200 ms.

## Verification

- **Strategy:** `integration_acceptance` — composes `DispatchBackend`, `InFlightRequests`, `RingFactory`, `WorkerLifecycle`, and `CancellationToken` lifecycles with explicit negative-state injection (worker death and shutdown cancellation).
- **Initial evidence:** `cargo test --manifest-path src/rs/Cargo.toml -p vertebra-http --test test_dispatcher --test test_spsc_violation` → green baseline before refactor.
- **Final evidence:** `cargo test --manifest-path src/rs/Cargo.toml -p vertebra-http --features tls,compression --test test_dispatcher --test test_spsc_violation` → exits 0 including `shm_worker_crash_sweeps_inflight_with_502_and_reclaims_rings` and `shm_reader_and_sweeper_exit_on_cancellation`.
- **Gate proof:** In `shm_worker_crash_sweeps_inflight_with_502_and_reclaims_rings`, an in-flight request whose worker crashes is immediately completed with status `502` (`"Bad Gateway"`) instead of hanging until timeout, and when `record_crash` exceeds `max_restarts` within the window, `circuit_breaker_tripped()` refuses further respawns and marks the worker unhealthy.

## Acceptance Criteria

- [x] `Dispatcher` uses `DispatchBackend::{Direct, Bridge, Shm}` with no `DashMap` allocated in `Direct` or `Shm` modes.
- [x] `dispatch_shm` uses reusable `ShmBatchScratch` (zero `HashMap` allocations) and locks correlation shards once per batch/drain pass.
- [x] `response_reader.rs` and `ring_factory.rs` are replaced by `dispatcher/shm_reader.rs` and `workers/{mod,factory,supervisor}.rs`.
- [x] `ShmDispatcher::spawn_sweeper`, `shm_reader`, and `workers::Supervisor` all terminate cleanly when `CancellationToken::cancel()` is called.
- [x] `make lint` exits 0; no new `# ` comments, nested imports, aliases, or private-module imports.
