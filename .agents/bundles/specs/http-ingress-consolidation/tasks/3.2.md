# 3.2 Routing and batcher

## Objective

Consolidate `router.rs` and `route_table.rs` into `src/rs/vertebra-http/src/routing.rs` with a method-tag-indexed `[Option<matchit::Router<HandlerId>>; 9]` table instead of per-request string hashing (`HTTP-29`), and assert exact cross-language FNV-1a `handler_id` reference constants in both Rust and Python (`HTTP-16`). Replace `collector.rs` and `policy.rs` with `src/rs/vertebra-http/src/batcher.rs` using `BatchLimit { max: usize }` (`HTTP-15`), zero-copy `http::uri::PathAndQuery` on `PendingRequest` (`HTTP-30`), and no dead `ResponseCollector` (`HTTP-39`). Delete `DirectRequest`/`DirectBatch` and move `src/rs/vertebra-http/src/direct_worker.rs` to `src/rs/vertebra-http/benches/support/mod.rs` (`HTTP-17`).

## Context

- **`HTTP-29` (`src/rs/vertebra-http/src/router.rs:35-37,72-106`):** `Router::lookup` uppercases the HTTP method into a `Cow<str>` and hashes it in `HashMap<String, matchit::Router<HandlerId>>` on every request, and allocates a `Vec<String>` on `405 Method Not Allowed`. Indexing by the 9 standard method tags (`0..=8`: `GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `HEAD`, `OPTIONS`, `TRACE`, `CONNECT`) with a small `Vec<(String, matchit::Router<HandlerId>)>` fallback for extension methods removes the per-request SipHash and uppercase scan.
- **`HTTP-16` (`src/rs/vertebra-http/src/route_table.rs:70-85`, `src/rs/vertebra-http/tests/test_collector.rs:99-125`, `src/rs/vertebra-http/src/policy.rs:118-173`):** `handler_id_reference_values` only asserts `id != 0`; `test_drain_by_timeout` never waits on a timeout because `RequestBatcher` drains immediately; `policy.rs` tests check unread EMA fields.
- **`HTTP-15` & `HTTP-39` (`src/rs/vertebra-http/src/policy.rs:16-105`, `src/rs/vertebra-http/src/collector.rs:45-128,255-277`):** `BatchPolicy::Adaptive` writes `ema_arrival_rate` (`:98`) that nothing reads, and `ResponseCollector` (`:45-128`) has no production callers.
- **`HTTP-30` (`src/rs/vertebra-http/src/response.rs:163-164`, `src/rs/vertebra-http/src/collector.rs:142-144`):** `PendingRequest` stores `path: String` and `query: Option<String>`, forcing two heap allocations per request even though `http::Uri` already holds a reference-counted `PathAndQuery` (`Bytes`-backed).
- **`HTTP-17` (`src/rs/vertebra-http/src/direct_worker.rs:1-390`, `src/rs/vertebra-http/src/dispatcher/types.rs:13-31`, `src/rs/vertebra-http/src/dispatcher/direct.rs:1-45`):** `DirectWorkerPool` is only used by benchmarks and unit tests, and `dispatch_direct` clones every `PendingRequest` into a duplicate `DirectRequest` struct.
- **Symbol overlap note (depends on 3.1):** Touches `lib.rs` (replacing `collector`, `policy`, `router`, `route_table`, `direct_worker` module declarations with `batcher` and `routing`), `response.rs` (updating `PendingRequest` construction at `:158-172` to pass `PathAndQuery` and `RequestTags`), and `dispatcher/{mod,direct,shm,types}.rs` (updating `Batch`/`PendingRequest` imports and removing `DirectRequest`).
- **Strategy justification:** `characterization` is used because routing semantics and opportunistic batch draining are preserved while removing dead types, per-request string allocations, and unread adaptive policy state, paired with the Criterion performance gate on `server_throughput`.

- Cross-language FNV-1a 64-bit constants verified across Rust unit tests and Python `test_routing.py`.
