# Task 4.1: Apply Python 3.15 and 3.15t PyO3 optimizations, PEP 782 zero-init PyBytes, anchored Request.body_view, and Dekker batch response notifications

## Objective

Optimize all PyO3 `0.30.1` native extension crates (`vertebra-py`, `vertebra-bundler`, `vertebra-storage`) for Python `3.12`–`3.15` and free-threaded `3.14t`/`3.15t` by disabling global `Mutex`-locked `freelist`s under `Py_GIL_DISABLED`, marking non-subclassed `#[pyclass]` types `immutable_type`, replacing dynamic `PyString::intern` calls with `pyo3::intern!`, adopting PEP 782 `PyBytes::new_with`, implementing an anchored zero-copy buffer-protocol `Request.body_view` accepted directly by `submit_response_raw`/`submit_batch_raw`, and exposing Dekker request-sleep helpers without per-request `py.detach` or `eventfd` syscalls.

## Context

- `13` hot-path `#[pyclass]` structs in `vertebra-py` declare `freelist = 128`, which under PyO3 `0.30.1` + `#[cfg(Py_GIL_DISABLED)]` wraps a global `Mutex` around every allocation and deallocation across worker threads (`3.14t`/`3.15t`).
- None of the `#[pyclass]` definitions across `vertebra-py`, `vertebra-bundler`, or `vertebra-storage` set `immutable_type` (`Py_TPFLAGS_IMMUTABLETYPE`), missing inline attribute/method cache specialization in CPython 3.14/3.15 and `3.15t`.
- `wsgi/environ.rs` (`3` sites) and `rsgi/scope.rs` (`3` sites) call runtime `PyString::intern(py, ...)` per request instead of static `pyo3::intern!`.
- `response.rs:239`, `headers.rs:51`, and `db.rs` (`13` sites including `ArrowCursor::to_arrow_ipc_bytes`) build intermediate Rust `Vec<u8>` buffers and copy them into `PyBytes::new` instead of writing directly into CPython's `PyBytesWriter` (`PyBytes::new_with` / PEP 782 on Python 3.15+).
- `Request.body_view` (`src/rs/vertebra-py/src/request.rs:148-150`) currently copies into a new `PyBytes` (`PyMemoryView_FromObject(bytes)`) instead of exposing a zero-copy CPython buffer protocol (`__getbuffer__` / `__releasebuffer__`) anchored to `Request` -> `Arc<BatchSnapshot>`, and `submit_response_raw` / `submit_batch_raw` only accept `&Bound<'_, PyBytes>` rather than any contiguous buffer-protocol object (`bytes`, `bytearray`, `memoryview`).
- `transport.rs:230-270` calls `py.detach` and unconditional `resp_notify.notify()` on every single response.

## Steps

1. Add failing tests in `src/py/tests/unit/server/test_zero_copy_buffer.py`, `src/py/tests/unit/ffi/test_ffi.py`, and `src/py/tests/unit/test_freethreaded_gil.py` verifying: (a) `Request.body_view` returns a read-only zero-copy `memoryview` backed directly by `Request` (implementing the buffer protocol so `memoryview(req)` works and keeps `Request` alive after `del req`), (b) `submit_response_raw` and `submit_batch_raw` accept `bytes`, `bytearray`, and `memoryview` (`req.body_view`) directly without intermediate `bytes(...)` conversion, (c) non-subclassed `_vertebra`, `_bundler`, and `_storage` classes prevent dynamic attribute/type dictionary mutation (`Py_TPFLAGS_IMMUTABLETYPE`), and (d) Dekker `prepare_request_sleep` / `cancel_request_sleep` FFI helpers round-trip cleanly.
2. Replace `freelist = 128` across all `#[pyclass]` definitions in `vertebra-py` (`request.rs`, `headers.rs`, `response.rs`, `asgi.rs`, `rsgi/{scope,http}.rs`, `wsgi/{environ,input,runner}.rs`) with `#[cfg_attr(not(Py_GIL_DISABLED), pyclass(..., freelist = 128, immutable_type))]` and `#[cfg_attr(Py_GIL_DISABLED, pyclass(..., immutable_type))]`, and add `immutable_type` to all non-subclassed `#[pyclass]` structs in `vertebra-py` (`broker.rs`, `agent.rs`, `telemetry.rs`, `db.rs`), `vertebra-bundler/src/lib.rs` (and submodules), and `vertebra-storage/src/lib.rs` (and submodules).
3. Replace dynamic `PyString::intern` calls in `src/rs/vertebra-py/src/wsgi/environ.rs` with static `pyo3::intern!` match helpers for common HTTP methods, versions, schemes, and `HTTP_*` header names; mark module-cached protocol singletons immortal under `#[cfg(Py_3_15)]` (`ffi::PyUnstable_SetImmortal`) and use PEP 814 `PyFrozenDict_New` under `#[cfg(Py_3_15)]` where read-only cached extension dicts are exposed.
4. Adopt `PyBytes::new_with` across `src/rs/vertebra-py/src/response.rs` (`Response::to_bytes`), `headers.rs` (lowercased ASGI header names), and `db.rs` (`ArrowCursor::to_arrow_ipc_bytes` and wire frame encoders).
5. Implement CPython buffer protocol (`__getbuffer__` and `__releasebuffer__`) on `Request` in `src/rs/vertebra-py/src/request.rs` so `memoryview(req)` and `req.body_view` return an anchored zero-copy read-only `memoryview` into the `BatchSnapshot` body slice (`0` payload copies).
6. Update `submit_response_raw` and `submit_batch_raw` in `src/rs/vertebra-py/src/transport.rs` to extract contiguous byte slices from `PyBytes` or `PyBuffer<u8>` (`memoryview` / `bytearray`), write directly into the lock-free SHM / in-process ring inline without per-request `py.detach` for payloads `<= 64 KiB`, coalesce `notify_if_sleeping` to once per batch, and expose `prepare_request_sleep()` and `cancel_request_sleep()` in `_vertebra`.
