# Task 3.2: Add explicit Tokio runtime builder, multi-worker SO_REUSEPORT embedded topology, free-threaded worker pool, and lock-free sharded dispatchers

## Objective

Scale `vertebra-http` linearly from 1 core (`1w`/`1t`) to 8+ cores (`4w`/`8w`/`8t`) by replacing `#[tokio::main]` with an explicit `current_thread` / `multi_thread` Tokio runtime builder, adding multi-process `SO_REUSEPORT` embedded worker supervision (`Topology::Embedded` with `workers > 1`) and multi-thread free-threaded Python `3.14t`/`3.15t` worker pools, gating `BatchBridge::init` to embedded mode, replacing `DashMap` `BridgeCorrelation` with sharded `InFlightRequests` + direct completion callback, and making `ShmDispatcher` + `shm_reader` lock-free and batch-affinitized.

## Context

- `src/rs/vertebra-http/src/main.rs:241` uses `#[tokio::main]`, ignoring `config.worker_threads` (`VERTEBRA_THREADS`) and spawning N OS threads even on a single pinned vCPU (`taskset -c 0`).
- `Topology::Auto` (`src/rs/vertebra-http/src/config.rs:146-151`) switches `workers > 1` into a single central Rust ingress process (`Topology::Shm`) that competes with `4`–`8` Python worker processes for the same CPU budget (`120.4k` at `4w` and `97.8k` at `8w` vs Granian RSGI's per-worker `SO_REUSEPORT` `206.8k` at `4w` and `246.6k` at `8w`), and `Topology::Embedded` ignores `config.workers.count > 1` and spawns only `1` Python thread (`factory.rs:212-238`).
- `main.rs:73` registers only `[GET, POST, PUT, DELETE, PATCH]` on mounted apps, rejecting `OPTIONS` and `HEAD` with `404` before ASGI/RSGI sees them, and `main.rs:277` calls `BatchBridge::init(64)` unconditionally even in SHM mode.
- `dispatcher/bridge.rs` uses `DashMap` (`BridgeCorrelation`), copies through `BatchWriter`'s `1 MiB` slab, and requires an async `spawn_response_reader` task hop.
- `dispatcher/shm.rs` serializes all `8` `RequestBatcher` shards behind a global `Mutex<ShmBatchScratch>`, round-robins individual items inside a single batch across *all* workers (multiplying IPC frames and `eventfd` wakes by `W`), and sends `oneshot` responses while holding the `InFlightRequests` shard `Mutex`.

## Steps

1. Write behavioral and regression tests in `src/rs/vertebra-http/src/dispatcher/tests.rs` and `src/rs/vertebra-http/tests/it/dispatcher.rs` verifying: (a) embedded bridge dispatch of `256` concurrent requests completes with zero deadlocks and zero `DashMap` correlation; (b) `ShmDispatcher` routes an entire batch to a single worker with zero global `Mutex<ShmBatchScratch>`, uses MRU warm-worker affinity when in-flight load is low and batch-level round-robin under load, and wakes sleeping workers only via Dekker `consumer_sleeping`; (c) `OPTIONS` and `HEAD` requests match mounted prefixes cleanly.
2. Replace `#[tokio::main]` in `src/rs/vertebra-http/src/main.rs` with `tokio::runtime::Builder::new_current_thread()` when `config.worker_threads <= 1` (or single-core embedded worker) and `new_multi_thread().worker_threads(config.worker_threads)` when `> 1`; register `Method::OPTIONS` and `Method::HEAD` alongside `[GET, POST, PUT, DELETE, PATCH]` on mounted prefixes; gate `BatchBridge::init` strictly to `Topology::Embedded`.
3. Implement multi-process `SO_REUSEPORT` embedded supervision in `src/rs/vertebra-http/src/main.rs` and `workers/factory.rs`:
   - When `Topology::Embedded` (or `Topology::Auto` on Unix when `SO_REUSEPORT` is available and SHM cross-process isolation is not explicitly requested; preserve explicit `--topology shm` completely) runs with `config.workers.count > 1` and `VERTEBRA_EMBEDDED_WORKER != "1"`, pre-initialize shared SHM broker/pubsub FDs in the parent supervisor and spawn `W` child `vertebra-server` processes with `VERTEBRA_EMBEDDED_WORKER=1`, `SO_REUSEPORT` enabled, and inherited broker FDs, forwarding `SIGINT`/`SIGTERM` and respawning crashed workers.
   - Inside embedded worker processes (`workers/factory.rs`), query `_vertebra.FREE_THREADED`; when running on free-threaded Python (`3.14t`/`3.15t`) and `py_threads > 1`, spawn `N` embedded Python worker threads sharing the lock-free `BatchBridge` `crossbeam` receiver, and store `JoinHandle`s for clean shutdown join.
4. Overhaul `src/rs/vertebra-http/src/dispatcher/bridge.rs` and `dispatcher/mod.rs`:
   - Replace `BridgeCorrelation` (`DashMap`) with the 8-shard `InFlightRequests` slab (`allocate_batch` + `complete_many`), register a direct `ResponseSink` callback on `BatchBridge` that completes `oneshot::Sender` directly when Python submits responses (releasing the shard `Mutex` before `tx.send(...)`), add a lightweight periodic `sweep_expired` background timer task, and submit request batches zero-copy via `BatchBridge::submit_inprocess_batch`.
5. Overhaul `src/rs/vertebra-http/src/dispatcher/shm.rs` and `shm_reader.rs`:
   - Delete `Mutex<ShmBatchScratch>` from `ShmDispatcher`; compute serialized batch byte length and write directly into the target worker's SHM slot via `request_ring.try_send_with(total_len, 0, |slot| ...)` (with brief bounded `send_with` fallback), routing the entire batch to one worker (sticking to the warm MRU worker when `in_flight <= 4` for optimal `c=1` cache locality and advancing round-robin per batch otherwise).
   - Call `worker.rings.notify_request_if_sleeping()` once per batch instead of unconditional `req_notify.notify()`.
   - Update `shm_reader.rs` to use Dekker `prepare_response_sleep` / `cancel_response_sleep` around `resp_notify.notified().await`, zero-copy `drain_responses_with` (`0` per-response `Vec<u8>` allocations), and release the `InFlightRequests` shard `Mutex` before invoking `tx.send(response)`.

## Notes & Discoveries

- `RouteTable::insert_mount_prefix_indexed` encodes `MOUNT_HANDLER_BASE | mount_index` (`0xFFFF_0000_0000_0000 | mount_index`) across `GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD` on both exact root and `/*rest` catch-all patterns, enabling `O(1)` mount resolution in Python without decoding `request.path`.
- `EmbeddedSupervisor` computes `(tokio_threads, py_threads)` per `SO_REUSEPORT` worker against `std::thread::available_parallelism()` (`sched_getaffinity`) so `4w` and `8w` on `8` cores run `1` `current_thread` Tokio runtime + `1` (or `2` on `3.14t`/`3.15t`) Python worker threads per process with zero core oversubscription.
