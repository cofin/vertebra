# Task 5.1: Overhaul Python worker loop with uvloop, inline vectorized sync dispatch, same-thread add_reader polling, Rust ASGI/RSGI batch drivers, O(1) mount routing, and PEP 810 lazy modules

## Objective

Eliminate `ThreadPoolExecutor(32)` GIL thrashing on synchronous native routes, fix the `worker.py` double-execution bug and async `BatchSnapshot` retention leak, enable `uvloop` automatically, unify single-loop polling on the event-loop thread via `loop.add_reader(notify_fd, ...)` + Dekker sleep handshakes, wire `AsgiRunner` and `RsgiAdapter` to `drive_asgi_batch` / `drive_rsgi_batch`, route mounted apps in `O(1)` via `handler_id`, accept zero-copy `memoryview` return values in `_serialize_result`, and declare PEP 810 `__lazy_modules__`.

## Context

- `src/py/vertebra/server/_loops.py` imports pure-Python `asyncio.new_event_loop()` even though `uvloop>=0.21.0` is installed, costing `2`–`3x` coroutine and I/O scheduling latency.
- `src/py/vertebra/server/worker.py:395-404` offloads every `"sync_native"` handler to `ThreadPoolExecutor(max_workers=32)` via `pool.submit()`, causing `33`-thread GIL thrashing on 1 vCPU; lines `405-423` also contain a double-execution bug where non-`"sync_native"` sync handlers run via `self._submit_sync_item(req, entry)` and then execute *again* inline and append a duplicate `raw_responses` tuple.
- `_dispatch_async_item` (`worker.py:337-363`) keeps `req: Request` alive across `await handler(...)`, pinning the entire `Arc<BatchSnapshot>` (`SlotView` or slab) until the slowest coroutine finishes (`io10 c=256`).
- `_serialize_result` (`_dispatch.py:136`) rejects `memoryview` / `bytearray` (`req.body_view`), forcing `bytes(...)` copies.
- `EventLoopPool` (`_loops.py`) spawns background OS event-loop threads even when `size == 1`, forcing cross-thread `call_soon_threadsafe` self-pipe wakeups per request instead of running `loop.add_reader(notify_fd, ...)` on the main worker thread (and `spawn` wakes per item instead of `spawn_batch`).
- `mount()` (`worker.py:173-189`) ignores `req.handler_id` and performs an `O(M)` linear prefix scan (`_match_mount`) per request instead of assigning negative `handler_id`s (`-1`, `-2`, ...) in `VERTEBRA_ROUTES` for `O(1)` lookup.

## Steps

1. Write failing regression and behavioral tests in `src/py/tests/unit/server/test_runner.py` and `test_stage1_hotpath_and_314t.py` covering: (a) inline vectorized `"sync_native"` batch execution with `0` `ThreadPoolExecutor` submissions by default and opt-in `sync_to_thread=True` route execution via thread pool without double-execution, (b) `_serialize_result` accepting `memoryview` (`req.body_view`) and `bytearray` directly, (c) `_dispatch_async_item` releasing its `Request` reference before `await` when `takes_request=False` (or dropping local `req` immediately after invocation setup), (d) `uvloop` event loop creation on POSIX when available, (e) `O(1)` negative `handler_id` mount dispatch, and (f) PEP 810 `__lazy_modules__` presence on `vertebra` and `vertebra.framework`.
2. Update `src/py/vertebra/server/_loops.py` to prefer `uvloop.new_event_loop` on POSIX via `import_optional("uvloop")` (falling back to `winloop` on Windows and `asyncio.new_event_loop` otherwise), add `spawn_batch` coalescing items into a single `call_soon_threadsafe` wakeup per target loop when `size > 1`, and support inline single-thread `loop` execution when `size == 1`.
3. Update `src/py/vertebra/framework/_router.py`, `_app.py`, and `src/py/vertebra/server/_dispatch.py`:
   - Add `sync_to_thread: bool = False` option on route decorators (`@app.get(..., sync_to_thread=False)`), classifying default sync routes as `"sync_inline"` (executed directly in the vectorized batch loop and flushed via one `submit_batch_raw`) and `sync_to_thread=True` routes as `"sync_thread"` (submitted once to `ThreadPoolExecutor` with the double-execution bug removed).
   - Accept `memoryview` and `bytearray` in `_serialize_result` so `return req.body_view` flows zero-copy to `submit_batch_raw` / `submit_response_raw`.
4. Update `src/py/vertebra/server/worker.py`, `_asgi/_runner.py`, and `_rsgi/_adapter.py`:
   - Assign negative `handler_id`s (`-1`, `-2`, ...) to mounted ASGI/WSGI/RSGI apps and export them in `build_route_table()` so `vertebra-http` stamps `req.handler_id` and `BatchRunner` dispatches mounts in `O(1)` (keeping `_match_mount` only as fallback when `handler_id == 0`).
   - Clear local `req` reference before `await coro` in `_dispatch_async_item` so handlers that do not retain `req` release `Arc<BatchSnapshot>` immediately on suspension.
   - Route unary HTTP ASGI batches through `_vertebra.drive_asgi_batch` in `AsgiRunner` (retaining WebSocket/SSE upgrade handling) and unary HTTP RSGI batches through `_vertebra.drive_rsgi_batch` in `RsgiAdapter`.
   - When `scheduler.size == 1` and `notify_fd is not None` (SHM worker mode), drive `try_get_batch()` directly on the `uvloop` thread via `loop.add_reader(notify_fd, ...)` with Dekker `prepare_request_sleep()` / `cancel_request_sleep()` so async native, ASGI, and RSGI requests execute on a single thread with **zero** cross-thread `call_soon_threadsafe` hops; use Dekker sleep/wake around `select.select` in threaded/blocking loop modes as well.
5. Add PEP 810 `__lazy_modules__` declarations to `src/py/vertebra/__init__.py` and `src/py/vertebra/framework/__init__.py` (remembering zero inline `#` comments anywhere in Python).
