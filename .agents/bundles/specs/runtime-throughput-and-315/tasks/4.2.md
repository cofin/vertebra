# Task 4.2: Implement Rust-native AsgiProtocol and drive_asgi_batch plus lazy RsgiScope, direct-submitting RsgiHttpProtocol, and drive_rsgi_batch

## Objective

Eliminate per-request Python wrapper objects, `asyncio.Queue`s, `asyncio.Event`s, and `asyncio.Task` allocations on single-step unary ASGI and RSGI requests by implementing frozen zero-suspension Rust `PyEmptyAwaitable` / `PyValueAwaitable`, Rust-native `AsgiProtocol` + `drive_asgi_batch`, and zero-alloc lazy `RsgiScope` + direct-submitting `RsgiHttpProtocol` + `drive_rsgi_batch` (also fixing the `RSGI_DONE` `&mut self` re-borrow bug under `3.14t`/`3.15t`).

## Context

- `VertebraSHMASGI` currently achieves only `7,488 req/s` (`c=1`) and `23,433 req/s` (`c=64`) on 1 core (`75,452 req/s` at `4w` vs Granian ASGI's `144,596 req/s`) because `_asgi/_runner.py` + `_queues.py` allocate `6`–`10` Python objects/dicts/coroutines per request (`UnaryHttpExchange`, `AsgiResponseAccumulator`, `receive()`/`send()` async coroutines, `list[tuple[bytes, bytes]]`, `bytearray`, and `loop.create_task` for every single item).
- `RsgiScope::from_snapshot` (`src/rs/vertebra-py/src/rsgi/scope.rs:41-81`) eagerly allocates `4` Rust `String`s (`proto`, `http_version`, `method`, `path` + `query_string`), rebuilds a new `Headers` object on every `.headers` property access, scans headers on every `.authority` access, and ignores sub-mount `root_path`; `RsgiDoneAwaitable` (`rsgi/http.rs:14-31`) lacks `frozen` (`&mut self.__next__`), causing `PyBorrowMutError` under concurrent awaits on `3.14t`/`3.15t`; `RsgiHttpProtocol` stores responses inside a Rust `Mutex<RsgiHttpState>` requiring Python `proto.take_response()` + `submit_response_raw(...)` round-trips.

## Steps

1. Write failing unit tests in `src/py/tests/unit/server/test_asgi.py`, `test_asgi_scope_and_extensions.py`, and `test_rsgi_protocol.py` covering: (a) `AsgiProtocol` (`receive`, `send`) and `drive_asgi_batch` handling both immediate unary ASGI apps (zero `asyncio.Task` creation via `PyIter_Send`) and suspending async ASGI apps (`asyncio.sleep` / multi-chunk streaming bodies / lifecycle exceptions -> `500`), (b) `RsgiScope` lazy field access, cached `.headers`, sub-mount `root_path` slicing, and static `pyo3::intern!` strings, (c) concurrent `await proto()` calls on the `RsgiDoneAwaitable` singleton without `PyBorrowMutError`, and (d) `RsgiHttpProtocol` direct Rust transport submission plus `drive_rsgi_batch` single-step coroutine stepping (while preserving `take_response()` when `direct_submit=False` for isolated unit tests).
2. Implement `PyEmptyAwaitable` (`frozen, immutable_type`, cached singleton) and `PyValueAwaitable` (`frozen, immutable_type`, returning its payload immediately on `__next__` via `PyStopIteration` with zero event-loop yield) plus `AsgiProtocol` (`receive`, `send`, encoding ASGI response headers directly to compact binary bytes in Rust and submitting unary responses on `more_body == False`, with chunk accumulation for multi-chunk bodies and disconnect wait event fallback) and `drive_asgi_batch(app, batch, loop, root_path)` in `src/rs/vertebra-py/src/asgi.rs`:
   - Step `coro = app(scope, proto.receive, proto.send)` once via `ffi::PyIter_Send(coro.as_ptr(), Py_None(), &mut result)`:
     - `PYGEN_RETURN`: response already buffered/submitted; flush batch responses at end of loop with zero `loop.create_task` allocation.
     - `PYGEN_NEXT`: schedule `coro` (resuming from the yielded future via a minimal continuation or `loop.create_task` wrapper) on `loop`.
     - `PYGEN_ERROR`: clear/log exception and emit `500` response if headers were not yet sent.
3. Refactor `src/rs/vertebra-py/src/rsgi/scope.rs` to store `(snapshot: Arc<BatchSnapshot>, index: usize, root_path: String, cached_headers: OnceLock<Py<Headers>>)` with zero eager string copies on construction, static `pyo3::intern!` strings for `proto`/`http_version`/`scheme`/common methods, and cached `Headers`.
4. Refactor `src/rs/vertebra-py/src/rsgi/http.rs` and `mod.rs`:
   - Mark `RsgiDoneAwaitable` `frozen, immutable_type` with `&self` on `__await__` and `__next__`.
   - Support direct transport submission inside `RsgiHttpProtocol::response_empty`, `response_str`, `response_bytes`, and `response_file` when attached to an active transport (falling back to buffering for `take_response()` when unattached or `direct_submit=False`), and implement `drive_rsgi_batch(app, batch, loop, root_path)` using the same C-API `PyIter_Send` single-step fastpath.
5. Register `PyEmptyAwaitable`, `PyValueAwaitable`, `AsgiProtocol`, `drive_asgi_batch`, and `drive_rsgi_batch` in `src/rs/vertebra-py/src/lib.rs` and update type stubs in `src/py/vertebra/_vertebra.pyi`.
