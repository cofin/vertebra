# Task 2.2: Right-size SHM tiered rings, cache SPSC heads, pad MPMC sequence slots, and add Dekker zero-syscall wakeups

## Objective

Eliminate per-request/per-batch `eventfd` syscalls and cross-core cache-line ping-pong across `SpscRing`, `MpmcRing`, `TieredRingSet`, and `WorkerRingPair` by right-sizing `TieredRingConfig::default()`, caching SPSC producer/consumer heads, checking `head == tail` before `slot_borrowed` CAS, padding MPMC sequence slots to `CACHELINE_BYTES`, and implementing a `SeqCst` Dekker `consumer_sleeping` + `active_tier_mask` handshake in `ShmHeader` (`ABI_VERSION = 3`) plus zero-copy SHM `SlotView`-backed `BatchSnapshot`s.

## Context

- `TieredRingConfig::default()` (`src/rs/vertebra-core/src/tiered_ring.rs:41-61`) allocates only `64` small slots (`63` usable), overflowing on single-worker `c=256` bursts.
- `SpscRing::try_recv_view` (`src/rs/vertebra-core/src/channel.rs:437`) executes an RMW `slot_borrowed.compare_exchange` *before* checking whether the ring is empty (`head == tail`), dirtying cache lines across all empty tiers on every poll.
- `SpscRing` reloads `read_head` (`Acquire`) on every `try_send` and emits `wait_write`/`wait_read` `SeqCst` `fetch_add` on every slot even when no futex waiter exists; `send_with` parks immediately on `Full` without brief `Backoff` spinning; `MpmcRing` packs 8 `AtomicU64` sequence numbers per 64-byte cache line (`channel.rs:647`).
- Both `ShmDispatcher` and `ShmWorkerTransport` call `eventfd::write(1)` unconditionally on every batch/response even when the peer is actively polling, and `TieredRingSet::try_recv` copies every SHM slot into a fresh heap `Vec<u8>`.

## Steps

1. Write behavioral tests in `src/rs/vertebra-core/tests/it/ring.rs`, `mpmc.rs`, and `shm.rs` verifying: (a) `ABI_VERSION == 3` and `ShmHeader` Dekker `consumer_sleeping` (`prepare_sleep`, `cancel_sleep`, `notify_if_sleeping`) skips `EventNotifier::notify()` when `consumer_sleeping == 0` and wakes reliably when `consumer_sleeping == 1`; (b) `TieredRingSet` `active_tier_mask` drains small-tier payloads without touching inactive large/xlarge rings and `drain_with` visits slots zero-copy without heap `Vec<u8>` allocation; (c) `SpscRing` cached heads and `try_recv_view` fast-empty check preserve strict SPSC FIFO ordering under high contention; (d) `MpmcRing` cache-line-padded sequence slots pass multi-producer/multi-consumer stress tests.
2. Bump `ABI_VERSION` to `3` in `src/rs/vertebra-core/src/buffer.rs` and add `pub consumer_sleeping: CacheLine<AtomicU32>` and `pub active_flags: CacheLine<AtomicU32>` to `ShmHeader` (updating any existing `ABI_VERSION` assertions in `vertebra-core` tests).
3. Optimize `SpscRing` and `MpmcRing` in `src/rs/vertebra-core/src/channel.rs`:
   - Check `head == tail` *before* `slot_borrowed.compare_exchange` in `try_recv_view`.
   - Add `cached_read_head: AtomicU64` and `cached_write_head: AtomicU64` on `SpscRing` so `try_send`/`try_send_with` only load `read_head(Acquire)` when `next == cached_read_head`, and `has_data` / `try_recv` utilize cached `write_head`.
   - Gate `wait_write.fetch_add(1, SeqCst)` / `wait_read.fetch_add(1, SeqCst)` or coalesce wakeups in `try_recv_batch` / `drain_with`, and add a bounded `Backoff` spin (`<= 32` steps) in `send_with` before calling `park_send`.
   - Add `SpscRing::drain_with<F: FnMut(&[u8], u32)>(&self, max_items: usize, f: F) -> Result<usize, ChannelError>` advancing `read_head` once per drained batch.
   - Pad `MpmcRing` sequence elements to `CacheLine<AtomicU64>` (`64` bytes per slot).
4. Update `TieredRingConfig::default()` in `src/rs/vertebra-core/src/tiered_ring.rs` to `small: 4096 x 512` (or `1024` slots, keeping per-worker SHM footprint compact at ~10 MiB while absorbing `c=256+` bursts without overflow), `medium: 32768 x 128`, `large: 262144 x 32`, `xlarge: 2097152 x 8`; record active tiers in the small ring's `ShmHeader.active_flags` bitmask (`bit 0..3`) and expose Dekker sleep/wake helpers (`prepare_sleep`, `cancel_sleep`, `should_notify_and_clear`) plus zero-copy `try_recv_view` and `drain_with` on `TieredRingSet` and `WorkerRingPair`.
5. Update `BatchSnapshot` (`bridge.rs`) and `ShmWorkerTransport` (`transport/mod.rs`) so `ShmWorkerTransport::try_get_batch` / `get_batch` decodes SHM request batches directly from `SlotView` (`Backing::ShmSlot(SlotView)`) without copying the slot into an intermediate `Vec<u8>` or copying bodies into a fresh `Bytes` buffer, and uses `response_ring.notify_if_sleeping(&resp_notify)` instead of unconditional `resp_notify.notify()` on every single response.

## Verification

- Strategy: `behavior_tdd` — new Dekker zero-syscall wakeup, `active_tier_mask` fast-drain, cached-head SPSC, and `SlotView`-backed `BatchSnapshot` behaviors verified by failing tests first, followed by full `vertebra-core` test suite.

## Acceptance Criteria

- [ ] `AC-2.2.1`: `ShmHeader` (`ABI_VERSION = 3`) provides `SeqCst` Dekker `consumer_sleeping` and `active_flags` fields, eliminating `eventfd` `write()` syscalls while the consumer is awake and guaranteeing lost-wakeup-free notification when sleeping.
- [ ] `AC-2.2.2`: `TieredRingConfig::default()` accommodates `c=256+` small-payload bursts (`>= 512` small slots) without ring overflow, and `TieredRingSet::drain_with` drains active tiers zero-copy in small-first order.
- [ ] `AC-2.2.3`: `SpscRing::try_recv_view` checks `head == tail` before `slot_borrowed` CAS, caches remote heads, spins briefly with `Backoff` before `park_send`, and `MpmcRing` pads sequence slots to `CACHELINE_BYTES`.
- [ ] `AC-2.2.4`: `ShmWorkerTransport` constructs `SlotView`-backed `BatchSnapshot`s without intermediate `Vec<u8>` slot copies.
