# 3.3 Bidirectional MCP <-> A2A bridges (`agent/bridges/{mcp,a2a}.py`)

## Objective
Create `src/py/vertebra/agent/bridges/{mcp,a2a,__init__}.py` providing bidirectional protocol translation between MCP `2026-07-28` and A2A `1.0`: `McpToolBridge` converts an A2A `AgentCard` and `A2AService` (or remote A2A endpoint) into callable `vertebra.agent.core.Tool` instances registered on an `MCPRegistry`, while `A2aAgentBridge` projects an `MCPRegistry` / `MCPService` and its `SkillController` instances into an A2A `1.0` `AgentCard` and `A2AService` task executor.

## Context
- `litestar_mcp/agent/bridges/mcp.py:21-125` and `litestar_mcp/agent/bridges/a2a.py:52-199` bridge `Agent` / `AgentGroup` to MCP and A2A, but also need direct protocol-to-protocol composition so any A2A remote peer can be called as an MCP tool (`a2a_<agent>_<skill_id>`) and any MCP tool/skill server can be discovered and invoked by A2A `1.0` peers (`message/send` and `message/stream`).
- W3C `TraceContext` (`traceparent`) and `CallerIdentity` must propagate across both bridge directions so distributed traces remain unbroken when an MCP tool call delegates to an A2A agent or vice versa.
- `behavior_tdd` applies because `vertebra.agent.bridges` introduces cross-protocol schema synthesis, execution delegation, and trace propagation.

## Steps
- [ ] 1. Create `src/py/vertebra/agent/bridges/mcp.py` implementing `McpToolBridge`:
  - `McpToolBridge.from_a2a_service(service: A2AService, *, prefix: str | None = None) -> list[Tool]` and `McpToolBridge.from_agent_card(card: AgentCard, transport: Callable[[dict[str, Any], dict[str, str]], Awaitable[dict[str, Any]]], *, prefix: str | None = None) -> list[Tool]`.
  - For each `AgentSkill` in `card.skills`, synthesize a `Tool` named `f"{prefix}_{skill.id}"` (or `skill.id`) with input schema `{"type": "object", "properties": {"prompt": {"type": "string"}, "context_id": {"type": "string"}, "data": {"type": "object"}}, "required": ["prompt"]}` that sends an A2A `1.0` `message/send` request carrying `TextPart(text=prompt)` (and optional `DataPart`), propagates `TraceContext` via `inject_w3c_trace_context`, and extracts the returned `Task` artifacts/messages into the MCP tool result.
- [ ] 2. Create `src/py/vertebra/agent/bridges/a2a.py` implementing `A2aAgentBridge`:
  - `A2aAgentBridge.from_mcp_service(mcp_service: MCPService, *, base_url: str, path: str = "/a2a", name: str | None = None, description: str = "") -> A2AService`.
  - Project every registered `SkillController` (`to_agent_skill()`) and standalone `Tool` in `mcp_service.registry` into `AgentSkill` entries on an A2A `1.0` `AgentCard` with `supported_interfaces=(AgentInterface(url=f"{base_url.rstrip('/')}{path}", protocol_binding="JSONRPC", protocol_version="1.0"),)`.
  - Route incoming A2A `message/send` and `message/stream` invocations (matching a target skill/tool via `message.metadata["skill_id"]` or `DataPart` `{"tool": name, "arguments": {...}}`) into `mcp_service` under the caller's `AgentContext` and emit `TaskStatusUpdateEvent` / `TaskArtifactUpdateEvent` frames.
- [ ] 3. Create `src/py/vertebra/agent/bridges/__init__.py` exporting `McpToolBridge` and `A2aAgentBridge`, and register `"bridges"` in `src/py/vertebra/agent/__init__.py`.
- [ ] 4. Commit: `feat(agent): add bidirectional McpToolBridge and A2aAgentBridge protocol translators` (signed), staging the paths in `files`.
