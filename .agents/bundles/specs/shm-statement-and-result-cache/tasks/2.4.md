# Task 2.4: Criterion Benchmarks & Multi-Worker 3.12/3.14t Integration Verification

## Objective

Create the Criterion benchmark suite in `src/rs/vertebra-core/benches/broker.rs` (registered in `src/rs/vertebra-core/Cargo.toml`) and the end-to-end multi-worker Python integration test suite in `src/py/tests/unit/extensions/test_broker_integration.py` covering `ShmBrokerTransport`, `ShmSessionBroker`, `NativeStatementCache`, `AlchemyPlugin`, `SQLSpecPlugin`, `/debug/zpages/broker`, and `DbPoolRecorder`.

## Context

- `src/rs/vertebra-core/Cargo.toml:45-76` registers Criterion benchmarks (`spsc`, `ring_throughput`, `codec`, `shm_transport`). Adding `[[bench]] name = "broker" harness = false` enables microbenchmarking uncontended CAS acquire/release, 8-thread futex contention, and seqlock statement cache lookup throughput.
- End-to-end verification must prove that multiple spawned worker processes sharing a broker segment respect `pool_size + max_overflow`, share compiled `StatementPlan` entries across processes on the first lookup after a peer worker's insert, and report accurate counters via `/debug/zpages/broker` and `DbPoolRecorder`.

## Steps

1. Add `src/rs/vertebra-core/benches/broker.rs` and register `[[bench]] name = "broker" harness = false` in `src/rs/vertebra-core/Cargo.toml`:
   - `bench_lease_uncontended_acquire_release`: measures single-thread `try_acquire` + `release` latency on a 32-slot `ShmLeaseTable`.
   - `bench_lease_contended_8_threads`: measures 8-thread acquire/release throughput across a 16-slot `ShmLeaseTable`.
   - `bench_statement_cache_seqlock_lookup`: measures `ShmStatementCache::lookup` latency on a populated 512-slot table.
2. Create `src/py/tests/unit/extensions/test_broker_integration.py` testing the complete Python + Rust stack:
   - `test_shm_broker_transport_async_contended_futex_wakeup`: runs 16 concurrent `asyncio` tasks acquiring and holding leases for 5 ms against a `ShmBrokerTransport(BrokerConfig(pool_size=3, max_overflow=1, acquire_timeout_ms=2000))`; asserts peak active leases never exceeds `4`, `overflow_in_use` reaches `1`, and all 16 tasks succeed without polling timeouts.
   - `test_shm_statement_cache_cross_process_hit`: spawns a child process that attaches to a named `ShmBrokerTransport`, compiles a parameterized SQL query via `get_or_compile_statement("postgresql", "SELECT * FROM users WHERE org_id = :org_id AND status = :status", ...)`, and exits; parent process calls `get_or_compile_statement` for the same SQL with a compiler callback that raises `AssertionError("compiler must not run on cache hit")` and verifies the cached `StatementPlan` is returned directly from shared memory with `statement_cache_hits == 1`.
   - `test_broker_plugin_zpages_and_otel_integration`: wires `BrokerPlugin`, `AlchemyPlugin`, `SQLSpecPlugin`, `ZPagesRegistry`, and `DbPoolRecorder`, executes lease checkouts and statement lookups, calls `zpages.handle_zpage("/debug/zpages/broker")`, and asserts the decoded JSON payload and `DbPoolRecorder` metrics match the exact acquire, release, and cache hit counts.
