# 9.5 Flatten TypeScript tests to mirror src/ts/vertebra-client/src/ and add OfflineDeltaQueue and adapter tests

## Objective

Standardize the TypeScript Vitest suite under `src/ts/vertebra-client/tests/<module>.test.ts` mirroring `src/ts/vertebra-client/src/`, eliminating the nested `tests/unit/` directory and splitting multi-module test files (`TST-13`). Add behavioral unit tests for `OfflineDeltaQueue` in `live.test.ts`, `ReconnectScheduler` in `reconnect.test.ts`, `QueryController`/`QueryCache` in `query.test.ts`, and the thin framework adapters (`react.test.tsx`, `vue.test.ts`, `svelte.test.ts`, `angular.test.ts`).

## Context

- **Confirmed evidence (`TST-13`):**
  - `src/ts/vertebra-client/tests/` currently mixes two files inside `tests/unit/` (`tests/unit/client.test.ts`, `tests/unit/store.test.ts`) with six files directly under `tests/` (`apex.test.ts`, `arrow.test.ts`, `live.test.ts`, `realtime.test.ts`, `telemetry.test.ts`, `wasm.test.ts`).
  - `src/ts/vertebra-client/tests/unit/client.test.ts:1-171` bundles `HttpClient` (`lines 11-119`), `computeBackoffDelay` (`lines 121-130`), `QueryCache` (`lines 132-165`), and `initHtmx` (`lines 167-171`), and line 5/21 still references `RealtimeChannel` removed in Chapter 7 (`7.5`).
  - `src/ts/vertebra-client/tests/realtime.test.ts:224-248` embeds the `HotReloadClient` test inside the `SseClient & WebSocketClient` suite and lines 119-122 assert `typeof SseClient === "function"`.
  - `src/ts/vertebra-client/tests/live.test.ts` does not test `OfflineDeltaQueue` enqueue, persistence, overflow eviction, or reconnect flush ordering.
  - Framework adapters (`src/react/`, `src/vue/`, `src/svelte/`, `src/angular/`) have zero dedicated test files.
- **File overlap note:** Runs after Chapter 7 (`frontend-and-tooling-consolidation`) has extracted `src/client/reconnect.ts` (`ReconnectScheduler`) and `src/query/index.ts` (`QueryCache`, `QueryController`) and deleted `RealtimeChannel`.
- **Verification strategy justification:** `characterization` is used because we are reorganizing the existing TypeScript test suite to match the production module structure and adding behavioral coverage for untested client classes.

## Steps

- [x] 1. Move `src/ts/vertebra-client/tests/unit/store.test.ts` to `src/ts/vertebra-client/tests/store.test.ts` (updating relative imports from `../../src/` to `../src/`).
- [x] 2. Split `src/ts/vertebra-client/tests/unit/client.test.ts` into four canonical files under `src/ts/vertebra-client/tests/` and delete `src/ts/vertebra-client/tests/unit/client.test.ts` (removing the empty `tests/unit/` directory):
  - `src/ts/vertebra-client/tests/client.test.ts`: `HttpClient` path interpolation, query string serialization, `TimeoutError` on abort, non-JSON error handling, retryable 503 vs non-retryable 403 status handling, and `middleware` request/response interception.
  - `src/ts/vertebra-client/tests/reconnect.test.ts`: `computeBackoffDelay` exponential jitter/cap and `ReconnectScheduler` (`schedule`, `reset`, `cancel`, `maxRetries` exhaustion).
  - `src/ts/vertebra-client/tests/query.test.ts`: `QueryCache` (`stableKey` nested object key ordering, `get` stale check, `getOrCreate` inflight deduplication and rejection cleanup, `invalidate` prefix matching) and `QueryController` state transitions (`idle` -> `loading` -> `success` / `error`).
