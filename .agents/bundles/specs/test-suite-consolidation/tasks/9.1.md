# 9.1 Record coverage baseline and replace weak or import-only Python test assertions

## Objective

Record the exact pre-consolidation Python line and branch coverage baseline per subpackage in the task notes before modifying any test files, so Task `9.6` can lock a non-regressing `fail_under` threshold. Delete pure import-existence tautologies (`test_subdomain_consolidation_and_shims`, `test_canonical_extension_exports`) and replace weak `is not None`, `callable(...)`, `hasattr(...)`, and `inspect.signature(...)` assertions across the Python unit suite with behavioral assertions that exercise real inputs and outputs (`TST-01`).

## Context

- **Confirmed evidence (`TST-01`):**

  - `src/py/tests/unit/server/test_runner.py:59-66` (`test_unified_event_loop_call_handler_accepts_loop_param`), `582-593` (`test_thread_safety_run_worker_no_free_threading_gate`), and `603-611` (`test_free_threading_run_worker_accepts_worker_count`) check `inspect.signature` and `inspect.getsource` instead of invoking the target functions.

  - `src/py/tests/unit/extensions/test_litestar_plugin.py:217-220` and `244-246` assert `is not None` on offloaded state and configs instead of asserting exact `CompressionConfig` and `CORSConfig` field values (`backend == "zstd"`, `minimum_size == 512`, `allow_origins == ["https://console.example.com"]`).

- **File overlap note:** The 8 Python test files modified in `9.1` are subsequently redistributed into canonical paths in `9.2` (`depends_on: [test-suite-consolidation:9.1]`).
- **Verification strategy justification:** `characterization` is used because we are capturing the baseline coverage of existing production code and strengthening existing test assertions without changing production behavior.
