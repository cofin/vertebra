# 9.4 Consolidate vertebra-core and vertebra-http integration tests into tests/it/main.rs and deduplicate ring/batcher tests

## Objective

Reduce Cargo link-time overhead across the Rust workspace by consolidating the 4 `vertebra-core` integration test files into `src/rs/vertebra-core/tests/it/main.rs` (keeping `tests/loom_spsc.rs` isolated behind `#![cfg(loom)]`) and the 17 `vertebra-http` integration test files into `src/rs/vertebra-http/tests/it/main.rs` (`TST-12`). Remove duplicate unit vs. integration ring and string-table tests in `vertebra-core` (`CORE-39`) and duplicate `BatchCollector` tests in `vertebra-http` (`HTTP-16`).

## Context

- **Confirmed evidence (`TST-12`, `CORE-39`, `HTTP-16`):**
  - `src/rs/vertebra-core/tests/` has 4 separate binaries (`shm_streaming_tests.rs`, `test_mpmc.rs`, `test_ring.rs`, `test_shm.rs`), plus `loom_spsc.rs` added in Chapter 8 (`8.3`).
  - `src/rs/vertebra-http/tests/` has 17 separate binaries (`apex_plsql_gateway_tests.rs`, `body_limits.rs`, `compression.rs`, `cors.rs`, `apex_session_routing_tests.rs`, `file_server_tests.rs`, `health_endpoint_tests.rs`, `http2_prior_knowledge.rs`, `ipc_roundtrip.rs`, `lifecycle_tests.rs`, `openapi_docs_tests.rs`, `proxy_headers_tests.rs`, `rate_limit.rs`, `security_headers_tests.rs`, `server_integration.rs`, `static_files.rs`, `tls_integration.rs`, `ws_pubsub_hub_tests.rs`; note `mcp_discovery_bridge_tests.rs` was removed in Chapter 3 task `3.10`).
  - `CORE-39`: `src/rs/vertebra-core/tests/test_ring.rs` duplicates `spsc_recv_hybrid_timeout` and `spsc_full_returns_error` from `src/rs/vertebra-core/src/ring/spsc.rs`, and `test_shm.rs` duplicates `method_name` roundtrips from `src/rs/vertebra-core/src/transport/headers.rs`.
  - `HTTP-16`: `BatchCollector` unit tests in `src/rs/vertebra-http/src/batcher.rs` overlap with integration batcher assertions.
- **File overlap note:** `src/rs/vertebra-core/src/ring/spsc.rs`, `src/rs/vertebra-core/src/transport/headers.rs`, and `src/rs/vertebra-http/src/batcher.rs` are touched here only inside their `#[cfg(test)] mod tests` blocks after Chapters 2, 3, and 8 have completed.
- **Verification strategy justification:** `characterization` is used because we are consolidating integration test binaries and deduplicating redundant unit/integration test cases while preserving all unique test coverage.
