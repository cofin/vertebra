# 2.2 Pooled SyncOracleDriver and AsyncOracleDriver, OracleWallet sqlnet.ora mTLS, DBMS_CLOUD staging, and OracleHybridSearch execution

## Objective
Add `vertebra[oracle]` (`oracledb>=2.5`, `cryptography>=43.0`) to `pyproject.toml`, implement pooled `oracledb` Thin/Thick execution and `DBMS_CLOUD.COPY_DATA` object store staging in `SyncOracleDriver` and `AsyncOracleDriver` (`src/py/vertebra/db/oracle/driver.py`), add `sqlnet.ora` parsing to `OracleWallet` (`src/py/vertebra/db/oracle/wallet.py`), fix the `ORA-01036` unbound parameter defect and add live RRF execution in `OracleHybridSearch` (`src/py/vertebra/extensions/sqlspec/oracle.py`), and resolve `B905`, `S105`, and `FW-56` across `src/py/vertebra/db/oracle/`.

## Context
- `src/py/vertebra/db/oracle/driver.py:50` calls `zip(cols, row, strict=False)` (`B905`, `FW-48`), `SyncOracleDriver.encode_vector` (`:89-97`) takes duplicate `type_code` and `dtype` arguments (`FW-56`), and neither `SyncOracleDriver` nor `AsyncOracleDriver` creates an `oracledb` pool, executes SQL (`execute_tuples`, `execute_df`), or stages `ObjectStore` datasets via `DBMS_CLOUD` (`FW-03`).
- `src/py/vertebra/db/oracle/wallet.py:59-75` (`OracleWallet.extract`) accepts duplicate `target_dir` and `cache_root` parameters (`FW-56`) and ignores `sqlnet.ora` files inside the wallet archive.
- `src/py/vertebra/db/oracle/containers.py:19` hardcodes `admin_password: str = "WelcomeOracle26ai!"` (`S105`, `FW-48`, `FW-56`).
- `src/py/vertebra/extensions/sqlspec/oracle.py:124-156` (`OracleHybridSearch.build_rrf_sql`) interpolates `candidate_limit` and `rrf_k` as literals while also returning `"rrf_k"` and `"candidate_limit"` in `binds`, which triggers `ORA-01036: illegal variable name/number` when passed to `oracledb` cursor execution.
- Note on test file: `src/py/tests/unit/data/test_oracle_driver.py` is modified after Task `2.1` (`depends_on: [db-mysql-and-oracle-drivers:2.1]`).
- Strategy `regression_tdd` applies because this task fixes the `ORA-01036` RRF bind mismatch, `B905` zip strictness, and `S105` hardcoded password while implementing live `oracledb` driver execution.
