# 3.2 Live KeyValueBackend and ChannelBus Redis/Valkey adapters

## Objective
Implement `KeyValueBackend` in `src/py/vertebra/framework/stores.py` and `ChannelBus` in `src/py/vertebra/framework/channels.py`, and upgrade `MemoryStore` (`src/py/vertebra/extensions/litestar/store.py`) and `ChannelsBackend` (`src/py/vertebra/extensions/litestar/channels.py`) so Redis/Valkey-backed stores delegate `delete_all`, `expires_in` (`PTTL`), and RESP3 client-side cache invalidations to the driver, and `ChannelsBackend` fans in remote Redis/Valkey pub/sub messages to local subscribers.

## Context
- `src/py/vertebra/extensions/litestar/store.py:59-122` (`MemoryStore`) keeps an unsynchronized local `self._entries` copy when `self._driver` is set, does not call `await self._driver.flushdb()` in `delete_all()` (`:101-103`), does not query `await self._driver.pttl(key)` in `expires_in()` (`:109-121`), and does not evict `self._entries` when `AsyncValkeyDriver` receives a RESP3 `invalidate` push frame.
- `src/py/vertebra/extensions/litestar/channels.py:66-123` (`ChannelsBackend`) publishes to `self._driver` (`:83`) but never subscribes to `self._driver` pub/sub channels or forwards remote messages into `self._queues`.
- `src/py/vertebra/framework/stores.py` and `src/py/vertebra/framework/channels.py` (flattened in `framework-consolidation:5.1`) lack the framework-native `KeyValueBackend` and `ChannelBus` adapters.
- Note on test file: `src/py/tests/unit/data/test_redis_valkey_driver.py` is modified after Task `3.1` (`depends_on: [db-redis-valkey-and-analytics:3.1]`), expanding `test_valkey_resp3_client_tracking_and_litestar_integration`.
- Strategy `behavior_tdd` applies because this task adds `KeyValueBackend`, `ChannelBus`, remote `PTTL`/`delete_all` delegation, and remote pub/sub fan-in.
