# 3.4 Unit and integration acceptance tests for RESP3 Redis/Valkey drivers, ChangeFeed Parquet spill, and DataFusionEngine

## Objective
Create and run integration tests in `src/py/tests/unit/data/test_redis_valkey_driver.py` and `src/py/tests/unit/data/test_pg_gateway.py` to verify end-to-end composition of the RESP3 TCP/TLS connection pools (`SyncRedisDriver`, `AsyncRedisDriver`, `SyncValkeyDriver`, `AsyncValkeyDriver`), `KeyValueBackend` and `ChannelBus`, `ChangeFeed` Parquet spill into `ObjectStore`, and `DataFusionEngine` vectorized SQL execution over spilled CDC Parquet datasets, including injected protocol and SQL security refusal states.

## Context
- Tasks `3.1`, `3.2`, and `3.3` implement the RESP3 wire parser and connection pool, `KeyValueBackend`/`ChannelBus` adapters, `ChangeFeed` `ObjectStore` Parquet spill, `QueryPipeline.execute`, and `DataFusionEngine` Arrow/Parquet SQL execution.
- Strategy `integration_acceptance` applies because this task verifies end-to-end composition across all Chapter 3 components plus negative refusal paths (corrupted RESP3 frames, `NOSCRIPT` errors, missing CDC spill objects, and SQL identifier injection attempts).

## Steps
- [ ] 1. Create tests in `src/py/tests/unit/data/test_redis_valkey_driver.py` and `src/py/tests/unit/data/test_pg_gateway.py` with the following integration and refusal acceptance tests:
  - `test_resp3_loopback_server_pipeline_evalsha_and_valkey_push_invalidation`: starts an `asyncio` loopback RESP3 server supporting `HELLO 3`, `CLIENT TRACKING ON`, `GET`, `SET`, `MGET`, `EVALSHA` (returning `-NOSCRIPT No matching script\r\n` on first call and caching on `EVAL`), `PUBLISH`, `SUBSCRIBE`, and interleaved `>2\r\n$10\r\ninvalidate\r\n*1\r\n$6\r\nuser:1\r\n` push frames; connects `AsyncValkeyDriver`, `KeyValueBackend`, and `ChannelBus` over loopback TCP, verifies pipelined `get_many`/`set_many`, `eval_script` `NOSCRIPT` recovery, automatic client-side cache eviction on push frame arrival, and remote pub/sub delivery through `ChannelBus.stream_events()`, and proves `Resp3Error` refusal when `-ERR unknown command` is injected.
  - `test_cdc_changefeed_parquet_spill_to_object_store_and_datafusion_arrow_query`: publishes small and `>7,500`-byte `ChangeEvent` payloads through `ChangeFeed(store=ObjectStore("memory://"))`, hydrates the spilled notification from `ObjectStore`, flushes the event log to `"cdc/events.parquet"` via `flush_to_parquet`, registers `"cdc/events.parquet"` in `DataFusionEngine` via `register_parquet_from_store`, executes an analytical SQL aggregation over the spilled events (`execute_dicts` and `stream_arrow_ipc`), decodes the resulting Arrow IPC stream with `pyarrow.ipc.open_stream`, and proves `KeyError` refusal when hydrating a deleted spill object.
  - `test_query_pipeline_and_rls_identifier_refusal_and_single_rtt_execution`: verifies `QueryPipeline` + `RelOverlay` + `TenantPredicate` single-RTT execution through `SyncPostgresDriver` and `AsyncPostgresDriver`, and proves `ValueError` refusal when unsafe identifiers (`"users; DROP TABLE secrets"`) or colliding CTE step parameter names are supplied.
- [ ] 2. Commit: `test(db): add RESP3 Redis/Valkey, ChangeFeed Parquet spill, and DataFusion acceptance suite` (signed), staging `src/py/tests/unit/data/test_redis_valkey_driver.py` and `src/py/tests/unit/data/test_pg_gateway.py`.

## Verification
- **Strategy:** `integration_acceptance` — composes the loopback RESP3 server, `AsyncValkeyDriver`, `KeyValueBackend`, `ChannelBus`, `ChangeFeed`, `ObjectStore`, `QueryPipeline`, and `DataFusionEngine`, and proves refusal on protocol errors, missing spill keys, and invalid SQL identifiers.
- **Initial evidence:** `uv run pytest src/py/tests/unit/data/test_redis_valkey_driver.py src/py/tests/unit/data/test_pg_gateway.py -q` → fails before the task.
- **Final evidence:** `uv run pytest src/py/tests/unit/data/test_redis_valkey_driver.py src/py/tests/unit/data/test_pg_gateway.py -q && uv run ruff check src/py/tests/unit/data/ && uv run mypy src/py/tests/unit/data/` → all exit 0.
- **Gate proof:** Injecting `-ERR syntax error\r\n` from the loopback RESP3 socket raises `Resp3Error: ERR syntax error`; deleting `"cdc/spill/2.json"` from `ObjectStore` before calling `ChangeFeed.hydrate_notification` raises `KeyError: 'Spilled CDC payload for event_id=2 is missing'`.

## Acceptance Criteria
- [ ] `src/py/tests/unit/data/test_redis_valkey_driver.py` and `src/py/tests/unit/data/test_pg_gateway.py` verify live loopback RESP3 handshakes, pipelining, `EVALSHA` -> `EVAL` fallback, Valkey push invalidation eviction, and `ChannelBus` pub/sub streaming.
- [ ] `ChangeFeed` -> `ObjectStore` Parquet spill -> `DataFusionEngine` Arrow IPC query pipeline is verified end-to-end.
- [ ] Protocol error (`Resp3Error`), missing spill object (`KeyError`), parameter collision (`ValueError`), and SQL identifier injection (`ValueError`) refusal paths are asserted.
- [ ] `make lint` exits 0; no new `# ` comments, nested imports, aliases, or private-module imports.
