# 3.1 Native RESP3 sync/async socket and TLS connection pool for RedisDriver and ValkeyDriver with pipelining, pub/sub, and Lua EVALSHA caching

## Objective
Implement a complete RESP3 wire protocol parser (`Resp3Parser`, `Resp3Error`) and pooled sync (`socket` / `ssl.SSLSocket`) and async (`asyncio.StreamReader` / `StreamWriter`) connections in `src/py/vertebra/db/redis.py` and `src/py/vertebra/db/valkey.py` supporting `HELLO 3`, `CLIENT TRACKING` push invalidations (`>`), pipelined batch execution (`execute_pipeline`), pub/sub channels (`subscribe` / `iter_pubsub`), and SHA-1 Lua script caching (`eval_script` trying `EVALSHA` first and falling back to `EVAL` on `NOSCRIPT`), while deduplicating `SyncValkeyDriver`/`AsyncValkeyDriver` onto `SyncRedisDriver`/`AsyncRedisDriver`.

## Context
- `src/py/vertebra/db/redis.py:38-141` and `src/py/vertebra/db/valkey.py:61-161` only mutate an in-memory `self._kv` dictionary and cannot parse RESP3 frames or open TCP/TLS sockets (`FW-02`).
- `src/py/vertebra/db/redis.py:69-85` (`SyncRedisDriver.encode_hello3_handshake`) accepts duplicate `auth_username`/`auth_password` and `username`/`password` parameters, and `valkey.py:61-161` duplicates `SyncRedisDriver` and `AsyncRedisDriver` (`FW-57`).
- Strategy `behavior_tdd` applies because this task introduces the RESP3 wire parser, TCP/TLS connection pool, pipelining, pub/sub, and `EVALSHA` script caching.

## Steps
- [x] 1. In `src/py/tests/unit/data/test_redis_valkey_driver.py:103-136`, add failing behavior tests `test_resp3_wire_parser_pipelining_evalsha_and_loopback_pool` verifying:
  - `Resp3Parser.parse_frame(buffer)` decodes RESP3 simple strings (`+OK\r\n`), bulk strings (`$5\r\nhello\r\n`), null (`_\r\n`), integers (`:42\r\n`), doubles (`,3.14\r\n`), booleans (`#t\r\n`), arrays (`*2\r\n...`), maps (`%1\r\n...`), push frames (`>2\r\n$10\r\ninvalidate\r\n*1\r\n$6\r\nuser:1\r\n`), and raises `Resp3Error` on `-ERR ...` / `-NOSCRIPT ...` frames.
  - `SyncRedisDriver.encode_hello3_handshake` accepts `*, username: str | None = None, password: str | None = None, client_name: str | None = "vertebra"` without `auth_username` or `auth_password`.
  - Against a local loopback RESP3 server socket (and in `memory://` test mode), `SyncRedisDriver` and `AsyncRedisDriver` execute `get`, `set(ex=...)`, `delete`, `pttl`, `flushdb`, `execute_pipeline`, `publish`, `subscribe`, and `eval_script(script, keys, args)` (computing `hashlib.sha1(script.encode()).hexdigest()`, sending `EVALSHA`, and retrying with `EVAL` when the server replies `-NOSCRIPT`).
  - `SyncValkeyDriver` and `AsyncValkeyDriver` subclass `SyncRedisDriver` and `AsyncRedisDriver`, intercept `>2\r\n$10\r\ninvalidate\r\n*1\r\n$6\r\nuser:1\r\n` push frames on the wire to evict `"user:1"` from `_client_cache` automatically, and invoke registered invalidation callbacks.
