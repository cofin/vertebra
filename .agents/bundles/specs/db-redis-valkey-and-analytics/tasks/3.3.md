# 3.3 Live ChangeFeed consumer with ObjectStore Parquet spill, QueryPipeline.execute, and DataFusionEngine vectorized Arrow SQL

## Objective
Add `vertebra[datafusion]` (`datafusion>=43.0`, `pyarrow>=18.0`) to `pyproject.toml`, upgrade `ChangeFeed` (`src/py/vertebra/db/cdc.py`) to bound its in-memory replay history, spill `>7,500`-byte notifications and WAL batches to `ObjectStore` Parquet/JSON objects, and raise `KeyError` on missing spilled payloads, harden `QueryPipeline` (`src/py/vertebra/db/pipeline.py`) and `TenantPredicate` (`src/py/vertebra/db/rls.py`) with strict SQL identifier validation, parameter collision checks, and `execute`/`execute_async` methods, and implement vectorized SQL execution over Arrow and Parquet tables in `DataFusionEngine` (`src/py/vertebra/db/datafusion.py`).

## Context
- `src/py/vertebra/db/cdc.py:44-118` (`ChangeFeed`) grows `self._history` without bound (`:47,99`), stores spilled payloads only in an in-process dict (`:45`), and silently returns `{}` when a spilled `event_id` is missing (`:107`, `FW-59`).
- `src/py/vertebra/db/pipeline.py:19-129` (`RelOverlay`, `CteStep`, `QueryPipeline`) does not validate SQL identifiers (`base_table`, `inserted_cte`, `deleted_ids_cte`, `id_column`, `CteStep.name`), accepts duplicate `chunk_size` and `max_pairs_per_call` parameters in `build_jsonb_object` (`:63-87`), silently overwrites colliding parameter keys across steps (`:115`), and lacks `execute` / `execute_async` (`FW-59`).
- `src/py/vertebra/db/rls.py:23-35` (`TenantPredicate`) does not validate `table_alias`, `tenant_column`, or `parameter_cast` identifiers (`FW-59`).
- `src/py/vertebra/db/datafusion.py:46-84` (`DataFusionEngine`) only returns a static dictionary from `explain_plan` and cannot execute SQL over Arrow or Parquet datasets (`FW-10`).
- Strategy `behavior_tdd` applies because this task adds `ObjectStore` Parquet spill on `ChangeFeed`, `QueryPipeline.execute`, and vectorized `DataFusionEngine` execution while enforcing `FW-59` bounds and identifier checks.
