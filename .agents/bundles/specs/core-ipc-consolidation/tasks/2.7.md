# 2.7 Batch bridge without blocking under lock

## Objective
Eliminate lock-across-send stalls and per-header allocations in `BatchBridge` (`src/rs/vertebra-core/src/bridge.rs`): move `DataSlab` and `TransportArena` inside `Mutex<BatchAccum>` so `BatchWriter` mutates them via `&mut` without per-field `AtomicUsize::fetch_add`, use `try_send` after releasing the mutex (`CORE-27`), remove redundant `BatchBridge` wrapper methods (`CORE-28`), store `headers_raw: Bytes` on `BridgeResponse`, and replace `resp_rx: tokio::sync::Mutex<Receiver<...>>` with a one-time `take_response_receiver()` handoff (`CORE-29`).

## Context
- `src/rs/vertebra-core/src/bridge.rs:143-227`: `BatchWriter` holds `write_lock: MutexGuard<'_, ()>` across `self.bridge.batch_tx.send(snapshot)`, which blocks the calling Tokio worker thread when `batch_tx` is full (`CORE-27`). Meanwhile `DataSlab::write` and `TransportArena::push` use `AtomicUsize::fetch_add(Ordering::AcqRel)` and `UnsafeCell` even though `write_lock` already serializes writers (`CORE-27`).
- `bridge.rs:94-107,151-158,188-193,267-289`: `init_with_codec`, `push_request`, `seal_batch`, `submit_responses_async`, and `try_recv_responses` are unused or test-only wrappers (`CORE-28`).
- `bridge.rs:21-26,76,278-281`: `BridgeResponse.headers` is `Vec<(Vec<u8>, Vec<u8>)>` (two heap allocations per header), and `recv_responses().await` locks a `tokio::sync::Mutex` around `resp_rx` even though `vertebra-http/src/main.rs:87` is its single consumer (`CORE-29`).
- `characterization` + performance gate applies because this task optimizes in-process bridge contention and allocations while preserving bridge dispatch semantics.

## Steps
- [x] 1. Refactor `DataSlab` and `TransportArena` in `src/rs/vertebra-core/src/transport/batch.rs` to take `&mut self` (plain `usize` cursor, no `UnsafeCell` or `unsafe impl Sync`), and wrap them in `Mutex<BatchAccum>` inside `BatchBridge` (`src/rs/vertebra-core/src/bridge.rs`) (`CORE-27`).
- [x] 2. Update `BatchWriter::seal(mut self) -> Result<usize, TransportError>` in `src/rs/vertebra-core/src/bridge.rs` to extract the `Arc<BatchSnapshot>` while holding the `Mutex<BatchAccum>` guard, drop the guard immediately, and call `self.bridge.batch_tx.try_send(snapshot).map_err(|_| TransportError::RingFull)` (`CORE-27`).
- [x] 3. Remove `init_with_codec` (pass `BridgeConfig` to `init`), `push_request`, `seal_batch`, `submit_responses_async`, and `try_recv_responses` from `BatchBridge`, and replace the `let _ = slab_data;` hack in `try_compress_slab` with clean `#[cfg(feature = "compression")]` / `#[cfg(not(feature = "compression"))]` functions (`CORE-28`).
- [x] 4. Change `BridgeResponse.headers` (`src/rs/vertebra-core/src/bridge.rs:21-26`) from `Vec<(Vec<u8>, Vec<u8>)>` to `headers_raw: Bytes` encoded via `RawHeaders`, replace `resp_rx: tokio::sync::Mutex<Receiver<Vec<BridgeResponse>>>` with `resp_rx: std::sync::Mutex<Option<Receiver<Vec<BridgeResponse>>>>` and `pub fn take_response_receiver(&self) -> Option<Receiver<Vec<BridgeResponse>>>`, and update `src/rs/vertebra-http/src/main.rs`, `src/rs/vertebra-http/src/dispatcher/bridge.rs`, and `src/rs/vertebra-py/src/api.rs` (`CORE-29`).
- [x] 5. Add unit test `bridge_seal_returns_ring_full_without_blocking_when_channel_saturated` in `src/rs/vertebra-core/src/bridge.rs`.
- [x] 6. Commit: `perf(bridge): drop lock before try_send, use RawHeaders Bytes, and hand off response receiver` (signed), staging the paths in `files`.
