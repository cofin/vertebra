# 2.5 One response wire format

## Objective
Unify SHM response framing on a single zero-copy wire format (`ResponseSlot` / `ResponseSlotView<'a>` in `protocol/response.rs` with compact `RawHeaders<'a>` in `transport/headers.rs` and typed `RequestFlags`/`FrameFlags` in `protocol/flags.rs`), deleting VRES `ResponseData` (`CORE-03`, `CORE-17`, `CORE-18`, `CORE-19`, `CORE-42`, `HTTP-09`) and updating `vertebra-http` and `vertebra-py` so every SHM response uses the same frame codec.

## Context
- `TieredRingSet` currently carries two incompatible wire formats: VRES `ResponseData` (`ring_pair.rs:31-77`) and `ResponseSlot` (`ipc.rs:24-170`). `vertebra-http/src/response_reader.rs:271` only calls `try_recv_response()`, which rejects `ResponseSlot` frames with `"bad magic"` (`CORE-03`).
- `ipc.rs:3-8` and `protocol/mod.rs:153-184` define two conflicting flag bit spaces (`CORE-17`).
- `ResponseSlot::decode_from` (`ipc.rs:126-170`) allocates two `String`s per header plus a `Vec<u8>` body (`CORE-18`), and `ResponseData::deserialize` (`ring_pair.rs:64-69`) copies headers and body out of the ring twice (`CORE-19`).
- `encode_headers_compact` (`transport/mod.rs:931-955`) silently truncates header names `> 255` bytes and values `> 65535` bytes (`CORE-42`), and `vertebra-http/src/dispatcher/shm.rs:226` duplicates the header encoding loop (`HTTP-09`).
- `regression_tdd` applies because sending a `ResponseSlot` frame through `RingPair` into `vertebra-http`'s response reader currently fails with `"bad magic"`.

## Steps
- [x] 1. Create `src/rs/vertebra-core/src/transport/headers.rs` defining `RawHeaders<'a>(&'a [u8])`, `HeaderEncodeError`, `encode_headers_into`, and `encode_headers` that validate `name.len() <= u8::MAX` and `value.len() <= u16::MAX` instead of truncating (`CORE-42`), and replace the duplicate loop in `src/rs/vertebra-http/src/dispatcher/shm.rs:220-238` with `headers::encode_headers_into` (`HTTP-09`).
- [x] 2. Create `src/rs/vertebra-core/src/protocol/flags.rs` with `RequestFlags(u32)` (`PRIORITY`, `COMPRESSED`, `CODEC_LZ4`, `CODEC_ZSTD`, `FIRE_AND_FORGET`) and `FrameFlags(u16)` (`STREAMING = 1 << 0`, `FINAL = 1 << 1`, `ERROR = 1 << 2`, `HEADERS_SENT = 1 << 4`, `TRAILERS = 1 << 5`), deleting the duplicate constants from `protocol/mod.rs` and `ipc.rs` (`CORE-17`).
- [x] 3. Move `src/rs/vertebra-core/src/ipc.rs` to `src/rs/vertebra-core/src/protocol/response.rs`, replacing owned `(String, String)` header encoding/decoding with `ResponseSlot::write_into(dst, request_id, status, flags: FrameFlags, headers: RawHeaders<'_>, body: &[u8])` and zero-copy `ResponseSlotView::decode(src: &'a [u8]) -> Result<ResponseSlotView<'a>, ResponseDecodeError>` borrowing `headers: RawHeaders<'a>` and `body: &'a [u8]` directly from the slot slice (`CORE-18`).
- [x] 4. In `src/rs/vertebra-core/src/transport/ring_pair.rs`: delete `ResponseData`, `RESPONSE_MAGIC`, and `write_response_slot` (`CORE-03`, `CORE-19`); update `TieredRingSet::send_response` and `try_recv_response_with<F, R>(&self, f: F)` to write and borrow `ResponseSlotView<'_>` directly over the `SpscRing` slot without intermediate `Bytes::copy_from_slice`.
- [x] 5. Update `src/rs/vertebra-http/src/response_reader.rs:265-305` and `src/rs/vertebra-http/src/dispatcher/shm.rs:250-320` to decode `ResponseSlotView<'_>` inside `try_recv_response_with` and copy the body slice into `Bytes` once, and update `src/rs/vertebra-py/src/api.rs` so `submit_response` and `submit_raw_response` both encode `ResponseSlot` via `RawHeaders` (`CORE-03`).
