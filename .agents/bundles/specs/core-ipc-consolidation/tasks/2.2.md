# 2.2 Remove dead core modules and dependencies

## Objective
Remove ~2,200 lines of unused code and UB-prone types from `vertebra-core` (`BufferPool`, `BufferChannel`, `SharedMutex`/`SharedRwLock`/`SharedCondvar`/`SpinLock`/`FileLock`, `guards.rs`, `protocol/state.rs`, `cleanup.rs`, `router::Router`, `Opcode`, dead protocol header structs, bench-only `Notifier` spin helpers, and root re-exports), while retaining `WaitWord` in `sync.rs` (to be moved to `platform/mod.rs` in Task 2.4) and retaining `ShmRegion::create_named` and `ShmRegion::open_named` in `src/rs/vertebra-core/src/shm.rs` (used by `shm-broker-lease-table`), move `normalize_typed_path` to `vertebra-http/src/router.rs`, make `sync::wait_on_address` use the sleep fallback on unsupported platforms, and remove unused Cargo dependencies and dead benchmarks.

## Context
- `BufferPool` (`src/rs/vertebra-core/src/buffer.rs:90-240`) creates aliasing `&mut Vec<u8>` references across live `Buffer` handles (UB under Stacked Borrows, `CORE-05`) and carries a no-op `release_multi` and `BufferHandle` alias (`CORE-43`); its only non-test consumer is the dead `BufferChannel` (`channel.rs:1017-1271`, `CORE-12`).
- `sync.rs:30-97,133-170,236-610` defines `FileLock`, `WaitWord`, `SharedMutex`, `SharedRwLock`, `SharedCondvar`, and `SpinLock` (`CORE-11`), while `wait_on_address` (`:172-187`) returns `Err(SyncError::Unsupported)` instead of calling `fallback_wait_timeout` when fallback mode is active (`CORE-06`). `WaitWord` is retained (to be folded into `platform/mod.rs` in Task 2.4) for `shm-broker-lease-table` cross-worker coordination, while `FileLock`, `SharedMutex`, `SharedRwLock`, `SharedCondvar`, and `SpinLock` are deleted.
- `guards.rs` (169 lines), `protocol/state.rs` (530 lines), `cleanup.rs` (106 lines, never populated by `create_named`, `CORE-14`), `router::Router` (`router.rs:1-76`), `Opcode` (`ipc.rs:178-222`, `CORE-16`), and `protocol::{RequestHeader, ResponseHeader, ControlMessageKind}` (`protocol/mod.rs:24-150`, `CORE-13`) have zero production callers. Per Decision D4, `logger.rs` and `telemetry.rs` are kept for Chapter 4 Task 4.10.
- `characterization` applies because all live workspace behavior is preserved while deleting dead modules, dependencies, and duplicate tests/benches.
