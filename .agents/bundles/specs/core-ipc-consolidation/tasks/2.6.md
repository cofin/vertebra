# 2.6 Transport batch and tiered ring cleanup

## Objective
Extract batch serialization and buffer pooling from `transport/mod.rs` into `transport/batch.rs` (`BatchHeader`, single `BatchSnapshot::new`, `BatchBufferPool` used during SHM deserialization, and `impl From<RingPairError> for TransportError`) (`CORE-20` pooling part, `CORE-21..24`), and fold `tiered_ring.rs` into `transport/ring_pair.rs` using `[Arc<SpscRing>; 4]` and `[RingTier; 4]` arrays with round-robin fair draining across tiers (`CORE-25`, `CORE-26`).

## Context
- `src/rs/vertebra-core/src/transport/mod.rs:741-890` writes the 16-byte batch wire header in two places and shadows `const BATCH_HEADER_SIZE: usize = 16` (`CORE-21`), defines 4 near-identical `BatchSnapshot::new*` constructors (`CORE-22`), writes out `RingPairError` -> `TransportError` mapping 3 times (`CORE-23`), names its vec-pair recycler `BufferPool` (`CORE-24`), and allocates fresh `Vec`s in `BatchSnapshot::deserialize_from` instead of pulling from the pool (`CORE-20`).
- `src/rs/vertebra-core/src/tiered_ring.rs` and `transport/ring_pair.rs` spell out `small`, `medium`, `large`, `xlarge` across 7 structs/functions (`CORE-25`), and `TieredRingSet` always scans `small -> xlarge` from index 0, starving larger tiers under continuous small-response traffic (`CORE-26`).
- `characterization` + performance gate applies because this task consolidates transport and tiered-ring internals while adding a fairness test for round-robin tier draining.

## Steps
- [x] 1. Create `src/rs/vertebra-core/src/transport/batch.rs` containing `TransportNode`, `DataSlab`, `TransportArena`, `BatchBufferPool` (renamed from `BufferPool`, `CORE-24`), `BatchHeader { flags, node_count, slab_len }` (`write_to`/`read_from`, `CORE-21`), `BatchSnapshot::new(slab, nodes, flags, pool: Option<Arc<BatchBufferPool>>)` (`CORE-22`), `BatchSnapshot::deserialize_from_pooled` (reusing `BatchBufferPool` buffers and returning `Result<&[u8], TransportError>` from `slab_bytes` instead of `.expect()`, `CORE-20`), and `ShmBatchWriter`.
- [x] 2. Implement `From<RingPairError> for TransportError` in `src/rs/vertebra-core/src/transport/mod.rs` and replace the three manual `.map_err` blocks with `?` (`CORE-23`).
- [x] 3. Fold `src/rs/vertebra-core/src/tiered_ring.rs` into `src/rs/vertebra-core/src/transport/ring_pair.rs`, delete `tiered_ring.rs`, and represent the 4 response tiers as `pub const RESPONSE_TIERS: usize = 4`, `tiers: [RingTier; RESPONSE_TIERS]`, `rings: [Arc<SpscRing>; RESPONSE_TIERS]`, and `RingPairFds { request_fd: RawFd, response_fds: [RawFd; RESPONSE_TIERS], req_notify_fd: RawFd, resp_notify_fd: RawFd }` with `to_env_vars` / `from_env` driven by `const TIER_ENV_NAMES: [&str; 4]` (`CORE-25`).
- [x] 4. Add `next_tier: AtomicUsize` (or `Cell<u8>` on single-threaded readers) to `TieredRingSet` so `try_recv_response_with` rotates the starting tier index on each poll (`(start + offset) % RESPONSE_TIERS`), preventing tier 0 from starving tiers 1..3 (`CORE-26`), and add unit test `tiered_ring_set_fair_drain_rotates_across_tiers` in `ring_pair.rs`.
- [x] 5. Update `vertebra-http/src/ring_factory.rs`, `vertebra-core/benches/shm_transport.rs`, and `.agents/skills/review-core/references/areas.toml` for the removal of `tiered_ring.rs`.
- [x] 6. Commit: `refactor(core): split transport/batch.rs and fold tiered rings into array with fair drain` (signed), staging the paths in `files`.
