# Task 1.1: Wire two-phase Rust PGO pipeline, multi-extension CARGO_TARGET_DIR builds, and tools/pgo lint gates

## Objective

Implement an end-to-end two-phase Rust Profile-Guided Optimization (PGO) pipeline across `vertebra-http` (`vertebra-server`) and all three PyO3 extension crates (`vertebra-py`, `vertebra-bundler`, `vertebra-storage`), honoring `CARGO_TARGET_DIR`, validating merged `.profdata` via `validate_profdata`, deduplicating `tools/pgo/rust_pgo.py` against `vertebra.build.packaging.pgo` with a proper `python -m tools.pgo.rust_pgo` CLI, ignoring `.profiles/` and `*.profraw`/`*.profdata` artifacts, and enforcing `ruff` and `mypy --strict` across `tools/pgo`.

## Context

- `src/py/vertebra/build/packaging/pgo.py` and `tools/pgo/rust_pgo.py` currently duplicate 250 lines of Rust PGO helpers, hardcode `config.manifest_path.parent.parent / "target" / "release"` (ignoring `CARGO_TARGET_DIR=/tmp/vtb-cargo-target` exported in `Makefile:26`), only build `_vertebra` via `maturin develop` (omitting `vertebra-bundler` and `vertebra-storage`), and only check `profdata_path.exists()` rather than running `validate_profdata(profdata_path)`.
- `src/rs/vertebra-bundler/pyproject.toml` and `src/rs/vertebra-storage/pyproject.toml` define `[tool.maturin]` locally (requiring `-m <manifest>`), whereas `src/rs/vertebra-py` relies on the repository-root `pyproject.toml` `[tool.maturin]` (omitting `-m` when running from repository root so `module-name = "vertebra._vertebra"` is preserved).
- `pgo.py:255` defines a top-level symbol alias `resolve_llvm_profdata = find_llvm_profdata` with zero external callers; remove the alias and export canonical `find_llvm_profdata` from `vertebra.build.packaging`.
- Keep `tools/pgo/python_pgo.py` self-contained with its `_query_sysconfig`, `_query_version`, and `sys` attributes so existing monkeypatch tests in `test_packaging_and_pgo.py:192-196` remain valid.

## Steps

1. Add failing behavioral unit tests in `src/py/tests/unit/build/test_packaging_and_pgo.py` covering:
   - `resolve_cargo_release_dir` honoring absolute and relative `CARGO_TARGET_DIR` environment overrides and falling back to `src/rs/target/release` when unset.
   - `EXTENSION_MANIFESTS` (`vertebra-py`, `vertebra-bundler`, `vertebra-storage`) and `build_instrumented_extensions` / `build_optimized_extensions` invoking `maturin develop` without `-m` for `vertebra-py` (reading root `pyproject.toml`) and with `-m <manifest>` for `vertebra-bundler` and `vertebra-storage`.
   - `build_optimized` and `build_optimized_extension` validating `.profdata` via `validate_profdata` and falling back to a clean release build without `-Cprofile-use` when `.profdata` fails validation or `llvm-profdata` is absent.
   - `run_pgo_pipeline` (`PgoPipelineResult`) executing Phase 1 instrumentation, running the training workload with `LLVM_PROFILE_FILE`, merging and validating `.profdata` (including `baseline_profdata` weighted merge and `use_existing_profdata=True` fast-path), and executing Phase 2 `-Cprofile-use` builds, plus `tools.pgo.rust_pgo.main` CLI option handling and a live `llvm-profdata` merge/validate check when `find_llvm_profdata()` is available.
2. Run `uv run pytest src/py/tests/unit/build/test_packaging_and_pgo.py -q` and confirm the new tests fail because the pipeline symbols and behaviors are absent.
3. Update `src/py/vertebra/build/packaging/pgo.py` and `src/py/vertebra/build/packaging/__init__.py`:
   - Remove `resolve_llvm_profdata = find_llvm_profdata` and export `find_llvm_profdata`, `EXTENSION_MANIFESTS`, `PgoPipelineResult`, `resolve_cargo_release_dir`, `build_instrumented_extensions`, `build_optimized_extensions`, `run_default_pgo_workload`, and `run_pgo_pipeline`.
   - Update `RustPgoConfig` (`maturin_features: str = "extension-module"`, `extension_manifests: tuple[Path, ...] = EXTENSION_MANIFESTS`, and `use_rustflags`).
   - Make `validate_profdata` return `False` on missing, empty, corrupt, or missing-binary conditions without raising uncaught `FileNotFoundError`.
