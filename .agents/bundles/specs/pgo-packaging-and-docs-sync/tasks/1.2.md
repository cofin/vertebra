# Task 1.2: Add Python 3.15/3.15t and musl packaging targets, PGO/binary staging, and SQLAlchemy dialect entry points

## Objective

Extend `BuildTarget`, `StandaloneBuilder`, `OnefileBuilder`, `vtb build`, and `pyproject.toml` so Python `3.15` / `3.15t` and Linux `musl` targets resolve and validate cleanly, PGO `.profdata` metadata and compiled `vertebra-server` binaries stage into standalone and onefile distributions, `OnefileBuilder` carries zero compatibility aliases, and all 12 `[project.entry-points."sqlalchemy.dialects"]` entries resolve to the canonical `*Dialect` classes.

## Context

- `src/py/vertebra/build/packaging/targets.py` currently lists only `3.12`, `3.13`, `3.14`, and `3.14t` in `_PATCH_VERSIONS`, lacks `linux-x86_64-musl` / `linux-aarch64-musl` in `KNOWN_TARGETS`, and does not reject unsupported `python_version` values.
- `src/py/vertebra/build/packaging/standalone.py` records only `python_pgo_enabled`, `python_lto_enabled`, and `-Cprofile-generate` `rustflags` when `pgo_enabled=True`, without recording `PythonBuildInfo` (`python_build`), `.profdata` digest/validation/`-Cprofile-use` metadata, or staging a compiled `vertebra-server` binary into `bin/`.
- `src/py/vertebra/build/packaging/onefile.py:80` contains an unused `extract_archive = extract_to` symbol alias.
- `pyproject.toml:22-30` `[project.entry-points."sqlalchemy.dialects"]` still references removed `*VtbDialect` names (`PostgresVtbDialect`, `OracleVtbDialect`, `MysqlVtbDialect`, `SqliteVtbDialect`) and omits `mssql.{vertebra,vtb}` (`MssqlDialect`) and `duckdb.{vertebra,vtb}` (`DuckdbDialect`).

## Steps

1. Add failing behavioral unit tests in `src/py/tests/unit/build/test_packaging_and_pgo.py` covering:
   - `SUPPORTED_PYTHON_VERSIONS` (`"3.12"`, `"3.13"`, `"3.14"`, `"3.14t"`, `"3.15"`, `"3.15t"`), `BuildTarget.resolve` for `"3.15"`, `"3.15t"`, `"linux-x86_64-musl"`, and `"linux-aarch64-musl"`, and `ValueError` on unsupported Python versions (e.g. `"3.11"`).
   - `StandaloneBuilder` with `pgo_enabled=True`, `profdata_path`, and `server_binary` staging `bin/vertebra-server` (`0o755`), recording `python_build`, `pgo_mode`, `profdata_bytes`, `profdata_sha256`, `profdata_valid`, and `rustflags` in `manifest.json`, configuring `VERTEBRA_SERVER_BINARY` in `__main__.py`, and round-tripping through `OnefileBuilder`.
   - `vtb build` CLI supporting `--python-version 3.15t`, `--profdata <path>`, `--server-binary <path>`, and converting invalid `--python-version` values into `ClickException` across both standalone and `--target backend` invocations.
   - Parsing `pyproject.toml` `[project.entry-points."sqlalchemy.dialects"]` via `tomllib` and resolving every registered `module:attr` target (all 12 entries across `postgresql`, `oracle`, `mysql`, `sqlite`, `mssql`, `duckdb` for `.vertebra` and `.vtb`) against `vertebra.extensions.sqlalchemy.dialects`.
2. Run `uv run pytest src/py/tests/unit/build/test_packaging_and_pgo.py -q` and confirm the new tests fail.
3. Update `src/py/vertebra/build/packaging/targets.py` and `src/py/vertebra/build/packaging/__init__.py` to export `SUPPORTED_PYTHON_VERSIONS`, add `3.15` / `3.15t` patch versions and `musl` / alias triples to `KNOWN_TARGETS`, and validate `python_version` in `detect_host` and `resolve`.
4. Update `src/py/vertebra/build/packaging/standalone.py` to accept `profdata_path: Path | None = None` and `server_binary: Path | None = None`, stage `bin/<server_binary.name>` (`0o755`), populate `VERTEBRA_SERVER_BINARY` in `_render_bootstrap()`, and record `PythonBuildInfo` (`python_build`) and `.profdata` metadata when `pgo_enabled` is enabled.
5. Remove `extract_archive = extract_to` from `src/py/vertebra/build/packaging/onefile.py`.
6. Update `src/py/vertebra/cli/build.py` to add `--profdata` and `--server-binary`, update `--python-version` help text for `3.15` / `3.15t`, and catch `ValueError` consistently across all target branches.
7. Update `pyproject.toml` `[project.entry-points."sqlalchemy.dialects"]` to map all 12 `.vertebra` and `.vtb` entries to `{Postgres,Oracle,Mysql,Sqlite,Mssql,Duckdb}Dialect`.
8. Run `uv run pytest src/py/tests/unit/build/test_packaging_and_pgo.py -q` and `make lint-all` and confirm green.
