# Learnings — `pgo-packaging-and-docs-sync`

- **PyO3 Multi-Extension Maturin Layout (`pyproject.toml` vs Crate-Local `pyproject.toml`)**: `src/rs/vertebra-bundler/pyproject.toml` and `src/rs/vertebra-storage/pyproject.toml` configure `module-name` locally (requiring `-m <manifest>`), whereas `src/rs/vertebra-py` relies on the repository-root `pyproject.toml` (`[tool.maturin] module-name = "vertebra._vertebra"`, `python-source = "src/py"`), so `maturin develop` for `vertebra-py` must run from the repository root without `-m src/rs/vertebra-py/Cargo.toml`.
- **Task 1.1 (`23d0be5`) — Two-Phase Rust PGO Pipeline & `tools/pgo` Lint Gates**: Deduplicated `tools/pgo/rust_pgo.py` onto `vertebra.build.packaging.pgo` with `python -m tools.pgo.rust_pgo` (`make build-pgo`), fixed `_REPO_ROOT` depth (`parents[5]`) in `pgo.py`, added `resolve_cargo_release_dir` (`CARGO_TARGET_DIR`) and single-pass `validate_profdata` before `-Cprofile-use` across `vertebra-http` and all three PyO3 extensions (`EXTENSION_MANIFESTS`), removed `resolve_llvm_profdata = find_llvm_profdata`, and added `tools/pgo` (`tools/pgo/__init__.py`) to `Makefile` `ruff`/`mypy` gates and `pyproject.toml`.
- **Task 1.2 (`774d920`) — Python `3.15`/`3.15t` & `musl` Packaging, PGO/Binary Staging & Dialect Entry Points**: Added `SUPPORTED_PYTHON_VERSIONS` (`3.12`–`3.15`, `3.14t`, `3.15t`) validation and `linux-x86_64-musl` / `linux-aarch64-musl` targets to `BuildTarget`, wired `--entrypoint`, `--profdata`, and `--server-binary` (`bin/<name>`, `VERTEBRA_SERVER_BINARY` bootstrap, `python_build` and `.profdata` SHA-256/validation metadata) into `StandaloneBuilder` and `vtb build`, removed `OnefileBuilder.extract_archive = extract_to`, and aligned all 12 `pyproject.toml` `[project.entry-points."sqlalchemy.dialects"]` entries to `{Postgres,Oracle,Mysql,Sqlite,Mssql,Duckdb}Dialect`.
- **Task 2.1 (`2dffe05`) — `AGENTS.md` & OKF v0.2 Documentation Precision Sync**: Updated `AGENTS.md` and 10 OKF v0.2 bundle chapters (`product-guidelines.md`, `tech-stack.md`, `workflow.md`, `packaging-and-pgo.md`, `cli.md`, `platform-and-lifecycle.md`, `hot-path-and-async-dispatch.md`, `pyo3-and-python-runtime.md`, `benchmarks-and-free-threaded.md`, `polyglot-test-matrix.md`) to match exact source symbols (`sync_native`, `state.health_endpoint.try_intercept(req_path)`, `drive_asgi_batch(single_root_asgi.dispatch_app, batch, ...)`, `Cargo.toml` `[profile.release]`) and the two-phase PGO / Python 3.15 packaging workflow.
- **Review Remediation — Default PGO Workload & Standalone Server Bootstrap**: `vertebra-server` reads `VERTEBRA_APP` (not `VERTEBRA_APP_MODULE`), `Headers` constructs via `Headers.from_pairs(...)`, and `Request`/`Response` import from `vertebra._vertebra`; capturing `vertebra-server` `stderr` to a temp file and polling `proc.poll()` inside `_wait_for_http_ready` avoids both pipe-buffer deadlocks and 15-second blind startup hangs. In `StandaloneBuilder._render_bootstrap`, checking zero required positional parameters (`inspect.signature`, excluding async/ASGI/RSGI callables) cleanly separates zero-arg CLI entrypoints from `App`/ASGI/RSGI/WSGI targets that launch `VERTEBRA_SERVER_BINARY` with `VERTEBRA_APP=<entrypoint>`.
