# 1.4 Concurrency, visibility-timeout recovery, cron leader-election, and DLQ tests across all queue backends

## Objective
Create `src/py/tests/unit/framework/test_distributed_queues.py` to verify concurrency safety, visibility-timeout crash recovery, delayed ZSET/SQL schedule promotion, dead-letter queue routing and replay, distributed cron leader election and failover, `MultiLaneWorkerRunner` `SIGTERM` lame-duck draining, and OpenTelemetry `messaging.*` span propagation across `MemoryQueueBackend`, `RedisQueueBackend`, `ValkeyQueueBackend`, `PostgresQueueBackend`, and `OracleQueueBackend`.

## Context
- Tasks `1.1`–`1.3` implement `MemoryQueueBackend`, `RedisQueueBackend`, `ValkeyQueueBackend`, `PostgresQueueBackend`, `OracleQueueBackend`, `CronScheduler`, and `MultiLaneWorkerRunner`.
- Strong tests must exercise observable behavior across all four backend families:
  1. Multi-consumer concurrent `dequeue` never delivers the same in-flight task to two active workers simultaneously (`XREADGROUP` consumer group partitioning on Redis/Valkey; `FOR UPDATE SKIP LOCKED` row locking on Postgres and Oracle).
  2. When a worker claims a message and crashes without calling `ack`, a second worker reclaims the message once `visibility_timeout_seconds` elapses (`XAUTOCLAIM` on Redis/Valkey; `locked_until <= now` on Postgres and Oracle) with `attempt` incremented.
  3. Tasks enqueued with `delay_seconds > 0` are not returned by `dequeue` before `scheduled_at`, and are atomically promoted once `now >= scheduled_at`.
  4. Failing tasks retry with exponential backoff up to `max_retries`, then move into the dead-letter queue (`list_dlq`) and can be re-enqueued via `replay_dlq(dlq_id)`.
  5. Three concurrent `CronScheduler` instances sharing a backend elect a single leader per minute slot; if the leader's lease expires before the next minute, a standby node acquires the lease and dispatches the next slot without duplicate execution.
  6. `MultiLaneWorkerRunner` transitions `LameDuckController` to `503` (`is_lame_duck is True`), finishes in-flight tasks before closing the backend, and exports `messaging.process` spans with parent `traceparent` continuity.
- `behavior_tdd` applies because each test verifies a concrete behavioral contract of the distributed queue and worker subsystem.

## Steps
- [ ] 1. Create `src/py/tests/unit/framework/test_distributed_queues.py` with parametrized and backend-specific test functions:
  - `test_queue_backends_fifo_and_lane_isolation`: parametrized across `memory://`, `redis://localhost:6379/0`, `valkey://localhost:6379/0`, `postgresql://localhost:5432/vtb`, and `oracle://localhost:1521/FREEPDB1`, verifying `enqueue`, `dequeue` per lane (`cpu`, `io`, `agent`), and `ack`.
  - `test_queue_backends_concurrent_workers_no_duplicate_delivery`: runs 4 concurrent worker coroutines pulling 40 tasks across `RedisQueueBackend`, `ValkeyQueueBackend`, `PostgresQueueBackend`, and `OracleQueueBackend`, asserting each `task_id` is processed exactly once.
  - `test_queue_backends_visibility_timeout_reclaims_unacked_tasks`: worker A dequeues a task with `visibility_timeout_seconds=0.05` and abandons it without `ack`; after `0.06s`, worker B calls `dequeue`, reclaims the task (`XAUTOCLAIM` / expired `locked_until`), processes it, and calls `ack`.
  - `test_queue_backends_delayed_schedule_promotion`: enqueues a task with `delay_seconds=10.0`, verifies `dequeue` returns `[]` at `t=0`, advances clock to `t=11.0`, runs `promote_scheduled(now=t+11.0)`, and verifies `dequeue` returns the promoted envelope.
  - `test_queue_backends_retry_backoff_and_dlq_replay`: registers a `@task(retry_policy=TaskRetryPolicy(max_retries=2, initial_backoff_seconds=0.01))` that raises `RuntimeError("boom")` on the first 2 attempts; verifies `nack` reschedules attempt 1, routes attempt 2 to DLQ (`len(await backend.list_dlq()) == 1`), and `replay_dlq(entry.dlq_id)` re-enqueues the task with `attempt == 1` so it succeeds when the handler recovers.
  - `test_postgres_listen_notify_zero_poll_wakeup_uses_direct_dsn`: configures `PostgresConfig(dsn="postgresql://pooler:6432/db", direct_dsn="postgresql://primary:5432/db", pooler_mode="transaction")`, verifies `PostgresQueueBackend` binds `LISTEN vertebra_queue_wakeup` to `direct_dsn` (`postgresql://primary:5432/db`), and wakes a waiting `dequeue(timeout_seconds=2.0)` within `< 50ms` upon `enqueue`.
  - `test_distributed_cron_scheduler_leader_election_and_failover`: starts 3 `CronScheduler` instances (`node-1`, `node-2`, `node-3`) against the same backend with a `* * * * *` task in `America/New_York`; verifies all 3 calling `tick(now=t0)` result in exactly 1 enqueued task for slot `t0`, and when `node-1` stops renewing its lease past `lease_ttl_seconds`, `node-2` acquires leadership at `t1` and enqueues the `t1` task.
  - `test_multi_lane_worker_runner_lame_duck_drain_and_otel_spans`: starts a `TraceContext`, enqueues jobs on `cpu`, `io`, and `agent` lanes, runs `MultiLaneWorkerRunner` with `LameDuckController` and `SpanExporter`, triggers `enter_lame_duck()` + `stop()` while a job is in flight, and asserts `lame_duck.readiness_status()[0] == 503`, the in-flight job completes and is `ack`ed before shutdown returns, and `span_exporter.drain_spans()` contains a `messaging.process` span sharing the parent `trace_id`.
