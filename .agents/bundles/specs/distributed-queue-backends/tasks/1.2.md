# 1.2 PostgresQueueBackend and OracleQueueBackend with SKIP LOCKED and LISTEN/NOTIFY

## Objective
Implement `PostgresQueueBackend` (`src/py/vertebra/framework/queues/postgres.py`) using `SELECT ... FOR UPDATE SKIP LOCKED`, zero-poll `LISTEN/NOTIFY` wakeups over `PostgresConfig.effective_direct_dsn` with adaptive `MIN(scheduled_at)` timeout clamping, exponential retry backoff, and a dead-letter table (`vertebra_queue_dlq`), and implement `OracleQueueBackend` (`src/py/vertebra/framework/queues/oracle.py`) using `SELECT ... FOR UPDATE SKIP LOCKED` cursor locking, transactional retry/DLQ transitions, and `MERGE INTO vertebra_queue_leases` leader election.

## Context
- `src/py/vertebra/db/postgres.py:23-63`: `PostgresConfig.effective_direct_dsn` (`:59-62`) provides the direct primary connection string required for `LISTEN/NOTIFY` when the main application pool uses transaction-mode PgBouncer/PgCat/pgdog (`PoolerMode = "transaction"` at `:20`, Decision D2).
- When a task is enqueued with a future `scheduled_at` (or rescheduled on retry), `pg_notify` fires immediately at enqueue time; a worker waking on that notification sees `0` due rows (`scheduled_at <= now`). Without adaptive timeout clamping, the worker would sleep for the full fallback `poll_interval_seconds`. Querying `SELECT MIN(scheduled_at) FROM vertebra_queue_jobs WHERE status = 'pending' AND scheduled_at > $1` and clamping the wait timeout to `min(timeout_seconds, max(0.05, earliest_due - now))` guarantees prompt execution of delayed continuation tasks.
- `src/py/vertebra/db/oracle/driver.py:118-183`: `AsyncOracleDriver` and `OraclePoolRegistry` configure Oracle 26ai connection pools. Oracle supports `SELECT ... FOR UPDATE SKIP LOCKED` for lock-free concurrent worker dequeue across rows ordered by `scheduled_at, enqueued_at`.
- `behavior_tdd` applies because `PostgresQueueBackend` and `OracleQueueBackend` introduce new relational queue backends with SQL DDL/DML contracts and transactional SKIP LOCKED semantics.

- [x] 1. Create `src/py/vertebra/framework/queues/postgres.py` implementing `PostgresQueueBackend`:
  - Define `PostgresQueueExecutor(Protocol)` (`execute`, `fetch_all`, `fetch_one`, `notify`, `wait_for_notify`, `close`) plus an adapter for `psycopg` / `asyncpg` (via `import_optional`) and a transactional SQL-verified in-memory/SQLite-compatible executor for deterministic contract testing.
  - Expose canonical DDL constants `POSTGRES_QUEUE_DDL` creating `vertebra_queue_jobs`, `vertebra_queue_dlq`, and `vertebra_queue_leases` with partial index `CREATE INDEX IF NOT EXISTS idx_vtb_queue_ready ON vertebra_queue_jobs (lane, scheduled_at) WHERE status IN ('pending', 'running')`.
  - Implement atomic claim query `CLAIM_POSTGRES_JOBS_SQL`:
    ```sql
    WITH claimed AS (
        SELECT task_id
        FROM vertebra_queue_jobs
        WHERE lane = ANY($1)
          AND (
              (status = 'pending' AND scheduled_at <= $2)
              OR (status = 'running' AND locked_until <= $2)
          )
        ORDER BY scheduled_at ASC, enqueued_at ASC
        FOR UPDATE SKIP LOCKED
        LIMIT $3
    )
    UPDATE vertebra_queue_jobs AS j
    SET status = 'running',
        locked_until = $4,
        consumer_name = $5,
        receipt_handle = $6
    FROM claimed
    WHERE j.task_id = claimed.task_id
    RETURNING j.task_id, j.task_name, j.lane, j.payload, j.attempt, j.max_retries,
              j.enqueued_at, j.scheduled_at, j.idempotency_key, j.traceparent, j.receipt_handle;
    ```
  - On `enqueue`, execute `INSERT INTO vertebra_queue_jobs ... ON CONFLICT (idempotency_key) DO NOTHING` and emit `SELECT pg_notify('vertebra_queue_wakeup', $1)` with the lane name.
  - On `dequeue`, if no rows are claimed immediately and `timeout_seconds > 0`, compute adaptive wait budget via `SELECT MIN(scheduled_at) FROM vertebra_queue_jobs WHERE lane = ANY($1) AND status = 'pending' AND scheduled_at > $2` (`effective_wait = min(timeout_seconds, config.poll_interval_seconds, max(0.05, earliest_due - now))`), wait on the `LISTEN vertebra_queue_wakeup` channel opened via `PostgresConfig.effective_direct_dsn`, and re-run `CLAIM_POSTGRES_JOBS_SQL`.
  - On `ack`, delete the claimed row where `task_id = $1 AND receipt_handle = $2`.
  - On `nack`, if `send_to_dlq` or `envelope.attempt >= envelope.max_retries`, move the row into `vertebra_queue_dlq` and delete from `vertebra_queue_jobs` inside one transaction; otherwise update `status = 'pending'`, `attempt = attempt + 1`, `scheduled_at = $2`, `locked_until = NULL`.
  - Implement `acquire_lease` and `renew_lease` using `INSERT INTO vertebra_queue_leases (lease_key, owner_id, expires_at, last_slot) VALUES ($1, $2, $3, $4) ON CONFLICT (lease_key) DO UPDATE SET owner_id = EXCLUDED.owner_id, expires_at = EXCLUDED.expires_at, last_slot = COALESCE(EXCLUDED.last_slot, vertebra_queue_leases.last_slot) WHERE vertebra_queue_leases.expires_at <= $5 OR vertebra_queue_leases.owner_id = EXCLUDED.owner_id RETURNING lease_key, owner_id, expires_at, last_slot`.
