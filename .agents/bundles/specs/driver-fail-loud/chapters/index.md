# Chapters: Fail-Loud Database Drivers

* [ch01 — Oracle and MSSQL Fail-Loud Drivers](ch01-oracle-mssql-fail-loud/spec.md) — [completed] Oracle and MSSQL drivers resolve their native module on every entry point and raise `MissingDependencyError` naming `vertebra-core[oracle]` / `vertebra-core[mssql]`, with SQLite execution and SQLite-only helpers deleted and `AsyncMSSQLDriver` forwarding `dialer` (2 tasks).
* [ch02 — DuckDB, SQLAlchemy, and Oracle Queue Fail-Loud Paths](ch02-duckdb-sqlalchemy-queue-fail-loud/spec.md) — [completed] A GIL-only `duckdb` dependency group feeds DuckDB tests that skip on free-threaded interpreters, DuckDB requires the `duckdb` package, the SQLAlchemy DB-API raises `InterfaceError` on unparsable URLs, and `OracleQueueBackend` requires an executor (4 tasks).
* [ch03 — PostgreSQL/MySQL memory:// Removal and RESP3 Loopback Test Fixture](ch03-remove-memory-fakes/spec.md) — [completed] PostgreSQL and MySQL drivers reject `memory://` with in-memory rows deleted, and a threaded loopback `resp3_server` fixture replaces every `memory://` Redis and Valkey construction in the driver, store, Advanced Alchemy, Starlette, and framework unit tests (3 tasks).
* [ch04 — Redis and Valkey memory:// Removal](ch04-redis-valkey-memory-removal/spec.md) — [completed] `RedisConfig` drops the `memory` scheme, the remaining cache tests use the fixture or live-only conformance, and Redis and Valkey drivers delete memory execution and raise `ImproperConfigurationError` through every `from_redis` / `from_valkey` store factory (2 tasks).
* [ch05 — MSSQL Codec Cleanup](ch05-mssql-codec-cleanup/spec.md) — [completed] Deletes the MSSQL Python batch wrappers, the `encode_tds_sql_batch` binding and stub, Rust TDS framing, `MSSQL_DIALECT_TAG`, and `MssqlPool`, keeping the placeholder rewriter and Python TDS packet helpers with docs that describe codecs (3 tasks).
* [ch06 — Oracle Codec Cleanup](ch06-oracle-codec-cleanup/spec.md) — [completed] Deletes Rust TNS framing, `TnsPacketType`, `ORACLE_DIALECT_TAG`, and `OraclePool`, removes the Oracle TNS and Redis hash-slot probes for natives `vertebra._vertebra` never exports, and rewrites Oracle and DuckDB module and adapter docs to describe codecs (3 tasks).
* [ch07 — vertebra-db Pools and MySQL Removal](ch07-vertebra-db-pools-and-mysql/spec.md) — [completed] Deletes the PostgreSQL, DuckDB, SQLite, and MySQL pools and dialect tags, the `OracleWalletMaterial` struct, the `mysql` module, and the `sha2` / `rmp-serde` dependencies, and rewrites crate docs to describe codecs (4 tasks).
* [ch08 — Install Hints and Extras Gate](ch08-install-hints-and-extras-gate/spec.md) — [completed] Defaults `MissingDependencyError` hints to `vertebra-core[<extra>]` and replaces undeclared extras and sentence-valued package names with real pip packages behind an AST extras gate (4 tasks).
* [ch09 — Conformance Outcomes for Missing Native Modules](ch09-conformance-outcomes/spec.md) — [completed] Conformance skips a case whose native module is absent, fails it under Docker mode only for non-pending engines, and applies strict `xfail` only when a pending engine's module imports (1 task).
* [ch10 — PostgreSQL, Redis, and Spanner Queue Backend Fail-Loud Paths](ch10-queue-backend-fail-loud/spec.md) — [completed] PostgreSQL and Spanner queue backends require an injected executor and Redis/Valkey queue backends a live client, with the in-memory fakes moved into tests (3 tasks).
* [ch11 — Documentation and OKF Sync](ch11-docs-and-okf/spec.md) — [completed] Aligns README, database usage and reference docs, and OKF data, testing, product, and ADR chapters with the fail-loud driver baseline (4 tasks).
* [ch12 — Queue Backend Docs and Knowledge](ch12-queue-docs-and-knowledge/spec.md) — [completed] The queues usage guide, queues reference, and OKF distributed-queues chapter state the executor-or-raise and client-or-raise rules with install packages (1 task).
* [ch13 — Agent Knowledge, Dependency Groups, and Embeddings Docs](ch13-agent-knowledge-and-embeddings-docs/spec.md) — [planned] `AGENTS.md`, workflow, benchmark, tech-stack, and test-matrix knowledge state the GIL-only `duckdb` group and `resp3_server` fixture; dialect knowledge, landing pages, and Oracle embedding docs state `InterfaceError` and the pending Oracle and SQL Server drivers (4 tasks).
