# Task 8.3 — Pool `BatchSnapshot` slab and node buffers across SHM worker deserialization

## Objective

Eliminate per-batch `Vec<TransportNode>` and `Vec<u8>` heap allocations in shared-memory worker `BatchSnapshot` deserialization by adding `BatchSnapshot::deserialize_from_pooled` backed by `BatchBufferPool` in `src/rs/vertebra-core/src/transport/batch.rs` (`CORE-20`).

## Context

- `BatchBufferPool` in `src/rs/vertebra-core/src/transport/batch.rs` (created in Chapter 2 Task 2.6) recycles `(Vec<u8>, Vec<TransportNode>)` pairs when `BatchSnapshot::Drop` runs for snapshots created via `BatchSnapshot::new` with an associated pool (`CORE-20`, `CORE-24`).
- In `src/rs/vertebra-core/src/transport/mod.rs`, `Transport::poll_batch` and `Transport::poll_batch_async` read incoming batches over the SHM request ring into `BatchSnapshot`. Deserialization must reuse recycled buffers from `BatchBufferPool` to eliminate heap churn on the worker hot path.

## Steps

- [x] 1. Record baseline Criterion numbers for `batch_snapshot_serde` and `transport_parity`:
  - `cd src/rs && cargo bench -p vertebra-core --bench shm_transport -- "batch_snapshot_serde|transport_parity"`
- [x] 2. In `src/rs/vertebra-core/src/transport/batch.rs`:
  - Add `pub fn deserialize_from_pooled(data: &[u8], pool: &Arc<BatchBufferPool>) -> Result<Arc<Self>, TransportError>` on `BatchSnapshot`:
    - Validate `BATCH_HEADER_SIZE`, `node_count`, `slab_len`, and `expected = BATCH_HEADER_SIZE.checked_add(node_bytes).and_then(|n| n.checked_add(slab_len))` (preserving checked bounds validation from Task 2.1).
    - Take `(mut slab, mut nodes)` from `pool.take()`.
    - Resize `nodes` to `node_count` (`nodes.resize(node_count, TransportNode::default())`) and copy the `TransportNode` slice via `core::ptr::copy_nonoverlapping`.
    - Clear and copy `&data[slab_start..slab_start + slab_len]` into `slab` (`slab.clear(); slab.extend_from_slice(&data[slab_start..slab_start + slab_len]);`).
    - Return `Ok(Arc::new(Self::new(slab, nodes, flags, Some(Arc::clone(pool)))))`.
- [x] 3. In `src/rs/vertebra-core/src/transport/ring_pair.rs` and `src/rs/vertebra-core/src/transport/mod.rs`:
  - Add `pub buffer_pool: Arc<BatchBufferPool>` to `RingPair` (initialized with `BatchBufferPool::new(8, config.request_slot_size, 64)` in `RingPair::create` and `RingPair::from_inherited`).
  - In `Transport::poll_batch` and `Transport::poll_batch_async`, call `BatchSnapshot::deserialize_from_pooled(slice, &ring_pair.buffer_pool)` instead of unpooled deserialization.
- [x] 4. In `src/rs/vertebra-core/benches/shm_transport.rs`:
  - Add `deserialize_pooled` benchmark cases in `bench_batch_snapshot_serde` (`node_count` in `[1, 16, 64]`) and update `shm_ring_roundtrip` in `bench_transport_parity` to use `deserialize_from_pooled`.

## Verification

- **Baseline & post-change characterization**:
  - `cd src/rs && cargo test -p vertebra-core`
  - `cd src/rs && cargo bench -p vertebra-core --bench shm_transport -- "batch_snapshot_serde|transport_parity"`
- **Performance gate**: `cd src/rs && cargo bench -p vertebra-core --bench shm_transport` — `batch_snapshot_serde/deserialize_pooled/64` improves by $\ge 25\%$ over `deserialize/64` and `transport_parity/shm_ring_roundtrip` improves by $\ge 15\%$ with zero steady-state heap allocations per batch after warm-up.

## Acceptance Criteria

- [x] `BatchSnapshot::deserialize_from_pooled` reuses `Vec<u8>` and `Vec<TransportNode>` buffers from `BatchBufferPool` and returns them on `BatchSnapshot::Drop` (`CORE-20`).
- [x] `RingPair` owns an `Arc<BatchBufferPool>` used by `Transport::poll_batch` and `Transport::poll_batch_async`.
- [x] `cargo test -p vertebra-core` and `cargo bench -p vertebra-core --bench shm_transport` pass and meet the performance gate.
