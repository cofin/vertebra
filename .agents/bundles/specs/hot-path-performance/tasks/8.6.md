# Task 8.6 — Pre-compile handler runner callables and collapse multi-wake dispatch in `vertebra.server`

## Objective

Pre-compile per-handler sync and async runner callables at route-registration time, batch synchronous thread-pool submissions when multiple sync requests arrive in one batch, and wake raw `asyncio` event loops once per batch instead of once per coroutine in `src/py/vertebra/server/_dispatch.py` and `src/py/vertebra/server/worker.py` (`PYB-20`).

## Context

- In `src/py/vertebra/server/_dispatch.py` and `worker.py`, `_dispatch_batch` in `async_mode=True` defines a fresh inner `_dispatch_sync`, `_dispatch_async`, or `_dispatch_rsgi` closure per request inside the hot loop (`PYB-20`).
- For synchronous handlers in `async_mode=True`, every request calls `executor.submit(_dispatch_sync)` individually even when a batch contains a single sync request (which can execute inline on the worker thread when no async work is pending) or multiple sync requests (which can be submitted as a single batch callable).
- When `scheduler` is a raw `asyncio.AbstractEventLoop`, `_dispatch_batch` previously looped `for coro in coros: scheduler.call_soon_threadsafe(scheduler.create_task, coro)`, waking the event loop thread $N$ times instead of once.

## Steps

- [x] 1. In `src/py/vertebra/server/_dispatch.py`:
  - Convert `_HandlerDispatchSpec` into a `msgspec.Struct(frozen=True, gc=False)` holding:
    - `is_async: bool`
    - `invoker: Callable[[Any, Any], Any]`
    - `sync_runner: Callable[[Any, dict[str, str], Any, Any, Any], None]`
    - `async_runner: Callable[[Any, dict[str, str], Any, Any, Any], Coroutine[Any, Any, None]]`
  - Build `sync_runner` and `async_runner` once inside `_build_handler_dispatch_spec(handler)` and cache the resulting `_HandlerDispatchSpec` in `_HANDLER_DISPATCH_CACHE`.
- [x] 2. In `src/py/vertebra/server/_dispatch.py`:
  - Add a module-level helper `_schedule_coros(scheduler: Any, coros: list[Coroutine[Any, Any, Any]]) -> None`:
    - If `callable(scheduler)`, call `scheduler(coros)` (calling `BatchTaskScheduler.schedule_many`).
    - Otherwise (when `scheduler` is an `asyncio.AbstractEventLoop`), schedule a single callback `scheduler.call_soon_threadsafe(_create_tasks_batch, scheduler, coros)` where `_create_tasks_batch(loop, batch)` iterates `for c in batch: loop.create_task(c)` on the event loop thread.
- [x] 3. In `src/py/vertebra/server/worker.py` and `_dispatch.py`:
  - In `_dispatch_batch`, replace the per-request `_dispatch_sync` closure with `spec.sync_runner`. When `len(partitioned.sync_native) == 1` and `not partitioned.async_native` and `not partitioned.mounts`, execute `spec.sync_runner(request, params, vr_cls, submit, submit_raw)` directly on the worker thread; when `len(partitioned.sync_native) > 1`, submit a single `_run_sync_batch(partitioned.sync_native, vr_cls, submit, submit_raw)` task (or chunked tasks across `executor._max_workers`) via `executor.submit`.
  - Replace the per-request `_dispatch_async` closure with `[spec.async_runner(request, params, vr_cls, submit, submit_raw) for request, spec, params in partitioned.async_native]` and schedule via `_schedule_coros(scheduler, coros)`.
  - Replace the per-request `_dispatch_rsgi` closure with a module-level `async def _run_mounted_request(mount: Any, request: Any, vr_cls: Any, submit: Any, submit_raw: Any) -> None` coroutine function and schedule via `_schedule_coros(scheduler, mount_coros)`.
- [x] 4. Add unit tests in `src/py/tests/unit/server/test_runner.py` verifying:
  - `_handler_dispatch_spec(handler)` returns a cached `_HandlerDispatchSpec` (`msgspec.Struct`) with pre-compiled `sync_runner` and `async_runner`.
  - `_schedule_coros` invokes `loop.call_soon_threadsafe` exactly once for a multi-coroutine batch on a raw `asyncio.AbstractEventLoop`.

- [x] `_HandlerDispatchSpec` is a `msgspec.Struct(frozen=True, gc=False)` with pre-compiled `sync_runner` and `async_runner` callables (`PYB-20`).

- [x] `_schedule_coros` wakes a raw `asyncio.AbstractEventLoop` once per batch via a single `call_soon_threadsafe` call.
- [x] All Python server unit tests pass and `ruff` + `mypy` report zero issues.
