# Task 8.7 — Fix Criterion benchmark measurement flaws in `vertebra-core` and `vertebra-http`

## Objective

Eliminate per-iteration `thread::spawn` overhead in wakeup benchmarks, UB-prone `Vec::from_raw_parts` alignment mismatches in `ring_throughput.rs`, constant-folding in `shm_transport.rs`, and leaked competing background responder threads in `server_throughput.rs` (`CORE-40`, `HTTP-41`).

## Context

- `CORE-40`:
  - In `src/rs/vertebra-core/benches/spsc.rs:100-150` (which absorbed `spin_wait.rs` in Chapter 2 Task 2.2), `bench_spsc_recv_hybrid_wakeup` called `std::thread::spawn` and `producer.join()` inside `b.iter()`, measuring ~30–80 µs of OS thread creation/teardown rather than futex/ulock wakeup latency.
  - `src/rs/vertebra-core/benches/ring_throughput.rs:13-23` (`make_spsc_heap`) allocates memory with alignment `CACHELINE_BYTES` (64 or 128) via `std::alloc::alloc(alloc_layout)` and wraps it in `ManuallyDrop::new(Vec::from_raw_parts(raw_ptr, 0, layout.total_size))`, which violates `Vec<u8>`'s alignment requirement of 1 and leaks every allocation across benchmark groups.
  - `src/rs/vertebra-core/benches/shm_transport.rs:118-132` (`bench_tiered_ring_selection`) passes a constant size into `config.select_tier(size)` without `std::hint::black_box` on the input argument, allowing LLVM to constant-fold the branch.
- `HTTP-41`:
  - `src/rs/vertebra-http/benches/server_throughput.rs:197-230` (`bench_bridge_dispatch`) spawns an infinite `std::thread::spawn` responder and an infinite `tokio::spawn` `recv_responses` loop on the process-global `BatchBridge::get()` without ever shutting them down. When `bench_bridge_dispatch_adaptive` (`server_throughput.rs:341-370`) subsequently spawns a second responder thread and a second `recv_responses` task on the same global `BatchBridge`, the two responders race for batches and responses are routed to the wrong `Dispatcher` (`HTTP-41`).

## Steps

- [x] 1. In `src/rs/vertebra-core/benches/spsc.rs:100-150` (`CORE-40`):
  - Replace the per-iteration `thread::spawn` + `join` with a persistent producer worker thread created outside `b.iter()` and coordinated via an `Arc<(AtomicU64, AtomicBool)>` step counter and `platform::wake_all` / `platform::wait_on_address_timeout` (or `std::sync::mpsc::SyncChannel`), terminating cleanly after `group.finish()`.
- [x] 2. In `src/rs/vertebra-core/benches/ring_throughput.rs:13-23` (`CORE-40`):
  - Replace `make_spsc_heap() -> (SpscRing, ManuallyDrop<Vec<u8>>)` with a struct `HeapRing { ptr: *mut u8, layout: std::alloc::Layout, ring: SpscRing }` that implements `Drop` via `unsafe { std::alloc::dealloc(self.ptr, self.layout) }` and exposes `fn ring(&self) -> &SpscRing`.
- [x] 3. In `src/rs/vertebra-core/benches/shm_transport.rs:118-132` (`CORE-40`):
  - Wrap the input `size` in `std::hint::black_box(size)` inside `b.iter(|| std::hint::black_box(config.select_tier(std::hint::black_box(size))))`.
- [x] 4. In `src/rs/vertebra-http/benches/server_throughput.rs:190-240, 335-380` (`HTTP-41`):
  - Add an `Arc<AtomicBool>` shutdown flag + `BatchBridge::get().shutdown()` / reset helper (or a shared `OnceLock<Arc<Dispatcher>>` fixture initialized once on a dedicated background runtime) so `bench_bridge_dispatch` and `bench_bridge_dispatch_adaptive` never have two concurrent responder threads or two `recv_responses` tasks polling `BatchBridge::get()` simultaneously.

## Verification

- **Baseline & post-change characterization**:
  - `cd src/rs && cargo bench -p vertebra-core --bench spsc -- --test`
  - `cd src/rs && cargo bench -p vertebra-core --bench ring_throughput -- --test`
  - `cd src/rs && cargo bench -p vertebra-core --bench shm_transport -- --test`
  - `cd src/rs && cargo bench -p vertebra-http --bench server_throughput -- --test`
- **Performance gate**:
  - `cd src/rs && cargo bench -p vertebra-http --bench server_throughput -- bridge_dispatch` — both `bridge_dispatch/http11_concurrent_1000` and `bridge_dispatch_adaptive/adaptive_concurrent_1000` complete cleanly with $\ge 105{,}000\text{ req/s}$ ($< 9.5\text{ ms}$ per 1,000 requests) and zero deadlocks or stolen responses.

## Acceptance Criteria

- [x] `spsc.rs` reuses a persistent producer thread outside `b.iter()` instead of spawning a thread per iteration (`CORE-40`).
- [x] `ring_throughput.rs` deallocates its aligned heap buffer via `std::alloc::dealloc` in `Drop` without constructing `Vec::from_raw_parts` (`CORE-40`).
- [x] `shm_transport.rs` passes `std::hint::black_box(size)` into `select_tier` (`CORE-40`).
- [x] `server_throughput.rs` runs `bench_bridge_dispatch` and `bench_bridge_dispatch_adaptive` sequentially without duplicate responder threads competing on `BatchBridge::get()` (`HTTP-41`).
