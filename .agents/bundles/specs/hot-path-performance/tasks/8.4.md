# Task 8.4 — Pre-encode compact headers and zero-copy `ResponseSlot` encode/decode borrow

## Objective

Encode response headers into the compact wire format (`[name_len: u8][name][val_len: u16 LE][val]`) once during `Response` construction/mutation in `vertebra-py`, and focus on `ResponseSlot::encode_into` / `decode_view` zero-copy borrow in `src/rs/vertebra-core/src/transport/response_slot.rs` and `src/rs/vertebra-py/src/transport.rs`, eliminating intermediate `Vec<(Vec<u8>, Vec<u8>)>` allocations, double encoding, and unnecessary buffer copying on the response path (`PYB-06`). Note: `BridgeResponse.headers_raw: Bytes` was already completed in Chapter 2 Task 2.7.

## Context

- `src/rs/vertebra-py/src/response.rs` (`extract_headers_list`) previously allocated a `Vec<(Vec<u8>, Vec<u8>)>` with two heap `Vec<u8>` allocations per header entry on `Response::new` / `Response::from_buffer`.
- In `src/rs/vertebra-py/src/transport.rs`, `submit_results` and `submit_response` should pass `resp.headers_raw` directly and utilize `ResponseSlot::encode_into` to serialize responses in-place into SHM slots without intermediate heap buffers.
- On the decoding side, `ResponseSlot::decode_view` in `src/rs/vertebra-core/src/transport/response_slot.rs` provides a zero-copy borrowed view of headers and payload directly from the mapped SHM frame.

## Steps

- [x] 1. In `src/rs/vertebra-py/src/response.rs`:
  - Replace `extract_headers_list` with `encode_py_headers_compact(headers: Option<Bound<'_, PyAny>>) -> PyResult<Bytes>` that writes `[name_len: u8][name_bytes][val_len: u16 LE][val_bytes]` directly into a single `Vec<u8>` buffer (reading `PyBytes::as_bytes()` and `PyString::to_str()?.as_bytes()` without per-header `Vec<u8>` allocations) and returns `Bytes::from(buf)`.
  - Change `pub headers: Vec<(Vec<u8>, Vec<u8>)>` on `Response` to `pub headers_raw: Bytes`.
  - Update `Response::headers` getter, `header_value(name: &[u8])`, and `set_header` on `Response` to iterate over `iter_raw_headers(&self.headers_raw)` and append/rebuild `self.headers_raw` when mutated.
- [x] 2. In `src/rs/vertebra-core/src/transport/response_slot.rs`:
  - Provide `ResponseSlot::encode_into(slot_buf: &mut [u8], request_id: u64, status: u16, headers_raw: &[u8], body: &[u8]) -> Result<usize, TransportError>` for zero-copy in-place serialization directly into the destination SHM ring slot without an intermediate `Vec<u8>`.
  - Provide `ResponseSlot::decode_view(slot_buf: &[u8]) -> Result<ResponseSlotView<'_>, TransportError>` enabling zero-copy borrowing of headers slice and body slice directly from the slot without allocations.
- [x] 3. In `src/rs/vertebra-py/src/transport.rs`:
  - In `submit_results` and `submit_response`, use `resp.headers_raw.clone()` ($O(1)$ `Bytes` reference increment) for in-process `BridgeResponse` (which already uses `headers_raw: Bytes` from Task 2.7), and call `ResponseSlot::encode_into` directly on the SHM ring slot when dispatching across SHM.
- [x] 4. In `src/rs/vertebra-http/src/main.rs` and `src/rs/vertebra-http/benches/server_throughput.rs`:
  - Pass `headers_mp: resp.headers_raw` directly into `PendingResponse` without calling `encode_response_headers`.

## Verification

- **Baseline & post-change characterization**:
  - `cd src/rs && cargo test --workspace --features tls,compression`
  - `make dev && uv run pytest src/py/tests/unit/ffi/ src/py/tests/unit/server/ -q`
- **Performance gate**: `cd src/rs && cargo bench -p vertebra-http --bench server_throughput -- bridge_dispatch` — `bridge_dispatch/http11_concurrent_1000` $\ge 105{,}000\text{ req/s}$ ($< 9.5\text{ ms}$ per 1,000 requests) with zero regression.

## Acceptance Criteria

- [x] `vertebra_py::response::Response` stores `headers_raw: bytes::Bytes` instead of `Vec<(Vec<u8>, Vec<u8>)>` (`PYB-06`).
- [x] `encode_py_headers_compact` encodes Python `dict`/`list`/`tuple` headers directly into a single `Bytes` buffer without intermediate per-header `Vec<u8>` allocations.
- [x] `ResponseSlot::encode_into` serializes directly into destination slot buffers and `ResponseSlot::decode_view` borrows slices without copying.
- [x] `submit_response` and `submit_results` pass `resp.headers_raw.clone()` in in-process mode and encode directly via `ResponseSlot::encode_into` in SHM mode.
- [x] All Rust and Python FFI/server tests pass and `bridge_dispatch` meets the performance gate.
