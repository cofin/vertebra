## Objective

Replace silent empty-result and fake in-memory KV stubs in `PostgresDriver`, `MysqlDriver`, `RedisDriver`, and `ValkeyDriver` with explicit `UnsupportedBackendError` when called against remote DSNs without an active connection (allowing `memory://` for in-memory test mode per Decision D1), share the RESP3 base implementation between `redis.py` and `valkey.py`, remove duplicate parameters in `PostgresConfig.compute_worker_pool_budget` and `SyncRedisDriver.encode_hello3_handshake`, dispatch `AsyncSqliteDriver` calls via `SyncPool`, and add `DatabaseRegistry.get_sync_driver`.

## Context

- `src/py/vertebra/db/postgres.py:135-143` (`SyncPostgresDriver.execute_tuples`) ignores `sql` and `parameters` and returns `list(self._in_memory_rows)` (always `[]`), and `src/py/vertebra/db/mysql.py:58-61` (`SyncMysqlDriver.execute_tuples`) ignores `sql` and `parameters` and returns `[]` (`FW-01`).
- `src/py/vertebra/db/postgres.py:65-80` (`PostgresConfig.compute_worker_pool_budget`) accepts both `reserved_super_connections: int = 5` and `reserved_admin_connections: int | None = None` for the same concept (`FW-55`).
- `src/py/vertebra/db/redis.py:87-104` and `src/py/vertebra/db/valkey.py:81-107` silently store keys in `self._kv: dict[str, bytes]` and return `1` from `publish()` even when configured with `redis://localhost:6379/0` or `valkey://localhost:6379/0` (`FW-02`), `valkey.py:61-161` duplicates `SyncRedisDriver` and `AsyncRedisDriver` (`FW-57`), and `SyncRedisDriver.encode_hello3_handshake` (`redis.py:69-85`) accepts duplicate `auth_username`/`auth_password` and `username`/`password` parameters (`FW-57`).
- `src/py/vertebra/db/sqlite.py:104-114` (`AsyncSqliteDriver.execute_tuples` and `close`) invokes blocking `sqlite3.Connection` methods synchronously on the calling asyncio event loop thread (`FW-58`).

## Steps

1. **Write behavior TDD tests in `src/py/tests/unit/db/test_native_db_drivers.py`**:
   - Assert `SyncPostgresDriver(PostgresConfig(dsn="postgresql://localhost:5432/app")).execute_tuples("SELECT 1")` and `SyncMysqlDriver(MysqlConfig(dsn="mysql://localhost:3306/app")).execute_tuples("SELECT 1")` raise `UnsupportedBackendError`.
   - Assert `SyncRedisDriver(RedisConfig(url="redis://localhost:6379/0")).get("k")` and `SyncValkeyDriver(ValkeyConfig(url="valkey://localhost:6379/0")).set("k", "v")` raise `UnsupportedBackendError`, while `RedisConfig(url="memory://")` and `ValkeyConfig(url="memory://")` execute in-memory KV and client-side cache invalidation.
   - Assert `AsyncSqliteDriver.execute_tuples` and `close` execute via `SyncPool.default().submit_async` without blocking the event loop, and `DatabaseRegistry.get_sync_driver` returns the synchronous driver for each registered alias.
2. **Harden `src/py/vertebra/db/postgres.py` and `src/py/vertebra/db/mysql.py` (`FW-01`, `FW-55`)**:
   - In `PostgresConfig.compute_worker_pool_budget` (`postgres.py:65-80`), remove `reserved_super_connections` and keep `reserved_admin_connections: int = 5`.
   - In `SyncPostgresDriver` (`postgres.py:109-147`) and `SyncMysqlDriver` (`mysql.py:45-62`), raise `UnsupportedBackendError` in `execute_tuples` unless an explicit executor callable is injected (`executor: Callable[[str, Sequence[Any]], list[tuple[Any, ...]]] | None = None`). In `AsyncPostgresDriver.execute_tuples` and `AsyncMysqlDriver.execute_tuples`, delegate to an async executor or `SyncPool.default().submit_async(self._sync.execute_tuples, sql, parameters)`.
3. **Deduplicate `src/py/vertebra/db/redis.py` and `src/py/vertebra/db/valkey.py` (`FW-02`, `FW-57`)**:
   - In `SyncRedisDriver.encode_hello3_handshake` (`redis.py:69-85`), remove `auth_username` and `auth_password`, keeping only `*, username: str | None = None, password: str | None = None, client_name: str | None = "vertebra"`. Update `ValkeyConfig.build_handshake_commands` (`valkey.py:46-50`) to pass `username=effective_user, password=effective_password`.
   - In `SyncRedisDriver`, check `self._config.url.startswith("memory://")` before accessing `self._kv` in `get`, `set`, `delete`, and `publish`; if the URL is not `memory://`, raise `UnsupportedBackendError(f"RESP3 driver I/O for {self._config.url!r} requires a connected transport or 'memory://' URL")`.
   - Make `SyncValkeyDriver` inherit from `SyncRedisDriver` (and `AsyncValkeyDriver` inherit from `AsyncRedisDriver`), overriding only `get`, `set`, `delete` to layer `_client_cache` and `handle_invalidation_push` on top of `super()`.
4. **Offload `AsyncSqliteDriver` to `SyncPool` and add `DatabaseRegistry.get_sync_driver` (`FW-58`)**:
   - In `src/py/vertebra/db/sqlite.py:91-114`, dispatch `await SyncPool.default().submit_async(self._sync.execute_tuples, sql, parameters)` in `AsyncSqliteDriver.execute_tuples` and `await SyncPool.default().submit_async(self._sync.close)` in `AsyncSqliteDriver.close`.
   - In `src/py/vertebra/db/_registry.py:49-129`, allow `memory://` URLs where appropriate and add `get_sync_driver(self, name: str = "default") -> object` caching and returning `SyncPostgresDriver`, `SyncMysqlDriver`, `SyncSqliteDriver`, `SyncRedisDriver`, `SyncValkeyDriver`, or `SyncOracleDriver`.
