# Task 2.1: Back `ShmBrokerTransport.publish` and `drain_channel` with a lock-free cross-process SHM channel buffer and multi-process tests

## Objective

Replace the process-local `self._channels: dict[str, list[ChannelMessage]]` in `ShmBrokerTransport` (`src/py/vertebra/extensions/broker/transport.py:353, 542-553`) with a lock-free shared-memory ring buffer so channel messages published in one worker process are visible to `drain_channel` across all attached processes.

## Context

- `src/py/vertebra/extensions/broker/transport.py:542-553`: `ShmBrokerTransport.publish` and `drain_channel` currently mutate an in-memory Python dict `self._channels`, which means invalidation events or transaction notifications published in worker A cannot be drained in worker B.
- `src/rs/vertebra-core/src/broker.rs`: Co-locates broker primitives in a single `ShmRegion`. Adding a compact 64-slot ring of 256-byte channel frames (`ShmChannelRing`) or exposing `publish_channel` / `drain_channel` on `LeaseBroker` keeps cross-process pub/sub inside the same shared-memory region.

## Steps

- [ ] 1. In `src/rs/vertebra-core/src/broker.rs`, add a fixed-capacity lock-free channel ring section (`ShmChannelSlot` with atomic sequence, 64-byte channel hash/name prefix, timestamp, and payload bytes) inside `ShmLeaseTable` and expose `publish_channel(&self, channel: &[u8], payload: &[u8], timestamp_ns: u64, lease_id: Option<&[u8]>) -> bool` and `drain_channel(&self, channel: &[u8]) -> Vec<ChannelFrame>`.
- [ ] 2. In `src/rs/vertebra-py/src/broker.rs`, expose `publish_channel` and `drain_channel` on `LeaseBroker`.
- [ ] 3. In `src/py/vertebra/extensions/broker/transport.py:542-553`, route `ShmBrokerTransport.publish` and `ShmBrokerTransport.drain_channel` through `self._native.publish_channel` and `self._native.drain_channel`.
- [ ] 4. Add a multi-handle / subprocess test in `src/py/tests/unit/extensions/test_shm_broker.py` verifying that `publish("cache_invalidate", b"users:42")` on one `ShmBrokerTransport` handle is returned by `drain_channel("cache_invalidate")` on a second `ShmBrokerTransport` attached to the same SHM region.

## Verification

- **Strategy**: `behavior_tdd` — New observable behavior (cross-process/cross-handle `publish` and `drain_channel` via shared memory).
- **Initial Failing Proof**: Two `ShmBrokerTransport` instances attached to the same `shm_name` fail to see each other's `publish(...)` messages because `self._channels` is an instance-local dict.
