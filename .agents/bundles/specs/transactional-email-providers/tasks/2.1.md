# 2.1 EmailTransport protocol, SmtpEmailTransport, and MemoryEmailTransport

## Objective
Extract the `EmailTransport` protocol, `EmailReceipt`, `EmailDeliveryError`, `WebhookEvent`, and enriched `EmailAttachment`, `EmailMessage`, `EmailConfig`, and `EmailService` into `src/py/vertebra/framework/email/base.py`, implement `MemoryEmailTransport` in `src/py/vertebra/framework/email/memory.py`, and implement `SmtpEmailTransport` in `src/py/vertebra/framework/email/smtp.py` supporting STARTTLS (`587`), implicit TLS (`465`), RFC 5322 `multipart/alternative` text + HTML bodies, `EmailAttachment` MIME parts, and connection pooling.

## Context
- `framework-consolidation:5.7` flattened `email` into single-file module `src/py/vertebra/framework/email.py`. Promoting `email` into a multi-backend subpackage requires removing `src/py/vertebra/framework/email.py` via `git rm src/py/vertebra/framework/email.py` before creating `src/py/vertebra/framework/email/__init__.py`, `base.py`, `memory.py`, and `smtp.py`. Keep worker lane orchestration consolidated in `src/py/vertebra/server/lanes.py`.
- `EmailService` currently stores an in-memory `_outbox: list[EmailMessage]` and returns `f"msg-{len(self._outbox)}"` regardless of `EmailConfig.backend` (finding `FW-08`).
- `EmailMessage` needs `idempotency_key: str | None = None`, `tags: dict[str, str]`, and `metadata: dict[str, str]` for provider correlation, and `EmailConfig` needs SMTP authentication/TLS/pooling options (`smtp_username`, `smtp_password`, `use_tls`, `use_starttls`, `pool_size`, `timeout_seconds`), REST provider options (`api_base_url`, `mailgun_domain`, `webhook_secret`, `max_retries`, `initial_backoff_seconds`), and AWS SES options (`aws_region`, `aws_access_key_id`, `aws_secret_access_key`, `aws_session_token`, `configuration_set_name`).
- `behavior_tdd` applies because `EmailTransport`, `MemoryEmailTransport`, and `SmtpEmailTransport` introduce new protocol contracts and RFC 5322 MIME + pooled SMTP delivery behavior.

  - `EmailAttachment(msgspec.Struct, frozen=True, gc=False, kw_only=True)`: `filename: str`, `content: bytes`, `content_type: str = "application/octet-stream"`, `content_id: str | None = None`.

    ```python
        to: tuple[str, ...]

        text_body: str = ""
    ```

    ```python
        default_from: str = "noreply@example.com"
        smtp_host: str = "localhost"
        smtp_port: int = 587
        smtp_username: str | None = None
        smtp_password: str | None = None

        use_starttls: bool = True

        webhook_secret: str | None = None

        initial_backoff_seconds: float = 0.5

        aws_access_key_id: str | None = None
        aws_secret_access_key: str | None = None
        aws_session_token: str | None = None
        configuration_set_name: str | None = None
    ```
  - `EmailTransport(Protocol)` with async methods `send(self, message: EmailMessage) -> EmailReceipt`, `send_batch(self, messages: Sequence[EmailMessage]) -> list[EmailReceipt]`, and `close(self) -> None`.
  - `EmailService`: resolves `EmailTransport` from `config.backend` (or accepts an explicit `transport: EmailTransport`), fills `message.from_email` from `config.default_from` when empty, exposes `send(message) -> str` (returning `receipt.message_id` for backward compatibility with `src/py/tests/unit/framework/test_framework_subdomains.py:121-126`), `send_with_receipt(message) -> EmailReceipt`, `send_batch(messages) -> list[EmailReceipt]`, `outbox`, `clear_outbox()`, and `close()`.
- [x] 2. Create `src/py/vertebra/framework/email/memory.py` implementing `MemoryEmailTransport`:
  - Stores sent `EmailMessage` and `EmailReceipt` records in memory, generates deterministic `f"msg-{seq}"` IDs (honoring `idempotency_key` deduplication so re-sending the same `idempotency_key` returns the original `EmailReceipt` without duplicating the outbox entry), and provides `outbox`, `receipts`, `find_by_recipient(email: str) -> list[EmailMessage]`, and `clear()`.
- [x] 3. Create `src/py/vertebra/framework/email/smtp.py` implementing `SmtpEmailTransport`:
  - `build_mime_message(self, message: EmailMessage) -> email.message.EmailMessage`: builds an RFC 5322 `email.message.EmailMessage` with `Subject`, `From`, `To`, `Cc`, `Reply-To`, `Message-ID` (`email.utils.make_msgid()`), custom `headers` (rejecting CR/LF header injection with `ValueError`), `text_body` + `add_alternative(html_body, subtype="html")` (`multipart/alternative`), and `add_attachment` for each `EmailAttachment` (splitting `maintype/subtype` from `content_type` and setting `cid` when `content_id` is provided).
  - Maintains a bounded connection pool (`collections.deque[smtplib.SMTP]` up to `config.pool_size`) protected by an `asyncio.Semaphore(config.pool_size)`.
  - Executes synchronous `smtplib.SMTP` / `smtplib.SMTP_SSL` operations (`ehlo`, `starttls` with `ssl.create_default_context()`, `login`, `noop` health check, `send_message`, `quit`) off the event loop via `asyncio.to_thread` (or an injected `smtp_factory` for deterministic unit testing), reconnecting once if a pooled connection raises `smtplib.SMTPServerDisconnected`.
