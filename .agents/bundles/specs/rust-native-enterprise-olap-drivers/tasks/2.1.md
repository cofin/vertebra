# Task 2.1: Implement SHM-brokered single-writer DuckDB Arrow driver (`src/rs/vertebra-db/src/duckdb.rs` + `src/py/vertebra/db/duckdb.py`) and wire `DatabaseRegistry`, `{Oracle,Mssql,Duckdb}*Config`, and `{oracle,mssql,duckdb}+vtb` SQLAlchemy dialects

## Objective

Implement the SHM-brokered DuckDB driver (`src/rs/vertebra-db/src/duckdb.rs` + `src/py/vertebra/db/duckdb.py`) that hosts a single shared DuckDB catalog across multi-worker processes and transfers Arrow `RecordBatch` streams zero-copy through `ShmRegion` Arrow IPC (while keeping `libduckdb-sys` C++ compilation strictly gated behind `--features duckdb`), and register Oracle, SQL Server (`mssql`), and DuckDB across `DatabaseRegistry`, `{Oracle,Mssql,Duckdb}*Config` (`src/py/vertebra/extensions/sqlspec/adapters.py`), and `+vtb` SQLAlchemy dialects (`src/py/vertebra/extensions/sqlalchemy/dialects.py`).

## Context

- DuckDB enforces a single-process write lock on database files; hosting DuckDB inside the SHM broker allows multiple Python worker processes to execute read/write queries against a single DuckDB instance and receive zero-copy `ShmRegion` Arrow IPC streams.
- Per `memory/default/topics/duckdb-resource-management.md`: `parquet_metadata_cache` must be applied via `SET parquet_metadata_cache = true` after connection initialization (not in `connect(config=...)` on DuckDB 2.0.0), and `httpfs` should configure `SET httpfs_connection_caching = true`, `SET enable_http_metadata_cache = true`, and cgroup-aware `max_memory` / `threads`.
