# 1.7 Baseline review run and triage

## Objective
Execute the full-tree baseline review procedure across `feat/stack-followups` using the 8 area reviewers, validate every shard output with `tools/scripts/review_setup.py ledger`, merge and deduplicate the findings into `.agents/bundles/specs/review-infrastructure/research/baseline-ledger.md`, cross-reference against `vertebra-design-quality/findings.md`, and route any newly discovered `critical` or `important` findings into Chapters 2–9 via `/flow:revise`.

## Context
- Roadmap Requirement R2 requires a full-tree baseline run of the 8 area reviewers before Chapters 2–9 begin so any finding not already in `findings.md` is assigned to its owning chapter worksheet before refactoring starts.
- Per the concurrency policy in `review-infra-design.md`, preflight runs once (`make review-check`, `make dev`, `make lint-all`, `make rs-test`, `make py-test`, `make ts-test`), code-area reviewers (`runtime-ipc`, `http-ingress`, `pyo3-bridge`, `python-framework`, `typescript-client`) run first using only read-only Allowed Commands, and cross-cutting reviewers (`performance`, `tests`, `docs-okf`) run after reading the code-area ledgers.
- `documentation_validation` applies because the deliverable is the machine-validated `baseline-ledger.md` artifact checked by `review_setup.py ledger` and `review_setup.py validate --rules privacy`.

## Steps
- [x] 1. Run preflight gates once and record outputs under `.agents/scratch/review-baseline/gates/`.
- [x] 2. Run `uv run python -m tools.scripts.review_setup route --files - < <(git ls-files)` to produce the exact shard file assignments for all 8 areas.
- [x] 3. Fan out the 5 code-area reviewers (`runtime-ipc-reviewer`, `http-ingress-reviewer`, `pyo3-bridge-reviewer`, `python-framework-reviewer`, `typescript-client-reviewer`) across their shards, then run the 3 cross-cutting reviewers (`performance-reviewer`, `tests-reviewer`, `docs-okf-reviewer`).
- [x] 4. Validate each shard ledger with `uv run python -m tools.scripts.review_setup ledger <shard-file>`, merge into `.agents/bundles/specs/review-infrastructure/research/baseline-ledger.md`, and cross-reference every entry against `vertebra-design-quality/findings.md` (marking already-tracked items with their owning `Chapter.Task` in `Status: accepted` or `duplicate:<anchor>`, and adding any new false positives to `false-positive-suppressions.md`).
- [x] 5. If any net-new `critical` or `important` finding with `Confidence: verified` is not yet covered by Chapters 2–9, invoke `/flow:revise` on the owning chapter spec and task worksheet to add its finding ID and steps.
- [x] 6. Commit: `docs(review): record validated full-tree baseline review ledger` (signed), staging `.agents/bundles/specs/review-infrastructure/research/baseline-ledger.md` (and any updated suppression catalog or revised chapter specs).
