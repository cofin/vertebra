# 1.1 Review setup validator and tests

## Objective
Create the manifest-driven structural validator, path router, and finding-ledger validator in `tools/scripts/review_setup.py`, expose `tools` on pytest's `pythonpath` in `pyproject.toml`, and add unit tests in `src/py/tests/unit/test_review_setup.py` covering every rule group (`manifest`, `checklist`, `suppressions`, `skills`, `agents`, `index`, `files`, `bundles`, `privacy`, `ledger`).

## Context
- `tools/__init__.py` exists, but `tools/scripts/` has no `__init__.py` (triggers Ruff `INP001` once `tools/scripts` is linted in Task 1.5).
- `pyproject.toml:88-90` (`[tool.pytest.ini_options]`) sets `testpaths = ["src/py/tests"]` without `pythonpath = ["."]`, so tests cannot import `tools.scripts.review_setup` without `sys.path` manipulation.
- Per `product-guidelines.md`, all value objects (`ReviewIssue`, `AreaShard`, `AreaSpec`, `AgentPolicy`, `ValidationPolicy`, `ReviewManifest`, `ChecklistEntry`, `SuppressionEntry`, `LedgerFinding`) must be `msgspec.Struct(..., frozen=True, gc=False)`, helper methods belong on their domain classes (`MarkdownDocument`, `ReviewSetupValidator`, `ReviewRouter`, `LedgerValidator`), output uses `sys.stdout.write` / `sys.stderr.write`, and zero inline `#` comments are permitted.
- `static_validation` applies because this task introduces a repository gate validator and its unit test suite.

## Steps
- [x] 1. Edit `pyproject.toml:88-93` (`[tool.pytest.ini_options]`) to add `pythonpath = ["."]` so `import tools.scripts.review_setup` resolves cleanly without `sys.path` mutations.
- [x] 2. Create `tools/scripts/__init__.py` with a module docstring and `__all__: list[str] = []`.
- [x] 3. Create `tools/scripts/review_setup.py` implementing:
  - `ReviewIssue(msgspec.Struct, frozen=True, gc=False)` with `rule: str`, `path: str`, `line: int`, `message: str`, and `def format(self) -> str` returning `f"ERROR [{self.rule}] {self.path}:{self.line}: {self.message}"`.
  - `ReviewManifest(msgspec.Struct, frozen=True, gc=False)` with `@classmethod def from_toml(cls, path: Path) -> ReviewManifest` using stdlib `tomllib`.
  - `MarkdownDocument(msgspec.Struct, frozen=True, gc=False)` with `@classmethod def parse(cls, path: Path) -> MarkdownDocument` using a stdlib YAML frontmatter parser (handling scalars, booleans, inline `[a, b]` lists, and multiline `- item` lists), extracting `<!-- truth: start -->` .. `<!-- truth: end -->` line spans, Markdown links, and headings.
  - `ReviewSetupValidator` with `validate(self, rules: frozenset[str] | None = None) -> list[ReviewIssue]` and private rule methods `_check_manifest`, `_check_checklist`, `_check_suppressions`, `_check_skills`, `_check_agents`, `_check_index`, `_check_files`, `_check_bundles`, and `_check_privacy`.
  - Privacy rule (`_check_privacy`): scans globs in `[policy].privacy_scan` against `[policy].forbidden_patterns` (skipping lines containing any `[policy].prohibition_line_markers` substring) and against private terms loaded from `os.environ.get(policy.forbidden_terms_env, "")` and `<repo_root>/<policy.forbidden_terms_file>` (never skipped by prohibition markers; reported only as `private term #<index>` without echoing the term).
  - `ReviewRouter` with `route(self, paths: Sequence[str]) -> dict[str, list[str]]` mapping changed file paths to `<area>` or `<area>:<shard>` keys (cross-cutting areas receive all changed paths when any code path matches).
  - `LedgerValidator` with `validate_file(self, ledger_path: Path) -> list[ReviewIssue]` checking `### <ID> · <severity> · <path>[:L<start>[-L<end>]]` headings, required bullet fields (`Finding`, `Evidence`, `Fix`, `Confidence`, `Status`), file existence and line bounds at `repo_root`, and `Confidence: verified` on accepted `critical`/`important` findings.
  - `main(argv: Sequence[str] | None = None) -> int` supporting `validate [--rules r1,r2] [--repo-root PATH]`, `route [--base REF | --files -]`, and `ledger <path>`.
- [x] 4. Create `src/py/tests/unit/test_review_setup.py` with:
  - Synthetic repo fixture builder `build_minimal_review_tree(tmp_path: Path) -> Path` creating a minimal valid `areas.toml`, `checklist.md`, `false-positive-suppressions.md`, one `review-runtime-ipc/SKILL.md`, paired `runtime-ipc-{reviewer,specialist}.md`, `.agents/skills/index.md`, and `.agents/bundles/index.md`.
  - Isolated negative tests for each rule group (`test_manifest_catches_orphan_source_file`, `test_checklist_catches_duplicate_and_misordered_ids`, `test_suppressions_catches_retired_or_unknown_checklist_id`, `test_skills_catches_truth_budget_and_missing_fp_index`, `test_agents_catches_write_tool_on_reviewer_and_forbidden_command`, `test_index_catches_missing_area_row`, `test_files_catches_executable_bit_and_symlink`, `test_bundles_catches_completed_spec_and_broken_source`, `test_privacy_catches_home_path_and_env_term_without_echoing`, `test_router_assigns_shards_and_cross_cutting`, `test_ledger_rejects_unverified_accepted_critical`).
  - Real-repo bundle check `test_real_repo_bundles_and_privacy_pass` running `ReviewSetupValidator(repo_root).validate(frozenset({"bundles", "privacy"}))` (full default rules are enabled once Tasks 1.2–1.4 land in Task 1.5).
- [x] 5. Commit: `feat(tooling): add agentic review setup validator, router, and ledger checker` (staged for coordinator batch commit).
