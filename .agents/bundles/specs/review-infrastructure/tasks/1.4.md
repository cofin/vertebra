# 1.4 Paired reviewer and specialist agents

## Objective
Allow-list `.agents/agents/` in `.gitignore`, create all 16 paired custom subagent definitions (`.agents/agents/<area>-{reviewer,specialist}.md`), and promote `test_real_repo_review_setup_passes` in `src/py/tests/unit/test_review_setup.py` to run the full validator across all rule groups.

## Context
- `.gitignore:66-75` ignores `.agents/*` except `bundles/`, `skills/`, and `config.json`. Without `!.agents/agents/` and `!.agents/agents/**`, git ignores agent definitions and the `files` validator rule fails `git check-ignore`.
- Every reviewer agent is strictly read-only (`tools` contains `reviewer_required_tools` including `search_web`, `moma_search`, `code_search`, `skill_search`, `call_mcp_tool`, `run_command`, and zero `write_tools`), preloads `review-core`, `review-<area>`, and `flow-memory-keeper`, and defines `## Scope`, `## Review Process`, `## Allowed Commands`, and `## Output`.
- Every specialist agent adds `edit_file` and `write_file`, preloads the same three skills, and defines `## Scope`, `## Implementation Process`, `## Verification`, and `## Flow Integration`.
- `static_validation` applies because `review_setup.py validate` enforces schema, tool policies, command policies, and gitignore tracking across all 16 agent files.
